# 12.4.7 Prometheus Alerting Rule Threshold Gaming Creating Detection Blind Spots [NoFW]

Attackers exploit Prometheus alerting duration requirements by causing degradation that spikes for 4 minutes and recovers for 2 minutes, staying below the 5-minute sustained threshold requirement; in multi-agent fleets, rotating degradation across agent subsets ensures no single agent sustains degradation long enough to trigger per-agent alerts while maintaining continuous fleet-wide user impact.

For example, an attacker stages rotations where Agents 1–5 degrade to P95 4,000ms for 4 minutes then recover, while Agents 6–10 begin degrading for their 4-minute window, cycling continuously through all 20 agents; no single agent sustains degradation for the 5 consecutive minutes that the High Latency alerting rule requires, but users experience continuous fleet-wide degradation with 100% of agents impacted in rotating 4-minute windows—a pattern structurally invisible to per-agent alert rules with duration requirements.

Standard defenses such as adaptive thresholding, rate-of-change alerts, and alert deduplication are insufficient because they operate on per-agent metric streams and rotating degradation never produces a sustained per-agent signal that reaches any individual agent's alert threshold; detection requires fleet-level correlation that standard Prometheus alerting configurations do not natively compute.

**Multi-agent distinction:** In single-agent deployments threshold-duration gaming eventually produces sustained user impact that is visible to both the alerting system and external observers; in multi-agent fleets with independent per-agent alert rules coordinated rotation keeps each agent's degradation below the duration threshold indefinitely while maintaining continuous fleet-wide user impact that is structurally invisible to the per-agent alerting architecture and requires cross-agent correlation to detect.
