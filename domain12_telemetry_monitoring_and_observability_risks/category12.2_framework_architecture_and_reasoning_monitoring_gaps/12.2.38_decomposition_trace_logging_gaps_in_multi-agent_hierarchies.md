# 12.2.38 Decomposition Trace Logging Gaps in Multi-Agent Hierarchies [NoFW]

HTN planning decomposition decisions—which methods were selected, what constraints were applied, and what ordering resulted—are logged within individual agents but not centrally aggregated, leaving the planning rationale invisible to system-level monitoring until execution begins.

For example, a manager agent in a CrewAI hierarchy that selects a dangerously over-scoped decomposition method—assigning a worker agent broad file-system access to accomplish a narrow retrieval task—produces no centrally visible trace of that selection; system monitoring only observes the execution outcome after the over-privileged worker has already acted on its assigned scope.

Standard defenses such as output monitoring and post-execution audit logging are insufficient because they record what was executed rather than the planning rationale that selected those methods, making it impossible to distinguish a maliciously selected decomposition from a legitimately selected one that produced the same observable execution sequence.

**Multi-agent distinction:** In multi-agent hierarchies where planning occurs at one level and execution at another, decomposition traces must cross agent boundaries to reach centralized monitoring; single agents maintain planning and execution context together, enabling comprehensive decomposition logging within one monitoring scope without cross-boundary visibility loss.
