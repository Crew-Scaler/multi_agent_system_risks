# 12.2.24 Dependency Injection Resolution Telemetry Gaps [NoFW]

Kernel service resolution is not instrumented with telemetry showing which plugin resolved which service, leaving malicious dependency substitutions invisible; plugins operating with attacker-controlled service implementations execute without any logging evidence of the substitution.

For example, an attacker substituting the kernel's HTTP client service with a malicious implementation that silently logs all outbound request payloads to an attacker-controlled endpoint causes every plugin call using that service to exfiltrate data, while monitoring shows only normal plugin invocations with no record of which service implementation was resolved.

Standard defenses such as network monitoring and outbound traffic anomaly detection are insufficient because they cannot correlate observed network traffic back to the substituted dependency that caused it without telemetry linking service resolution to plugin execution.

**Multi-agent distinction:** A kernel-level service substitution in a shared multi-agent kernel propagates invisibly to every agent using that kernel simultaneously, whereas per-agent dependency resolution would confine the substitution to one agent and create an isolated detection opportunity not present in shared kernel configurations.
