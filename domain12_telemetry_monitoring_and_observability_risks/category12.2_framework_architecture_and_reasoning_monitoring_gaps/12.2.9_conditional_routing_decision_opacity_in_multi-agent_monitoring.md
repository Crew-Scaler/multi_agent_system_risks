# 12.2.9 Conditional Routing Decision Opacity in Multi-Agent Monitoring [NoFW]

Conditional edge routing events record which node was selected but not the reasoning or state conditions that triggered the selection, making it impossible to determine whether routing was legitimate or the result of poisoned state manipulating control flow.

For example, in a LangGraph pipeline with a conditional edge routing between a "finalize" node and an "elevated_permissions_retry" node, poisoned state causes the router to select the elevated-permissions path; the audit log records "routed to elevated_permissions_node" without capturing which state field value triggered the condition, preventing investigators from distinguishing an adversarial routing manipulation from a legitimately triggered escalation.

Standard defenses such as access control enforcement at routing nodes and post-hoc audit review are insufficient because they do not capture the state snapshot or condition evaluation that produced each routing decision, leaving the causal chain from injected state to selected path entirely invisible in telemetry.

**Multi-agent distinction:** Single-agent systems centralize all routing logic within one observable orchestration context; multi-agent pipelines with distributed conditional routing create cascading decision trees where each agent's routing choice affects downstream agents' received state, requiring complete decision provenance graphs that current telemetry architectures do not produce.
