# 12.2.51 Contingency Activation Blind Spots [NoFW]

Monitoring distinguishes between unexpected and expected contingency activations, treating activations in response to detected failures as benign; adversaries who corrupt contingency branch conditions to trigger activations under false pretenses exploit this monitoring assumption, as synchronized contingency use across agents appears identical whether driven by real failures or attacker-controlled triggers.

For example, an attacker injects a false sensor reading that satisfies the contingency branch condition for emergency rerouting; the multi-agent system activates the rerouting contingency across multiple agents simultaneously, which monitoring records as normal failure-response behavior even though no actual failure occurred and the injected condition was fabricated.

Standard defenses such as contingency activation logging and failure event correlation are insufficient because they validate that activation follows detected failures without verifying that the detected failure itself was authentic rather than attacker-injected.

**Multi-agent distinction:** In a single-agent system, contingency activations can be cross-referenced against the agent's own sensor history to assess whether the triggering condition was legitimate; in multi-agent systems, contingency conditions are often evaluated by one agent and executed by another, removing the cross-referencing opportunity and making synchronized coordinated activations across agents indistinguishable from legitimate coordinated failure responses.
