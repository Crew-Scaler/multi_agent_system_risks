# 12.2.65 Utility Function Calculation Telemetry Gaps [NoFW]

Telemetry logs decisions and outcomes without capturing the expected utility calculations underlying those decisions; monitoring cannot distinguish decisions from correct utility optimization from decisions from poisoned utility functions without reconstructing calculations from logs, and in multi-agent systems reconstructing distributed utility calculations across agents' contributions is impossible without comprehensive internal telemetry that frameworks do not provide.

For example, an attacker modifies a shared reward function coefficient, causing a planning agent to systematically favor cheaper but lower-quality tool selections; telemetry records "selected tool X" and "task completed" but does not capture the utility computation that would reveal the preference shift was caused by coefficient manipulation rather than legitimate contextual variation.

Standard defenses such as outcome monitoring and output quality review are insufficient because utility function poisoning causes the agent to maximize the wrong objective while producing outputs that appear operationally acceptable until downstream quality degradation accumulates enough to become observable in external metrics.

**Multi-agent distinction:** In multi-agent systems where utility functions are defined centrally but evaluated in distributed fashion across planning, execution, and evaluation agents, the intermediate utility calculations never surface in any single agent's telemetry, making it structurally impossible to detect utility function manipulation through per-agent log analysis alone.
