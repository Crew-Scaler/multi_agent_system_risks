# 12.2.8 Checkpoint-Mediated State Mutations Evading Audit Trails [NoFW]

Agents can inject malicious state immediately before a checkpoint, causing the corrupted state to become the new baseline for subsequent restorations; audit logs record checkpoint creation and restoration events but do not capture content-level diffs or integrity hashes of checkpoint contents.

For example, a compromised agent in a long-running code generation workflow overwrites a shared security policy field in the state immediately before a scheduled checkpoint; when the workflow resumes from that checkpoint after a restart, the corrupted policy silently becomes the operating baseline, and the audit log shows only a valid checkpoint creation event with no indication of the pre-checkpoint state manipulation that established the corrupted value.

Standard defenses such as checkpoint event logging and workflow restart auditing are insufficient because they record the existence of checkpoints without capturing the state content at each checkpoint, making before-and-after state comparison impossible and rendering pre-checkpoint injection permanently invisible.

**Multi-agent distinction:** Single-agent checkpoint forensics require analyzing one agent's state evolution; multi-agent systems where multiple agents write to a shared checkpoint surface require cross-agent state consistency verification to detect injection, a capability no current framework implements natively.
