# 12.2.7 Framework Architecture Documentation Gaps Enabling Attack Reconnaissance [NoFW]

Publicly available framework documentation describes per-framework threat models in detail, but multi-agent deployments combining multiple frameworks lack documented cross-framework integration threat models, enabling adversaries to synthesize multi-framework attack plans by composing framework-specific vulnerability knowledge.

For example, an attacker reading that LangGraph validates state transitions explicitly while Semantic Kernel uses dynamic LLM-driven routing can craft an attack that passes LangGraph's explicit validation checks but successfully biases Semantic Kernel's routing through description injection, exploiting the gap between two documented-but-never-jointly-analyzed threat models that no integration security review covers.

Standard defenses such as per-framework security reviews and framework-specific penetration testing are insufficient because they evaluate each framework's threat model independently and produce no combined integration threat model describing cross-framework attack surfaces that emerge only when frameworks are composed.

**Multi-agent distinction:** Single-framework deployments have one documented attack surface; cross-framework multi-agent pipelines expose a combinatorial attack surface at every integration boundary that is absent from any single framework's documentation and therefore never subjected to systematic threat modeling by operators relying solely on framework-level documentation.
