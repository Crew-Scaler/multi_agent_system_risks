# 12.2.13 Tool Invocation Semantic Analysis Gaps [NoFW]

LangChain tool invocation telemetry records function name and parameters but applies no semantic appropriateness check against current context, leaving parameter injection attacks such as deleting audit logs invisible in telemetry that shows a structurally valid call.

For example, a database management agent receives an injected instruction causing it to invoke `delete_table(table='audit_logs')` during what appears to be a routine schema maintenance task; telemetry records a structurally valid tool invocation with correct parameter types, but no monitoring system flags that deleting audit logs is contextually inconsistent with the stated maintenance objective, allowing evidence destruction to proceed undetected.

Standard defenses such as tool authorization lists and parameter type validation are insufficient because they verify the structural validity of tool calls—correct tool name, permissible parameters, authorized caller—without evaluating whether the combination is semantically appropriate given the agent's current task context and stated objective.

**Multi-agent distinction:** Single-agent tool invocation monitoring can potentially correlate tool calls against a known task context within one agent's scope; multi-agent systems require tracing parameter provenance across agents to detect cases where parameters generated by an upstream agent were injected and then passed downstream as trusted inputs to tool invocations that no per-agent context check can flag as inappropriate.
