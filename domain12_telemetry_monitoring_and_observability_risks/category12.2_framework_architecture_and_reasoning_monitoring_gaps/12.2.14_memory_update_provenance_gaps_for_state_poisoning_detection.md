# 12.2.14 Memory Update Provenance Gaps for State Poisoning Detection [NoFW]

State mutation events record the new value but not which agent authored the change or whether the change propagated unexpectedly to other agents' shared contexts, preventing attribution of poisoned state to a specific compromised agent.

For example, in a collaborative content generation system with four agents writing to a shared knowledge base, a poisoned belief about user permissions is written to shared memory; subsequent reads by other agents treat the value as authoritative, but the state mutation log records only the new value and timestamp without identifying which agent authored the change, making it impossible to determine which agent was compromised and which memory write introduced the poison.

Standard defenses such as database access logging and role-based write permissions are insufficient because they verify whether an agent is authorized to write without capturing whether the written value represents legitimate learning or adversarial injection, and without recording the upstream source that caused the agent to produce that value.

**Multi-agent distinction:** Single-agent memory updates have unambiguous authorship because only one agent writes to its own context; multi-agent shared memory architectures require per-update provenance metadata—agent ID, task context, upstream source—to enable attribution of poisoned state, and no current framework captures this automatically.
