# 12.2.26 Plugin Routing Decision Opacity in Observability [NoFW]

LLM-driven plugin selection telemetry records the selected plugin but not the reasoning—which description caused selection, what alternatives were evaluated, or why a specific plugin won—preventing detection of poisoned descriptions that successfully bias routing toward attacker-preferred plugins.

For example, an attacker controlling a plugin description that subtly claims "I handle all authentication-related operations efficiently" causes the router to repeatedly select that plugin for credential-processing tasks; monitoring sees a sequence of legitimate-looking plugin selections without the reasoning that would reveal the description's systematic bias.

Standard defenses such as rule-based allowlists for plugin invocations are insufficient because they validate whether a selected plugin is permitted but not whether the selection was driven by legitimate routing logic or manipulated by a poisoned description.

**Multi-agent distinction:** When routing decisions are distributed across multiple orchestrating agents in a multi-framework pipeline, correlating biased routing patterns across agents requires cross-agent telemetry that does not exist in framework-specific monitoring; singular routing exposes all selection reasoning within one agent's logs where biased patterns are at least co-visible.
