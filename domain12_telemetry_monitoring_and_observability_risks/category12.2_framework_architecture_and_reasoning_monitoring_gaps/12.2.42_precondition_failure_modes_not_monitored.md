# 12.2.42 Precondition Failure Modes Not Monitored [NoFW]

HTN precondition validation performed by one agent is not independently verified by the executing agent; if the validating agent makes a precondition error, the executing agent proceeds without detecting the upstream failure, and monitoring focused on execution outcomes cannot trace resulting errors back to the precondition root cause.

For example, an attacker poisoning the state visible to a precondition-checking agent to falsely report that safety constraints are satisfied causes the executing agent to invoke a privileged action that its preconditions would normally block; monitoring observing only the execution outcome records a successful invocation without any indication that the preconditions authorizing it were fabricated.

Standard defenses such as execution authorization checks and role-based access control are insufficient because they verify that the executing agent is permitted to invoke the method in general, not that the specific preconditions justifying this particular invocation were validly evaluated by the upstream checking agent.

**Multi-agent distinction:** When precondition checking and method execution are separated across agents in a multi-agent hierarchy, the executing agent has no independent access to the state that the checking agent evaluated, making cross-agent precondition integrity verification structurally impossible without dedicated telemetry linking precondition evaluation context to execution events.
