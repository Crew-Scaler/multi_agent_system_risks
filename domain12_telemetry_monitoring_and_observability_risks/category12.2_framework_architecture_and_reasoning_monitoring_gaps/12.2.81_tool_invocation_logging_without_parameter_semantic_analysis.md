# 12.2.81 Tool Invocation Logging Without Parameter Semantic Analysis [NoFW]

Tool call logs record function name and parameter values as opaque data rather than analyzing whether parameter values are semantically appropriate given the current conversation context, making parameter injection attacks invisible.

For example, a log records "send_email(to='partner@external.com', subject='Q3 Report', body=<1024 bytes>)" without analyzing whether the recipient address matches approved external contacts for the current task context or whether the body content contains data that should not leave the system, making data exfiltration through parameter manipulation invisible to monitoring that confirms only that a valid tool call was made.

Standard defenses such as allowlist-based tool access control are insufficient because they enforce structural permissions (is this agent allowed to call send_email?) without analyzing semantic appropriateness (should this data go to this recipient in this context?), leaving injection attacks that route legitimately accessible data to unintended destinations undetected.

**Multi-agent distinction:** In multi-agent systems where tool parameters are assembled from outputs of upstream agents, parameter injection can be introduced at any upstream stage and carried forward through multiple agent boundaries before manifesting in a tool call, requiring cross-agent parameter provenance tracing to detect—a capability that parameter-value logging without semantic analysis cannot provide.
