# 12.2.39 Partial Order Execution Monitoring Without Complete Ordering Information [NoFW]

When an HTN plan specifies partial ordering, executing agents log which sequence they chose without recording that alternative orderings were also permissible; monitoring systems see apparently deterministic execution while actual non-determinism provides attack surface that monitoring cannot reason about.

For example, a planning agent specifying that task A (data access) and task B (permission escalation) are unordered before task C (exfiltration) allows an attacker manipulating the executing agent to always choose the B-before-A ordering, acquiring elevated permissions before accessing data—while monitoring logs a deterministic-appearing sequence with no indication that the attacker-chosen ordering was selected from a set of permissible alternatives.

Standard defenses such as execution sequence auditing and task-ordering policies are insufficient because they validate the logged sequence against an allowed sequence policy but cannot detect violations of ordering constraints that were permissible but never recorded as constraints in the execution trace.

**Multi-agent distinction:** When planning semantics are specified by one agent and executed by another, the executing agent's logs omit the ordering freedom that the planning agent encoded; single agents maintain both planning and execution context and can log the full partial-order specification alongside the chosen execution sequence for complete monitoring coverage.
