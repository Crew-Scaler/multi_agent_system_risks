# 12.2.15 Error Recovery Sequence Telemetry Gaps [NoFW]

LangChain error recovery logs retry count and final success status but not which code paths each retry exercised, making deliberate error injection attacks that force execution through attacker-chosen retry paths undetectable in telemetry.

For example, an attacker submits inputs specifically crafted to trigger parsing failures that activate a retry path executing with relaxed input validation; the agent retries three times, the third retry under relaxed validation succeeds and performs an unauthorized data access, while telemetry records "operation retried 3 times, succeeded" without indicating that the successful retry used a different—and less secure—code path than the first two attempts.

Standard defenses such as retry count limits and circuit breakers are insufficient because they control the quantity and pacing of retries without monitoring which specific execution paths are exercised on each retry attempt, leaving path-selective attack sequences that exploit the difference between initial-attempt and retry-attempt validation logic undetectable.

**Multi-agent distinction:** Single-agent error recovery telemetry is bounded within one execution context; multi-agent systems require cross-agent error orchestration telemetry that can detect coordinated error injection attacks where multiple agents simultaneously trigger failures designed to force specific retry paths across the distributed system, a pattern that per-agent telemetry never observes as a coordinated sequence.
