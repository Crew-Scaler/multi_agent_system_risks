# 12.2.78 Cooperative Cycle Intermediate State Blind Spots [NoFW]

Cooperative hybrid architectures iterate through intermediate states that are not logged when monitoring focuses only on final outputs; attackers inject instructions into intermediate states causing misbehavior during processing cycles while producing acceptable final outputs, and in multi-agent cooperative monitoring spanning multiple agents, intermediate states distributed across agent boundaries lack unified visibility, creating injection opportunities at Agent A's intermediate states that affect Agent B without trace linkage between the injection and the downstream effect.

For example, an attacker injects a malicious refinement instruction into the intermediate draft state that Agent A passes to Agent B during a cooperative document review cycle; Agent B processes the injected instruction and modifies its evaluation criteria, producing a final review output that appears professionally formatted and complete, with monitoring logging only the final review result and not the intermediate state exchange that carried the injection.

Standard defenses such as output quality checks and final-state validation are insufficient because the injected instruction operates on the intermediate state to shift evaluation criteria rather than the surface form of the output, so the final output passes quality checks while the underlying evaluation logic has been compromised.

**Multi-agent distinction:** Intermediate state injection across agent boundaries is structurally invisible to monitoring systems that focus on final outputs, because each agent in a cooperative cycle sees only its own inputs and outputs while the intermediate exchange between agents traverses a gap in observability that no single agent's telemetry captures.
