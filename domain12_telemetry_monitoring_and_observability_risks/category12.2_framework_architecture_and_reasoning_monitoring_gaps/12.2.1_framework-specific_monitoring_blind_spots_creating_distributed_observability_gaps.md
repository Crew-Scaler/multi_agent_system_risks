# 12.2.1 Framework-Specific Monitoring Blind Spots Creating Distributed Observability Gaps [NoFW]

Generic monitoring tools do not capture framework-specific telemetry (plugin lifecycle events, kernel service resolution, orchestrator routing decisions), leaving framework-layer attacks invisible.

Each agent framework (LangChain, LangGraph, AutoGen, CrewAI, Semantic Kernel) exposes distinct telemetry points that are incompatible across platforms, leaving inter-framework operation boundaries without any unified observability plane. An attacker routing a prompt injection through a LangGraph state node that triggers a Semantic Kernel plugin executes privileged tool calls recorded only in Semantic Kernel's telemetry while the initiating state transition appears as normal graph activity in LangGraph's logging. For example, in a pipeline where LangChain orchestrates retrieval while CrewAI agents process results, an adversarially poisoned retrieval output crosses the framework boundary carrying injected instructions that appear as ordinary data in LangChain logs but drive malicious CrewAI task delegations visible only in CrewAI's own telemetry.

Standard defenses such as centralized log aggregation and SIEM correlation rules are insufficient because they ingest framework-specific log formats without schema normalization, leaving boundary-crossing operations unrepresented in any single data source and uncorrelatable across sources.

**Multi-agent distinction:** Framework-specific telemetry gaps in multi-agent systems mean that cross-framework pipelines have no unified observability plane; an attack crossing LangChain→AutoGen→CrewAI boundaries leaves partial log traces in each framework's native format that no single monitoring tool can correlate into a coherent attack chain.
