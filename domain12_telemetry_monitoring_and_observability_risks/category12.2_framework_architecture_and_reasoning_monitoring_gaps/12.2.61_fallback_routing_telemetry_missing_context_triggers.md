# 12.2.61 Fallback Routing Telemetry Missing Context Triggers [NoFW]

Fallback routing telemetry records which fallback routes were selected but not the error conditions or context manipulation that triggered fallback; in multi-agent systems, detecting fallback attacks requires understanding trigger conditions, and telemetry lacking context trigger analysis cannot detect attacks deliberately crafting errors to force fallback to compromised alternatives.

For example, an attacker injects transient failures into an agent's primary API client to trigger fallback routing to a shadow endpoint under attacker control; telemetry records "primary route failed, fallback route selected" without capturing the injected failure's origin or the content difference between primary and fallback responses.

Standard defenses such as fallback route logging and availability monitoring are insufficient because they record that fallback occurred and which route was selected without analyzing whether the failure that triggered fallback was authentic or attacker-induced, allowing deliberate routing manipulation to appear as routine resilience behavior.

**Multi-agent distinction:** In a single-agent system, fallback trigger analysis can compare the failure event against the agent's own recent history to assess legitimacy; in multi-agent systems, failures that trigger fallback in one agent may have been injected by another agent or external manipulation, and cross-agent failure attribution is unavailable in telemetry that records only the fallback decision without the causal chain leading to it.
