# 12.2.59 Error Message Content Opacity Creating Detection Blind Spots [NoFW]

Error logging captures error messages but applies no semantic analysis of message content; attackers craft error messages containing malicious instructions or suspicious patterns that telemetry records as unstructured text without parsing, creating blind spots where sophisticated attacks embed instructions in error semantics that monitoring sees as "error occurred: [content]" without analyzing what that content contains.

For example, an attacker causes a database query to fail with a crafted error message containing injection instructions formatted as a stack trace; the error handler passes the message to a recovery agent that interprets the injected instructions as remediation steps, while monitoring records only "database error" without parsing the message content that drove the malicious recovery action.

Standard defenses such as error rate alerting and exception category logging are insufficient because they classify errors by type and count without parsing message semantics, allowing malicious instruction payloads embedded in error text to pass through the logging pipeline as unanalyzed string data.

**Multi-agent distinction:** In a single-agent system, crafted error messages affect only the local error handler's behavior and can be reviewed in a unified context; in multi-agent systems, crafted error messages propagate across agent boundaries as part of error-response protocols, where each agent's error handler may consume and act on the malicious content without any cross-agent semantic analysis detecting the instruction injection pattern embedded in error semantics.
