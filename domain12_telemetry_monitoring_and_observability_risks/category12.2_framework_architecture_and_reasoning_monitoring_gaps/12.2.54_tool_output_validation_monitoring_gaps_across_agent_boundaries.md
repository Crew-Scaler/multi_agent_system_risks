# 12.2.54 Tool Output Validation Monitoring Gaps Across Agent Boundaries [NoFW]

Tool output validation occurs at the consuming agent level; in multi-agent systems Tool A's output validated by Agent A is not re-validated by Agent B when consumed downstream, and monitoring shows "Tool A output validated" without visibility that Agent B skipped cross-boundary re-validation, allowing corrupted tool outputs to propagate through agent chains without re-validation telemetry.

For example, Agent A validates a database query result as well-formed JSON before passing it downstream, but Agent B consumes the same data after it has been modified in transit and accepts it without re-validation because monitoring already logged the original validation event as sufficient proof of data integrity.

Standard defenses such as schema validation at the producing agent and integrity checks at API boundaries are insufficient because they verify tool outputs against format specifications at one point in the pipeline without ensuring that subsequent agents independently revalidate data that may have been altered between agents.

**Multi-agent distinction:** In a single-agent system, tool outputs are validated once by the agent that invoked the tool and then consumed by the same agent, removing the inter-agent transit gap; in multi-agent pipelines, validated outputs cross agent trust boundaries where the validation provenance may not transfer, creating blind spots where corrupted data appears pre-validated to downstream agents and monitoring records only the original validation event.
