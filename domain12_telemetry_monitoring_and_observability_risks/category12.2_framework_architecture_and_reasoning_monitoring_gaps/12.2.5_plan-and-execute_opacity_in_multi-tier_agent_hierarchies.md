# 12.2.5 Plan-and-Execute Opacity in Multi-Tier Agent Hierarchies [NoFW]

Planning-phase reasoning that drives subsequent execution is often not logged, making it impossible to trace why an execution agent took a specific action.

Plan-and-Execute architectures structurally separate planning agents that generate task decompositions from execution agents that carry out steps, but logging infrastructure is uniformly applied at the execution layer—recording tool calls and output values—while the planning layer's reasoning, constraints, and delegation decisions are rarely persisted, creating a causal attribution dead zone where execution actions cannot be traced to the planning intent that produced them. A maliciously injected planning instruction causes downstream execution agents to take anomalous actions; security monitoring sees the anomalous tool calls but finds no logged planning context explaining why they were issued, making root-cause analysis impossible. For example, in a document processing pipeline with a supervisor planner and specialized OCR, classification, and extraction workers, an adversary poisoning the planner's context causes it to delegate extraction to a worker not authorized for sensitive fields; the worker's extraction call appears in logs as a structurally valid action with no record indicating it originated from manipulated planning context.

Standard defenses such as execution-layer audit logging and tool authorization enforcement are insufficient because they operate downstream of the planning decision, recording what happened without capturing the planning-phase reasoning that determined it should happen.

**Multi-agent distinction:** Single-agent systems maintain a continuous reasoning trace within one context window; multi-tier architectures fragment decision provenance across isolated agent contexts, meaning that planning-layer injections produce execution-layer anomalies without any shared logging scope that connects the cause to the effect.
