# 12.3.11 Temporal Validity Enforcement Blind Spots [NoFW]

Knowledge base entries carry temporal validity metadata, but monitoring does not verify that retrieving agents check this metadata before using retrieved content; stale documents past their validity date remain retrievable and are used without the monitoring system detecting the temporal validity violation.

For example, a regulatory compliance agent retrieves a data-retention policy document whose validity period expired 18 months ago; the retrieval event is logged with a successful status and the agent's resulting compliance determination is also logged, but monitoring never records that the temporal validity annotation on the retrieved document was neither checked nor enforced, leaving the stale-document-driven compliance decision invisible as a policy violation.

Standard defenses such as TTL-based expiration enforcement at the knowledge base level and document age dashboards are insufficient because they track whether validity metadata exists on stored documents, not whether the agents retrieving those documents actually consult and enforce validity constraints before incorporating the content into their reasoning.

**Multi-agent distinction:** In multi-agent systems, a shared knowledge base with temporal validity gaps exposes all agents to stale content simultaneously; because the validity check failure occurs at the agent side rather than at the knowledge base side, per-knowledge-base monitoring cannot detect it, and without per-retrieval enforcement logging for each agent, there is no signal indicating which agents violated temporal constraints or how many decisions across the agent fleet were based on expired content.
