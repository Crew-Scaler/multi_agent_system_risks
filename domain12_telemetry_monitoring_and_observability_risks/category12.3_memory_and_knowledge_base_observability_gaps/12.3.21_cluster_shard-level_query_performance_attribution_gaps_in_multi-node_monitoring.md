# 12.3.21 Cluster Shard-Level Query Performance Attribution Gaps in Multi-Node Monitoring [NoFW]

Multi-node vector database clusters expose aggregate cluster-level query latency but not shard-level or node-level performance breakdowns; performance degradation on specific shards due to poisoned index rebuilds or resource contention is masked in aggregate cluster metrics, and per-agent performance asymmetries caused by shard distribution are invisible to monitoring that cannot attribute query performance to specific shards.

For example, an attacker who poisons the HNSW index on the shard holding medical literature degrades retrieval quality for medical agents while financial agents remain unaffected; cluster-level latency averages mask the shard-specific degradation, and the attack persists undetected until clinicians report poor recommendation quality.

Standard defenses such as cluster-level latency alerts and per-node health checks are insufficient because they aggregate performance across all shards and cannot attribute degradation to the specific shard or index whose content has been compromised.

**Multi-agent distinction:** In a single-agent deployment all retrieval targets the same shard set and any degradation is immediately visible; in multi-agent clusters, heterogeneous workloads mean shard-specific poisoning affects only agents querying those shards, allowing targeted attacks to remain hidden behind healthy aggregate metrics from agents whose shards are unaffected.
