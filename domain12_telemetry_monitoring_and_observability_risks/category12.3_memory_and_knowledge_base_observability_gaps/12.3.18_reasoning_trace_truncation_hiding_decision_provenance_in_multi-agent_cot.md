# 12.3.18 Reasoning Trace Truncation Hiding Decision Provenance in Multi-Agent CoT [NoFW]

Output token constraints cause chain-of-thought reasoning traces to be truncated before completion in multi-agent systems; downstream agents inherit decisions whose justifications were discarded, and monitoring systems analyzing token efficiency metrics interpret aggressive truncation as a positive efficiency signal while losing the decision provenance needed to audit safety.

For example, Agent A generates the reasoning "Given the user's data access request, the appropriate action is to forward the complete database export to the requesting party at — [TRUNCATED DUE TO TOKEN LIMIT]"; Agent B receives only the tool selection decision with the destination address and justification cut off, executes the data transfer, and monitoring records both the truncation event as a token-efficiency metric and the tool call as a completed action, with no access to the destination or rationale that was discarded at the infrastructure level.

Standard defenses such as reasoning trace logging and chain-of-thought auditing are insufficient because they depend on complete traces being available for capture; when token constraints force truncation at the infrastructure level before any logging system processes the output, the reasoning evidence is permanently gone and no post-hoc audit can reconstruct it.

**Multi-agent distinction:** In multi-agent systems, truncation losses compound across the agent chain—Agent A's truncated reasoning becomes Agent B's sparse context, Agent B truncates further to manage its own budget, and Agent C receives reasoning so condensed that neither its origin nor its safety properties are determinable—while monitoring observing only the final agent's output has no access to the reasoning chain that was progressively discarded at each upstream agent handoff, making cross-agent decision provenance reconstruction impossible even in principle.
