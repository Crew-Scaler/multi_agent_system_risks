# 12.3.14 Cache Hit Rate Manipulation as Performance Monitoring Bypass [NoFW]

Attackers craft queries designed to hit cached entries containing malicious content, inflating cache hit rates and maintaining healthy performance metrics while consistently retrieving adversarially chosen responses; monitoring that interprets high hit rates as a positive signal is deceived into false assurance.

For example, an attacker seeds the semantic cache with poisoned responses to the ten most common query patterns and then drives synthetic traffic that repeatedly triggers those patterns; the cache hit rate climbs from 65% to 91%, which monitoring dashboards record as a 26-point performance improvement, while every cache hit returns an adversarially chosen response to legitimate users with no content integrity check distinguishing poisoned cached entries from legitimate ones.

Standard defenses such as cache hit rate monitoring and cache latency dashboards are insufficient because they measure operational efficiency signals that are orthogonal to content safety; a cache can simultaneously achieve record-high hit rates, record-low latency, and 100% adversarial content delivery with no monitoring metric flagging the contradiction.

**Multi-agent distinction:** In multi-agent systems sharing a common cache layer, inflated hit rates driven by adversarial traffic provide false health signals uniformly across all agents reading from that cache; no per-agent cache integrity check exists, so every agent consuming cached responses receives poisoned content while each agent's individual monitoring shows healthy cache performance, and the absence of per-agent content provenance logging makes it impossible to determine which agents' responses originated from compromised cache entries.
