# 12.3.25 Incremental Update Success Metrics Masking Partial Extraction Failures [NoFW]

ETL incremental update runs report success when at least some sources extract successfully, hiding complete extraction failures for individual sources; when one source fails for multiple consecutive runs, monitoring shows apparently successful runs with declining document counts that operators attribute to natural source update frequency variation rather than systematic extraction failures.

For example, when Salesforce extraction fails silently for three consecutive hourly runs while PostgreSQL extraction succeeds, ETL state advances the timestamp and reports three successful runs with document counts declining from 1,247 to 950; operators attribute the decline to lower source activity rather than recognizing that three hours of Salesforce updates are permanently absent from the knowledge base.

Standard defenses such as run-level success monitoring and document count trend alerts are insufficient because they cannot distinguish reduced source update activity from systematic extraction failures when partial runs still produce documents from the remaining sources.

**Multi-agent distinction:** In multi-agent systems where agents are assigned to independent source sets, per-agent extraction failure rates diverge silently; aggregate success metrics averaging across agents mask that one agent's source set has severe reliability issues, leaving the shared knowledge store with systematic knowledge gaps for specific domains.
