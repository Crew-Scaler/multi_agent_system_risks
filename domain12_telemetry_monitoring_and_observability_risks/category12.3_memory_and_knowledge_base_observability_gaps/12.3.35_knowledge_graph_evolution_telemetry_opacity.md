# 12.3.35 Knowledge Graph Evolution Telemetry Opacity [NoFW]

Knowledge graph updates lack detailed telemetry tracking why relationships were modified or who authorized specific changes, leaving minimal audit trails for attackers injecting relationships; in multi-agent systems with shared knowledge graphs, the collective update pattern creates plausible deniability when multiple agents query and update simultaneously, enabling attackers to inject relationships that appear to result from legitimate multi-agent consensus rather than adversarial manipulation.

For example, an attacker who injects a false relationship "drug X is safe for pediatric use" into a shared medical knowledge graph during a period when three agents are simultaneously updating the graph from clinical trial data creates an injection that appears as one of many legitimate concurrent updates; the absence of relationship-level provenance logs means no audit trail identifies which agent or process created the false edge.

Standard defenses such as graph change logs and version control for knowledge graphs are insufficient because they track that relationships were added or removed without capturing the authorization chain, confidence score, or source evidence that would distinguish adversarially injected relationships from legitimate updates.

**Multi-agent distinction:** In single-agent systems all knowledge graph mutations are attributable to one source; in multi-agent systems where multiple agents query and update a shared graph concurrently, the collective write pattern provides plausible deniability for injected relationships, and a poisoned relationship propagates immediately to every agent's retrieval without any per-agent write provenance to isolate the injection source.
