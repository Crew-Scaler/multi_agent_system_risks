# 12.3.23 ETL Quality Rejection Metrics Aggregation Hiding Per-Source Data Quality Failures [NoFW]

ETL quality validation monitoring reports aggregate rejection rates across all data sources without per-source breakdowns; a single source experiencing severe quality degradation (such as a Confluence space generating auto-generated low-quality content) can be hidden behind high-quality metrics from other sources, delaying detection of source-specific data quality failures.

For example, when a Confluence wiki starts producing auto-generated stub pages that fail minimum-length checks, 1,400 of 1,500 daily rejections may originate from that one space while all other sources maintain below-1% rejection rates; aggregate monitoring showing "15% overall rejection rate" provides no signal that Confluence is the sole problem source requiring remediation.

Standard defenses such as global rejection rate alerts and data quality dashboards are insufficient because they report fleet-wide averages that dilute source-specific anomalies, making it impossible to isolate which source system is responsible.

**Multi-agent distinction:** In multi-agent systems where agents are assigned to different source systems, per-agent rejection breakdowns would immediately surface the failing source; without that decomposition, the shared knowledge store silently accumulates quality gaps that affect every agent's retrieval while per-source accountability remains invisible in aggregate metrics.
