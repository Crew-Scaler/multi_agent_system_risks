# 12.3.4 Cross-Agent Memory Sharing Obscuring Individual Responsibility [NoFW]

Shared memory accessed by multiple agents makes it impossible to determine which agent introduced a particular memory entry without granular write-attribution logging.

Shared memory stores—vector databases, knowledge graphs, episodic stores—receive writes from multiple agents during normal operation, but write events are typically logged at the store level without capturing which specific agent instance, task context, or authorization chain produced each write. This architectural property means that when a poisoned memory entry is discovered, the investigation cannot identify its origin without per-write provenance metadata that most deployments do not collect. For example, in a ten-agent customer-support system where five agents write to shared episodic memory, a poisoned episode that causes biased responses cannot be attributed to any individual agent; all five are equally plausible sources, and the shared write log shows only a timestamp and entry content with no agent identifier.

Standard defenses such as role-based access controls and write-access audits are insufficient because they record who was authorized to write, not which of the authorized agents actually performed each specific write; without per-write agent identity logging, access controls establish eligibility but not attribution, leaving poisoning investigations without a starting point.

**Multi-agent distinction:** In single-agent systems, write attribution is trivial because only one agent writes to memory; in multi-agent systems, the shared write surface makes attribution impossible without explicit provenance instrumentation, and poisoned entries propagate to every reading agent while the writing agent remains unidentified—enabling attackers to inject content through any one agent knowing that shared access will disseminate it and the lack of per-write attribution will prevent tracing.
