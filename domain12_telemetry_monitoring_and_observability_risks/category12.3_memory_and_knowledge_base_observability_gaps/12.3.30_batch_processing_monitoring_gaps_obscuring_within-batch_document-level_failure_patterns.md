# 12.3.30 Batch Processing Monitoring Gaps Obscuring Within-Batch Document-Level Failure Patterns [NoFW]

Batch-level monitoring records whether a batch succeeded or failed overall; within-batch document-level failures (quality validation rejections, duplicate detection failures, individual document processing errors) are invisible to batch-level metrics, and partial retry logic that reprocesses entire batches creates duplicate ingestion that monitoring attributes to retry success rather than correctness failure.

For example, a batch of 100 documents where 23 fail quality validation and 77 succeed is reported as a successful batch completion; across 20 such batches, monitoring shows 20/20 successful batches while 460 documents have silently failed ingestion, creating knowledge gaps that agents discover only when querying for content that was never indexed.

Standard defenses such as batch success rate monitoring and retry success logging are insufficient because they treat any batch with a non-zero success count as passed, and retry logic that reprocesses entire batches reintroduces duplicates of already-ingested documents without any monitoring signal distinguishing deduplication noise from correctness failures.

**Multi-agent distinction:** In multi-agent systems where agents submit concurrent batches to a shared knowledge store, race conditions on overlapping document sets create duplicate ingestion events that batch monitoring attributes to normal parallel processing; within-batch failure distributions also differ across agents without any per-agent breakdown to identify which ingestion pipeline has the worst document-level error rate.
