# 12.3.6 Trajectory Integration Hiding Multi-Step Attacks [NoFW]

Trajectories that aggregate multi-step solution paths present monitoring with only final outcomes, concealing malicious intermediate steps embedded early in the trajectory that appeared to be legitimate problem-solving actions at time of execution.

For example, a poisoned trajectory step labeled "validate output format" silently sets an internal safety-bypass flag at step 3 of a 20-step trajectory; downstream monitoring observes only the final successful trajectory completion, and the benign-looking step description provides no indication that an adversarial state change occurred midway through execution.

Standard defenses such as final-outcome validation and trajectory completion logging are insufficient because they inspect trajectories at their endpoints rather than instrumenting each intermediate step at execution time; by the time the final outcome is observable, the intermediate state changes have already taken effect and any injected state is embedded in the trajectory's result.

**Multi-agent distinction:** In multi-agent systems where multiple teams share trajectory libraries, a single poisoned intermediate step propagates across every agent and team using that trajectory; monitoring each team's output in isolation cannot detect the shared malicious step because each team's final outcome individually appears legitimate, while the common injected step remains invisible in any per-team view.
