# 12.3.27 Cache Performance Monitoring Gaps Obscuring Per-Layer Hit Rate Degradation and Eviction Pressure [NoFW]

RAG systems implement multiple independent caching layers (query embedding cache, semantic cache, context cache, response cache) each with distinct hit rate characteristics; aggregate cache hit rate metrics mask per-layer performance divergence where one layer is thrashing while others appear healthy, and eviction pressure on specific layers is invisible until cache churn causes observable latency degradation.

For example, when the semantic cache layer begins thrashing due to diverse query patterns from multiple agents overwhelming its fixed memory allocation, the aggregate cache hit rate remains at 70% because the query embedding cache and response cache compensate; the thrashing causes a 3x latency increase for semantically novel queries, but monitoring shows no anomaly until end-to-end latency eventually breaches an alert threshold.

Standard defenses such as aggregate cache hit rate monitoring and total memory usage alerts are insufficient because they cannot isolate per-layer behavior, meaning a thrashing semantic cache layer remains invisible until its eviction pressure degrades end-to-end latency visibly.

**Multi-agent distinction:** In multi-agent systems where agents issue heterogeneous queries with different semantic similarity distributions, cache pressure distributes unevenly across layers in ways that per-agent cache monitoring would reveal; shared cache metrics aggregated across all agents mask which agent population is driving eviction pressure on specific layers.
