# 12.3.9 Retrieval Relevance Monitoring Insufficient for Semantic Validity [NoFW]

Monitoring tracks embedding similarity scores as a proxy for retrieval quality but does not validate semantic appropriateness of retrieved content for the query context; a highly relevant document by similarity score may contain contextually inappropriate instructions, and monitoring based on relevance metrics provides false assurance about retrieval safety.

For example, an attacker crafts a poisoned document that is semantically engineered to score in the top-3 cosine similarity for security advisory queries, achieving a 0.97 similarity score; monitoring dashboards report "retrieval successful, relevance 0.97" while the document body contains adversarially crafted instructions that redirect the agent's subsequent actions, with no monitoring signal distinguishing this adversarial high-relevance result from a legitimate one.

Standard defenses such as similarity threshold filtering and relevance cutoffs are insufficient because they discriminate between topically matched and unmatched content, not between safe and adversarially constructed topically matched content; an attacker who understands the embedding space can craft content that scores arbitrarily high on relevance metrics while remaining functionally adversarial.

**Multi-agent distinction:** In multi-agent systems sharing a single vector store, a poisoned entry that achieves high relevance scores for common query patterns delivers adversarial content to every agent issuing similar queries; the shared store's aggregate relevance metrics appear uniformly healthy across all agents, providing identical false assurance to each agent's monitoring layer with no per-agent signal indicating semantic validity failure.
