# 12.3.10 Knowledge Graph Relationship Cardinality Explosion Monitoring Gap [NoFW]

Knowledge graph inference rules can create exponential relationship counts in subgraphs; monitoring that tracks total relationship counts may not detect subgraph cardinality explosions until system-wide performance degradation becomes apparent, by which point all agents sharing the graph are already affected.

For example, an attacker inserts a set of inference rules that transitively link a small medical entity subgraph to thousands of downstream concepts; aggregate monitoring shows "total graph relationships: increased by 5%" while the targeted subgraph grows from 10,000 to 2 million relationships, and query latency for medical topics degrades unacceptably before the subgraph explosion is discovered through manual investigation triggered only by user complaints.

Standard defenses such as total relationship count alerting and graph size thresholds are insufficient because they measure aggregate graph properties that absorb localized subgraph explosions below detection thresholds; a 20x increase in one subgraph may represent only a 3% increase in total graph size if the affected subgraph was initially small relative to the whole.

**Multi-agent distinction:** In multi-agent systems sharing a knowledge graph, a cardinality explosion in one subgraph simultaneously degrades retrieval for every agent whose queries traverse that subgraph; aggregate latency monitoring averaging across all agents absorbs the spike from affected agents into the mean, so the explosion remains below alert thresholds until it has grown large enough to degrade system-wide performance for all agents at once, at which point the damage is already systemic.
