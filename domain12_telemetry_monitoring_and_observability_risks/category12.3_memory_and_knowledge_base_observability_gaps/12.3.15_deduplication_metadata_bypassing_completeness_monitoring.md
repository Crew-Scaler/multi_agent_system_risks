# 12.3.15 Deduplication Metadata Bypassing Completeness Monitoring [NoFW]

Deduplication processes track how many documents were removed as duplicates but not which specific documents were considered duplicates of which source, preventing detection of false-positive deduplication that removes unique legitimate content or false-negative deduplication that allows poisoned documents to persist alongside their originals.

For example, a deduplication process identifies a recently updated security policy document as a near-duplicate of an older version and silently discards the newer document; the knowledge base completeness dashboard shows the expected total document count because the deduplicated-document count increased by one to absorb the removal, and the missing policy update is not discovered until an agent makes a compliance determination based on the outdated retained version.

Standard defenses such as document count monitoring and aggregate deduplication rate dashboards are insufficient because they track volume metrics rather than deduplication provenance chains; without logging which document was considered a duplicate of which source document, there is no means to audit whether any specific deduplication decision was a false positive that removed legitimate unique content.

**Multi-agent distinction:** In multi-agent systems where multiple agents rely on a shared deduplicated knowledge base, a false-positive deduplication that removes a legitimate document creates a uniform knowledge gap affecting every agent that would have queried that content; monitoring cannot distinguish this from a legitimate absence of matching documents, and the missing-content signal manifests identically across all agents as empty retrieval results rather than as a completeness failure attributable to faulty deduplication.
