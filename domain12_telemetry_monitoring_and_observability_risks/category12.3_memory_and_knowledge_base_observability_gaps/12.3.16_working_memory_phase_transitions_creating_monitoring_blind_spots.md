# 12.3.16 Working Memory Phase Transitions Creating Monitoring Blind Spots [NoFW]

Working memory lifecycle phase transitions (assembly, processing, reasoning, generation, disposal) create discrete observability gaps; the disposal phase erases intermediate reasoning states and tool invocation evidence before monitoring can capture them, and attackers who time injection to the generation phase exploit the window between reasoning completion and disposal.

For example, an attacker times a prompt injection to activate during the generation phase of Agent A's working memory lifecycle; the malicious instruction executes and its effect is encoded in the generated output before the subsequent disposal phase clears all intermediate context, leaving monitoring with no evidence of the injection because the working memory state that contained it is erased as part of normal memory management before any log capture occurs.

Standard defenses such as output monitoring and post-generation action auditing are insufficient because they observe completed outputs after the working memory state that produced them has already been discarded during disposal; without continuous capture of in-flight working memory state across all phases, any evidence that existed only within the generation phase is permanently lost before it can be recorded.

**Multi-agent distinction:** In multi-agent systems where Agent A's generated output becomes Agent B's input, the disposal-phase erasure of Agent A's working memory prevents any subsequent audit of what reasoning state or injected instruction led to the output Agent B receives; each agent's monitoring covers only its own working memory phases, but cross-agent phase boundaries create attribution gaps that no individual agent's monitoring can bridge, and the absence of per-write provenance across phase transitions means injection evidence disappears at every agent handoff.
