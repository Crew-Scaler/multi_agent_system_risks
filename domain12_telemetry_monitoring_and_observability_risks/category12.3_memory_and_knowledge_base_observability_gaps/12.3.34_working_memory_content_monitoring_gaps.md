# 12.3.34 Working Memory Content Monitoring Gaps [NoFW]

Working memory maintains intermediate facts during inference, but in multi-agent systems with shared working memory, tracking which agents retrieve and use which facts becomes opaque; monitoring cannot determine which agent accessed which fact and for what purpose in shared visibility contexts, and attackers exploit this opacity by poisoning working memory knowing that attribution of the poisoned fact to a specific agent becomes unclear in shared memory monitoring.

For example, when Agent A writes a poisoned fact about network credentials into shared working memory and Agent B subsequently reads and acts on it, monitoring records both the write and the read as normal memory operations; because no log captures which agent's read led to which action, the credential exfiltration cannot be attributed to either agent's working memory access.

Standard defenses such as shared memory access logs and agent activity monitoring are insufficient because they record memory operations without linking specific facts to the downstream actions they influenced, leaving causal chains between poisoned memory content and agent behavior untraced.

**Multi-agent distinction:** In single-agent systems, working memory is private and read-write provenance is trivial to attribute; in multi-agent systems with shared working memory, any agent can read any fact written by any other agent, and the absence of per-agent write provenance means a poisoned fact influences every agent's retrieval results simultaneously without triggering per-agent anomaly detection.
