# 12.3.8 Semantic Memory Query Logging Gaps Enabling Audit Evasion [NoFW]

RAG query logging is selectively disabled or sampled for performance reasons; adversaries who probe the logging coverage can identify which query patterns are not recorded and craft attack queries that consistently avoid instrumented paths, leaving no audit trail.

For example, an attacker systematically probes the logging infrastructure by issuing queries across varying embedding dimensions, query lengths, and time intervals to determine which categories are excluded from sampling; once the unlogged query characteristics are identified, all subsequent attack queries are crafted to match those characteristics, ensuring the attack traffic generates no audit records regardless of its frequency or impact.

Standard defenses such as sampled logging and query rate monitoring are insufficient because sampling by definition creates coverage gaps, and an adversary who maps the sampling coverage through probing can route all attack traffic through the unsampled intervals indefinitely without triggering any retention-based detection.

**Multi-agent distinction:** In multi-agent systems that share a centralized logging infrastructure, the logging coverage profile—which query patterns are sampled and which are excluded—is consistent across all agents; once an attacker identifies the logging gaps by probing through any one agent, the same unlogged paths are exploitable across every agent in the system simultaneously, making the discovery reusable for evasion at scale.
