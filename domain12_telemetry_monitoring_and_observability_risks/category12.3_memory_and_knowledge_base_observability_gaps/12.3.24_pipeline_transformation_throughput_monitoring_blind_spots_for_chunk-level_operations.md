# 12.3.24 Pipeline Transformation Throughput Monitoring Blind Spots for Chunk-Level Operations [NoFW]

ETL monitoring tracks document-level throughput (documents per second) without measuring chunk-level throughput; semantic chunking complexity varies dramatically per document, and document-level metrics can appear healthy while chunk-level processing throughput has degraded by an order of magnitude due to chunking algorithm performance regression.

For example, a regression in semantic boundary detection that increases per-chunk processing time from 2ms to 20ms causes document throughput to drop only 10% (from 50 to 45 docs/sec, below alert thresholds), yet chunk throughput falls 90% (from 5,000 to 500 chunks/sec), silently degrading knowledge base population for weeks before agents report poor retrieval coverage.

Standard defenses such as document-level throughput alerts and pipeline latency dashboards are insufficient because they measure coarse-grained document counts rather than the chunk-level operations that determine actual knowledge store population rate and quality.

**Multi-agent distinction:** In multi-agent systems where agents process documents with heterogeneous chunking complexity, document-level monitoring falsely implies one agent is slower when it actually handles more complex content; the shared knowledge store accumulates uneven domain coverage without any per-agent chunk-level signal to identify which pipeline stage is the bottleneck.
