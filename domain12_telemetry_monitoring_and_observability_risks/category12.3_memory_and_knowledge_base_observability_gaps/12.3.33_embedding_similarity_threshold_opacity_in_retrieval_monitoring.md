# 12.3.33 Embedding Similarity Threshold Opacity in Retrieval Monitoring [NoFW]

Multimodal RAG systems retrieve content based on embedding similarity thresholds but monitoring does not track whether retrieved content crossed thresholds marginally or comfortably, creating blind spots where agents retrieve barely-relevant content; in multi-agent systems attackers craft poisoned embeddings positioned just above retrieval thresholds that consistently retrieve malicious content while appearing legitimate in logs that show only which content was retrieved, not the proximity of each retrieval to the threshold boundary.

For example, an attacker who crafts a poisoned embedding with cosine similarity 0.71 to common medical query embeddings (just above a 0.70 retrieval threshold) ensures the malicious document is consistently retrieved for medical queries; monitoring logs show the document retrieved without recording that its similarity score was 0.71 versus 0.95 for legitimate documents, making the marginally-above-threshold positioning invisible to analysts.

Standard defenses such as retrieval result logging and content filtering are insufficient because they capture which documents were retrieved rather than the distributional signature of similarity scores, allowing threshold-hugging attacks to evade anomaly detection that would trigger on very low similarity values.

**Multi-agent distinction:** In multi-agent systems where a shared vector index serves all agents, a poisoned embedding positioned just above the retrieval threshold is retrieved by every agent querying semantically similar topics; the absence of per-agent similarity score distribution monitoring means the shared retrieval vulnerability is multiplied across all agents with no attribution to the specific index entry responsible.
