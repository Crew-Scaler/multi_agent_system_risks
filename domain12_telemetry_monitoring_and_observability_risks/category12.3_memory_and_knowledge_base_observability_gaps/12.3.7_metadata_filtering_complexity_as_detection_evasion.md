# 12.3.7 Metadata Filtering Complexity as Detection Evasion [NoFW]

Complex retrieval metadata filters combine temporal, contextual, and frequency-based conditions in ways that monitoring systems cannot exhaustively track; adversaries craft poisoned memory entries with retrieval conditions specifically designed to activate only under metadata combinations that fall outside instrumented monitoring coverage.

For example, an attacker crafts a poisoned knowledge entry that retrieves only when metadata filters simultaneously specify time-of-day between 02:00 and 04:00, user-role=service-account, and project-id=prod-infra; monitoring that samples queries during business hours and tracks only common filter combinations never observes a retrieval event for this entry, even though it activates consistently during off-hours maintenance windows.

Standard defenses such as query logging and retrieval auditing are insufficient because they record which entries were retrieved under which metadata conditions but do not enumerate which filter combinations were evaluated and found non-matching, leaving conditional trigger activation conditions permanently undocumented in the audit record.

**Multi-agent distinction:** In multi-agent systems, each agent contributes its own metadata context to shared retrieval calls, creating a combinatorial space of cross-agent metadata attribute combinations far larger than any single-agent deployment; monitoring cannot enumerate all combinations that could trigger conditional poisoned entries, and attackers can design trigger conditions that activate only under cross-agent metadata configurations that have never appeared in any instrumented monitoring interval.
