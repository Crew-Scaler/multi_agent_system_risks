# 12.5.34 Error Recovery Patterns Invisible in Distributed Tracing [NoFW]

Error recovery in multi-agent systems distributes across agents (Agent A detects failure, Agent B implements retry, Agent C verifies recovery); per-agent distributed tracing captures each agent's local recovery actions but not the cross-agent recovery orchestration, creating "recovery blindness" where monitoring cannot determine whether distributed recovery actually restored the system to a correct state.

For example, when a data ingestion agent (Agent A) detects a database timeout and signals a retry agent (Agent B) to re-execute the query, Agent B logs a successful retry and a verification agent (Agent C) logs a successful check, but no monitoring system assembles these distributed traces to confirm that the recovered data matches the original failed transaction, leaving a potential silent data corruption undetected.

Standard defenses such as per-agent retry logging and distributed tracing systems are insufficient because distributed tracing correlates timing and request identifiers but not the semantic correctness of recovery outcomes, and no single trace aggregator reconstructs whether cross-agent coordination restored system state to a valid point.

**Multi-agent distinction:** Recovery blindness is a structurally multi-agent problem: in a single-agent system, the full recovery lifecycle is observable within one process boundary; in multi-agent systems, the detection, execution, and verification of recovery are distributed across independent agents whose logs cannot be assembled into a unified recovery outcome without purpose-built cross-agent orchestration monitoring that is absent from standard distributed tracing tooling.
