# 12.5.14 Audit Trail Integrity Violations Through Evaluation Log Tampering [NoFW]

Evaluation logs that serve as quality decision audit trails are writable by agents or have modifiable timestamps; adversaries can retroactively alter evaluation logs to make malicious changes appear to have passed evaluation in historical runs, destroying the evidentiary basis for quality governance.

For example, an attacker with write access to the evaluation log store can update the timestamp and result fields of last week's failed security evaluation to show a pass, permanently rewriting the historical record used by auditors to confirm that quality gates were respected before deployment.

Standard defenses such as append-only log policies and log backup schedules are insufficient because they protect against log deletion but not against modification, and tamper-evident logging is rarely deployed for evaluation pipelines despite being standard practice for security-critical audit logs.

**Multi-agent distinction:** Single-agent evaluation logs represent one audit stream that can be protected in isolation; multi-agent evaluation systems maintain separate log streams per agent that may be stored in different systems with inconsistent tamper-protection policies, so an attacker can selectively modify the least-protected agent's log to alter the historical record while leaving others untouched.
