# 12.5.92 Auto-Scaling Configuration Blind Spots [NoFW]

Auto-scaling adds new agent replicas with potentially different monitoring configurations than the existing fleet; newly provisioned replicas may lack telemetry collectors, have different logging levels, or be missing alert rules that the baseline fleet has, creating monitoring coverage inconsistencies that grow with fleet scale and provide adversaries with under-monitored entry points.

For example, when a load spike triggers auto-scaling that provisions new agent replicas from a base container image predating the latest telemetry-collector configuration, the new replicas operate without structured logging, and all tool invocations and reasoning traces on those replicas are invisible to the fleet's monitoring stack until the configuration gap is manually corrected.

Standard defenses such as golden-image policies and configuration management are insufficient in fast-scaling environments because auto-scaling events occur asynchronously, and monitoring coverage verification is rarely included in the scale-out health check that declares new replicas ready to receive traffic.

**Multi-agent distinction:** In multi-agent systems, auto-scaling affects different agent roles independently, so scaling events for high-demand orchestrator agents may introduce under-monitored instances at the coordination layer—where tool delegation and inter-agent routing decisions originate—creating the largest possible monitoring gap at the highest-privilege point in the agent hierarchy.
