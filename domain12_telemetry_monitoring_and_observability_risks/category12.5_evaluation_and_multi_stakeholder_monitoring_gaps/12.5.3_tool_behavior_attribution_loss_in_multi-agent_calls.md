# 12.5.3 Tool Behavior Attribution Loss in Multi-Agent Calls [NoFW]

Batched or parallel tool invocations from multiple agents are attributed to aggregate infrastructure metrics rather than individual agents, making tool-level anomaly detection per agent impossible.

When multiple agents invoke shared tool endpoints in parallel, infrastructure monitoring aggregates tool-level metrics—latency, error rate, throughput—without preserving per-agent attribution, so a latency spike caused by Agent A injecting pathological queries into a shared database tool appears as an unexplained infrastructure anomaly rather than as Agent A's targeted manipulation. For example, an adversary who compromises Agent A to issue malformed queries that degrade tool performance for all downstream agents is invisible to security review because all agents' calls merge into a single tool-level metric stream with no originating agent recorded.

Standard defenses such as distributed tracing and infrastructure monitoring are insufficient because concurrent multi-agent calls interleave trace contexts in ways that break per-agent attribution at the tool layer, and aggregate tool health metrics are specifically designed to hide individual-agent outliers that could reveal the attack.

**Multi-agent distinction:** In single-agent architectures every tool call has an unambiguous originating process; in multi-agent architectures shared tool endpoints receive concurrent requests whose aggregation is necessary for infrastructure monitoring but destroys the per-agent attribution that anomaly detection requires to distinguish attack-originating agents from legitimate callers.
