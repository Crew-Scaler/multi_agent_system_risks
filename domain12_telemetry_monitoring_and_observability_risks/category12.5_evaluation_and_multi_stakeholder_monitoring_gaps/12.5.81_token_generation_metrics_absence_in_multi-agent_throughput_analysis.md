# 12.5.81 Token Generation Metrics Absence in Multi-Agent Throughput Analysis [NoFW]

Inference monitoring reports requests-per-second without tracking tokens-per-second; adversaries craft prompts that produce minimal token outputs (appearing as high-throughput healthy operations) while consuming disproportionate compute through expensive reasoning operations, and monitoring that tracks only request throughput cannot detect this compute-to-output ratio manipulation.

For example, an attacker who crafts prompts that instruct a reasoning agent to perform expensive multi-step internal verification before producing a one-sentence output can force an agent to consume tokens equivalent to a full document analysis while monitoring records only a single lightweight inference request, making repeated compute exhaustion attacks appear as normal high-throughput operation until infrastructure capacity is fully consumed.

Standard defenses such as rate limiting and per-user request quotas are insufficient because they count requests rather than compute consumed per request, and adversarial prompts that trigger disproportionate compute consumption while producing minimal output bypass request-count-based controls entirely.

**Multi-agent distinction:** In a single-agent system, compute-to-output ratio manipulation affects one serving endpoint and may be partially detectable through that endpoint's GPU utilization metrics; in a multi-agent pipeline where reasoning-intensive agents operate upstream of output-generating agents, the compute consumption is distributed across agents in a way that no single agent's metrics reveal the adversarial compute amplification pattern.
