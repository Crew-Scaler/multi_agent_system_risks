# 12.5.82 Cross-Agent Correlation Absent from Standard Monitoring [NoFW]

Standard Prometheus and Kubernetes monitoring collect per-service metrics without cross-service correlation capabilities; coordinated attacks that manifest as Agent A latency spikes correlating with Agent B failures (indicating attack propagation) appear in monitoring as two independent service events rather than as a correlated attack pattern, preventing detection of coordinated multi-agent campaigns through standard monitoring stacks.

For example, an attacker executing a decomposition attack routes phase one through Agent A (causing a 200ms latency spike that Prometheus records as an isolated service event) and phase two through Agent B 30 seconds later (causing an error rate increase that Prometheus records as a separate unrelated service event); standard monitoring shows two distinct, unrelated service degradations while the attacker's coordinated two-phase campaign completes undetected.

Standard defenses such as distributed tracing and service dependency mapping are insufficient because they capture causal chains within single request paths but not coordinated activity patterns that span multiple independent request paths with temporal separation, which is precisely the structure that decomposition attacks exploit.

**Multi-agent distinction:** In a single-agent system, all attack activity appears in one metric stream where temporal correlation is trivially computable; in a multi-agent system, correlated attack phases distributed across N agents produce N independent metric streams that standard monitoring infrastructure never joins, making cross-agent correlation a capability that must be explicitly built rather than one that emerges naturally from per-service monitoring.
