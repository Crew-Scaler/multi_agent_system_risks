# 12.5.86 Cross-Agent Coordination Timing Blind Spots [NoFW]

Per-agent latency monitoring does not track inter-agent communication timing patterns; adversaries who exploit kernel timing or KV cache characteristics to create specific latency patterns in one agent that trigger malicious behavior when propagated to a dependent agent execute timing-based cross-agent attacks that are completely invisible to individual-agent telemetry.

For example, an attacker who exploits KV cache contention in a gateway agent to introduce a precisely timed 80ms response delay causes a dependent execution agent to fall into a specific retry path that, due to a logic error in the retry handler, grants elevated tool access; since per-agent monitoring shows the gateway agent's p95 latency as within normal variance and the execution agent's elevated tool access as a single brief anomaly, no timing-based cross-agent causal chain is ever reconstructed from available telemetry.

Standard defenses such as per-agent latency SLO monitoring and retry logic audits are insufficient because they evaluate each agent's timing and behavior independently without constructing the inter-agent timing relationship graph needed to detect that specific latency values in one agent deterministically trigger specific behavioral states in dependent agents.

**Multi-agent distinction:** In a single-agent system, all timing effects originate and manifest within one process, making timing-based vulnerabilities detectable through single-process profiling; in a multi-agent system, timing-based attacks propagate across agent boundaries where the causal link between a latency event in one agent and a behavioral consequence in another agent is never computed by any standard monitoring system.
