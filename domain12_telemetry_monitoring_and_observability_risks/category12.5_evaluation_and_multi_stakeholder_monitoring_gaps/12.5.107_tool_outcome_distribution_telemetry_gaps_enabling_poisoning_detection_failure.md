# 12.5.107 Tool Outcome Distribution Telemetry Gaps Enabling Poisoning Detection Failure [NoFW]

Tool success rates and outcome distributions critical for expected utility calculation are not systematically monitored or logged; when attackers poison outcome distribution assumptions by modifying agent beliefs about tool success rates, monitoring has no ground truth to detect the deviation, and in multi-agent systems with shared tool registries, poisoned outcome distributions affect all querying agents simultaneously while individual agents with local tool models might detect inconsistency that shared-registry deployments cannot.

For example, an attacker who modifies an agent's internal tool-success-rate priors to underestimate a security tool's reliability causes the agent to avoid invoking it for low-confidence decisions; observed tool call logs show normal invocation frequency for high-confidence cases, so outcome distribution monitoring that only tracks actual call outcomes has no signal that the agent's belief about the tool has been poisoned.

Standard defenses such as tool success-rate dashboards and failure-rate alert thresholds are insufficient because they measure actual observed outcomes rather than agents' internal beliefs about expected outcome distributions; an agent can operate on a poisoned probability model while all observed tool outcomes appear within normal ranges.

**Multi-agent distinction:** In multi-agent systems with shared tool registries, poisoning the outcome distribution model stored in the registry affects all agents that pull their tool priors from it simultaneously, creating uniform misestimation across the fleet that cannot be detected by per-agent outcome analysis because no individual agent's behavior deviates from its corrupted prior.
