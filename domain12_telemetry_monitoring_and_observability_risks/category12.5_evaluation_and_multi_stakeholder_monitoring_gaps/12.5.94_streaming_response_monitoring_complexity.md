# 12.5.94 Streaming Response Monitoring Complexity [NoFW]

Streaming responses in batched multi-agent contexts create boundary misalignment between batch processing units and response streaming units; per-request attribution in monitoring becomes unreliable when response boundaries do not align with batch boundaries, preventing accurate characterization of individual streaming responses' contribution to aggregate metrics.

For example, when an LLM inference batch groups three concurrent agent requests and streams their combined output, the per-request response boundaries within the batch may not align with the streaming framing, causing monitoring systems to attribute completion tokens to the wrong agent request and mischaracterize which agent produced which content.

Standard defenses such as request-ID tagging and per-token logging are insufficient because streaming batch implementations may interleave or reorder tokens across logical requests before they are flushed to the log sink, destroying per-request attribution fidelity before monitoring has any opportunity to enforce correct boundaries.

**Multi-agent distinction:** In multi-agent systems, different agent types generate outputs at different token rates, increasing the probability that high-throughput agents' tokens merge with low-throughput agents' tokens in shared streaming buffers; the resulting cross-agent token interleaving makes individual agent output attribution unreliable across the entire monitoring stack.
