# 12.5.90 Caching Creating Hit/Miss Monitoring Blind Spots [NoFW]

Cache hits bypass real-time tool invocation and RAG pipeline execution, making those operations invisible to tool invocation monitoring; an agent that primarily queries cached results appears to have no tool usage in monitoring while actually relying on cached outputs from previous tool invocations, and poisoned cached content drives agent behavior without generating any current-period monitoring signal.

For example, if a RAG pipeline's vector-store cache is poisoned with malicious retrieval content, subsequent agent queries that hit the cache drive decisions based on poisoned documents without generating any new retrieval telemetry, making the manipulation completely invisible to tool-invocation monitoring from the moment the poison is installed.

Standard defenses such as retrieval-pipeline audit logging and tool-invocation anomaly detection are insufficient because cache hits bypass the instrumented retrieval code paths entirely, leaving no event for anomaly detectors to analyze; the poisoned content influences agent behavior without ever appearing as a logged operation in the current monitoring window.

**Multi-agent distinction:** In multi-agent systems, a shared semantic cache serving multiple agent types allows poisoned cache content to silently influence every agent simultaneously, while per-agent monitoring shows no tool invocations and therefore no anomalies across the entire fleet, defeating distributed detection strategies that depend on per-agent signals.
