# 12.5.83 GPU Telemetry Insufficient for Detecting Quantization-Based Attacks [NoFW]

Standard GPU monitoring metrics (utilization percentage, memory usage, temperature, power draw) do not capture quantization-layer behavior (activation range distributions, per-layer precision loss, KV cache integrity); quantization-based instruction injection attacks that operate at the model weight precision level produce no GPU-level anomalies and remain completely invisible to DCGM-based fleet monitoring.

For example, an attacker who modifies quantization calibration data during model preparation shifts specific layer activation ranges so that certain input patterns trigger precision underflow in those layers; the resulting behavioral manipulation produces no change in GPU utilization, memory usage, temperature, or power draw metrics, leaving DCGM-based fleet monitoring completely blind to the compromise for the full deployment lifetime of the manipulated model.

Standard defenses such as GPU memory usage monitoring and inference throughput tracking are insufficient because quantization precision manipulation operates at the numerical representation level within existing compute and memory budgets—a poisoned quantized model consumes identical GPU resources to a clean one, producing no hardware-level telemetry anomaly that standard monitoring can detect.

**Multi-agent distinction:** In a single-agent system, a quantization-based attack compromises one inference endpoint; in a multi-agent fleet where all agents share the same quantized model artifact, quantization manipulation deployed through normal model update channels simultaneously compromises every agent in the fleet without triggering any per-agent GPU telemetry anomaly, making fleet-wide silent compromise a direct consequence of shared model distribution and absent quantization-layer monitoring.
