# 12.5.66 Tool Invocation Audit Log Blind Spots in Service Mesh [NoFW]

Service mesh network logs capture connection endpoints and byte counts but not semantic content of agent-to-agent tool invocations; attackers routing malicious instructions through service mesh connections evade semantic audit coverage, as mesh logs show "Agent A called Agent B's tool endpoint" without logging the instruction content or parameters passed in the call.

For example, an attacker who gains control of an intermediate broker agent passes a prompt-injection payload as a tool invocation parameter from Agent A to Agent B's code-execution tool; the service mesh audit log records "Agent A → Agent B: /execute_tool POST 2KB" while the malicious instruction content remains entirely outside the audit record, leaving investigators unable to reconstruct the attack chain from available telemetry.

Standard defenses such as TLS inspection and web application firewalls are insufficient because they operate on network payloads without understanding agent-specific protocol semantics, so they cannot distinguish legitimate tool parameters from injected instructions encoded in structurally valid JSON bodies.

**Multi-agent distinction:** In a single-agent system, all tool invocations originate from one process whose reasoning context can be directly inspected; in a multi-agent system, tool invocations traverse inter-agent boundaries where only the transport layer is observable, creating semantic audit gaps proportional to the number of agent-to-agent handoffs in each workflow path.
