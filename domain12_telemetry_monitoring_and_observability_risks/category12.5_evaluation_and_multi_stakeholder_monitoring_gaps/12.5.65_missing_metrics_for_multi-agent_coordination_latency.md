# 12.5.65 Missing Metrics for Multi-Agent Coordination Latency [NoFW]

Standard Kubernetes pod metrics capture per-pod latency but not inter-pod communication latency for multi-agent message passing and coordination; attackers can degrade inter-agent communication performance without triggering standard per-pod latency alerts, as coordination overhead is invisible to monitoring that captures only intra-pod processing time.

For example, an attacker who introduces artificial delays into inter-agent message queues between a planning agent and its execution workers causes the execution agents to appear idle in pod-level latency metrics while the coordination channel becomes a bottleneck degrading end-to-end task completion rates—an attack pattern invisible to any standard Kubernetes horizontal pod autoscaler or per-pod SLO dashboard.

Standard defenses such as service mesh latency monitoring and distributed tracing are insufficient because they capture network-layer round-trip times between services but do not instrument the semantic orchestration queue depths and message-waiting intervals that characterize multi-agent coordination overhead.

**Multi-agent distinction:** In a single-agent system, all processing latency is collocated within one pod's metrics; in a multi-agent system, the coordination latency between agents constitutes a distinct observability domain that falls into the gap between pod-level metrics (measuring intra-pod computation) and network-level metrics (measuring raw packet transit), leaving orchestration bottlenecks systematically unmeasured.
