# 12.5.32 Tool Execution Errors Hidden in Aggregated Success Rates [NoFW]

Tool execution success rates aggregated by tool type rather than by originating agent hide agent-specific parameter accuracy problems; an agent that systematically passes incorrect parameters to a tool appears in monitoring as a tool reliability issue rather than an agent accuracy issue, preventing correct root cause attribution.

For example, in a financial data pipeline where Agent A queries a database tool by passing malformed date range parameters, the tool returns an error on every call from Agent A; but because tool-level monitoring aggregates the 87% success rate across all agents using the same tool (where Agents B and C succeed at 99%), Agent A's systematic failure appears as a tool reliability anomaly at 87% rather than a parameter correctness problem in Agent A, misdirecting remediation to tool infrastructure.

Standard defenses such as tool-level success rate monitoring and per-tool SLA dashboards are insufficient because they aggregate failures by tool rather than by calling agent, so agent-specific parameter accuracy problems are permanently attributed to tool infrastructure rather than to the agent producing invalid parameter values.

**Multi-agent distinction:** In multi-agent systems, tool-level metric aggregation creates a mismatch between where failures originate (in one agent's parameter generation) and where they appear in monitoring (in the tool's aggregate success rate), so neither the tool's operators nor other agents' operators can identify which agent's behavior requires remediation; this attribution gap does not exist in single-agent systems where tool call errors are directly tied to the single calling entity.
