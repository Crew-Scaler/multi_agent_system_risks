# 12.5.57 MLflow Metrics Aggregation Hiding Individual Agent Regressions [NoFW]

MLflow aggregates experiment metrics across all test agents using averages and percentiles; an experiment that improves 9 agents by 5% while degrading one agent by 95% shows aggregate improvement that masks the severe outlier regression, and aggregate passing evaluation criteria lead to deployment that creates severe degradation for the affected agent.

In a content moderation MAS where 10 specialized agents handle different content categories, a model update evaluated across all agents shows +5% average accuracy improvement; however, the update introduces a catastrophic accuracy regression in the hate-speech detection agent, reducing its detection rate from 90% to 4.5%; MLflow reports the experiment as passing all aggregate metric thresholds while the regression in the highest-risk content category is deployed to production undetected.

Standard defenses such as mean accuracy thresholds, percentile-based evaluation, and aggregate experiment passing criteria are insufficient because statistical averaging explicitly obscures outliers by design, and no standard MLflow metric configuration surfaces per-agent outlier analysis or requires all-agents-pass criteria rather than average-passes criteria.

**Multi-agent distinction:** Evaluation aggregation creates an incentive-misaligned safety property unique to multi-agent systems: improving many agents slightly while catastrophically degrading one agent can pass any average-based evaluation gate, and in multi-agent fleets where different agents handle different risk levels, the degraded agent may be the highest-risk specialist whose failures have the most severe consequences, yet aggregate metrics have no mechanism to apply per-agent risk weighting to evaluation outcomes.
