# 12.5.50 Vector Database Query Latency Hiding Semantic Drift [NoFW]

Vector database monitoring tracks query latency as a health proxy, but semantic drift from poisoned embeddings or corrupted HNSW graph structures causes fast queries that return wrong results; agents querying a semantically corrupted vector database experience correct latency metrics while operating on degraded retrieval content, and in multi-agent deployments all agents share this false health signal.

For example, an adversary who gains write access to a shared vector database poisons 10% of document embeddings with semantically shifted vectors that map unrelated concepts to close proximity; all subsequent retrieval queries return low-latency results with high similarity scores, but the returned documents are contextually incorrect; monitoring dashboards show green health status based on latency and similarity score metrics while every agent using the database operates on corrupted retrieval results.

Standard defenses such as query latency monitoring and index health checks are insufficient because they validate that the database infrastructure is functioning correctly rather than that the semantic content of the index is accurate; semantic drift from embedding poisoning or adversarial content injection produces operationally identical infrastructure metrics to a healthy index.

**Multi-agent distinction:** Vector database semantic drift represents a shared attack surface in multi-agent systems: a single database compromise affects all agents whose retrieval is grounded in that index simultaneously, and because the false health signal is emitted by the shared infrastructure, no individual agent's monitoring can detect the corruption without access to ground-truth retrieval quality labels that are rarely maintained in production.
