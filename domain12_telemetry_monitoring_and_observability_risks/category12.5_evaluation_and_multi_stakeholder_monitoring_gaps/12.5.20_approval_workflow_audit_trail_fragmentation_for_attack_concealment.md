# 12.5.20 Approval Workflow Audit Trail Fragmentation for Attack Concealment [NoFW]

Multi-agent approval workflows fragment audit trails across per-agent log streams at each agent handoff boundary; attacks that span the approval chain (manipulating the recommendation agent's output, the approval agent's decision, and the execution agent's action) leave evidence distributed across three separate logs with no unified audit trail connecting the manipulated chain.

For example, an attacker who manipulates the recommendation agent to suggest an unsafe deployment, the approval agent to fast-track it, and the execution agent to skip the rollback safeguard leaves one log entry in each agent's stream that individually appears routine—a recommendation, an approval, an execution—but the connecting thread showing that each step was manipulated to serve the same attack goal exists in no single log.

Standard defenses such as per-agent audit logging and centralized log aggregation are insufficient because aggregation collects logs from all agents but does not reconstruct the semantic chain connecting decisions across agents, leaving cross-agent attack causality invisible to any analyst reviewing aggregate logs.

**Multi-agent distinction:** Single-agent approval workflows produce a linear log of decisions that auditors can review as a coherent sequence; multi-agent approval workflows distribute the decision chain across agents whose logs are managed independently, creating structural fragmentation that makes cross-agent attack reconstruction impossible without unified provenance tooling that these pipelines do not deploy.
