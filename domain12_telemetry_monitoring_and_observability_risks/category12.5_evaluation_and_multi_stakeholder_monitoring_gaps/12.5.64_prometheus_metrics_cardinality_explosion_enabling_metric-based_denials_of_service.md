# 12.5.64 Prometheus Metrics Cardinality Explosion Enabling Metric-based Denials of Service [NoFW]

Prometheus metrics with unbounded label cardinality (labeled with user IDs, query contents, or dynamic identifiers) can be exploited by causing agents to emit high-cardinality metrics; in multi-agent fleets where all agents contribute to centralized Prometheus, coordinated high-cardinality metric emission overwhelms the monitoring system's storage capacity, causing fleet-wide monitoring blind spots.

For example, an attacker who can inject user-controlled strings into metric label values causes each agent replica to emit thousands of unique time series per minute; across a 20-agent fleet, this generates millions of distinct label combinations that exhaust Prometheus storage within hours, causing fleet-wide monitoring blindness at precisely the moment the attacker escalates to a more consequential second-stage attack.

Standard defenses such as label cardinality limits and metric relabeling rules are insufficient because they require operators to enumerate all potentially unbounded label dimensions in advance, and novel metric emission paths introduced through agent update cycles frequently escape the relabeling rule coverage.

**Multi-agent distinction:** In a single-agent system, cardinality explosion overwhelms only that agent's metric collection; in a multi-agent fleet sharing centralized Prometheus infrastructure, cardinality explosion from any one agent degrades monitoring coverage for all agents simultaneously, making the shared infrastructure a single point of denial-of-observability failure.
