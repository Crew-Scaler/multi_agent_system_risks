# 12.5.88 Load Balancer Routing Metrics Obscuring Agent-Level Behavior [NoFW]

Load balancer aggregate traffic distribution metrics show that requests are spread across replicas but mask individual replica behavior; an attack affecting one replica appears as normal aggregate load distribution, and per-replica anomaly detection requires additional instrumentation beyond standard load balancer metrics.

For example, when a compromised replica returns subtly wrong outputs to the 20% of users routed to it by weighted round-robin, aggregate load-balancer metrics show even traffic distribution and normal throughput, so the replica-level attack is invisible until per-replica output content analysis is added.

Standard defenses such as aggregate health checks and fleet-wide request-rate monitoring are insufficient because they average per-replica behavior into fleet-level signals that absorb single-replica anomalies without raising alerts; detecting the attack requires per-replica semantic output analysis that standard load-balancer instrumentation does not provide.

**Multi-agent distinction:** In multi-agent systems where different agent roles map to distinct replica pools, an attack confined to one agent role's replica set is doubly hidden—first by within-pool aggregation and second by cross-pool metrics that blend behaviors from functionally distinct agent types—so neither pool-level nor fleet-level monitoring surfaces the role-specific compromise.
