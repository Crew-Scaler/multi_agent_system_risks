# 12.5.45 Efficiency Metric Correlation Analysis Blind Spot [NoFW]

Efficiency monitoring tracks metrics such as latency, token count, and API calls in isolation; coordinated attacks that simultaneously elevate multiple metrics (high latency plus high tokens plus unusual API call patterns) reveal attack signatures only through cross-metric correlation that single-metric threshold monitoring does not perform.

For example, an adversary who injects a prompt causing an agent to enter a reasoning loop simultaneously increases latency (from 200ms to 2s), token count (from 500 to 4K), and API call frequency (retry loop generates 5× normal calls); each individual metric stays below its separate alert threshold because thresholds are calibrated per-metric in isolation, but the joint signature of high latency with high tokens with abnormal API calls is a clear attack indicator that correlated monitoring would detect.

Standard defenses such as individual metric dashboards and per-metric threshold alerts are insufficient because they assume metrics degrade independently, making them blind to coordinated attack patterns where multiple metrics co-vary in ways that are individually explainable but collectively anomalous.

**Multi-agent distinction:** Cross-metric correlation analysis is more difficult in multi-agent systems because metrics are collected from independent agents whose natural operational variations may appear correlated by coincidence; attackers exploit this by distributing the elevation of different metrics across different agents (one agent shows high latency, another shows high token count), so that no single agent's metrics require correlation analysis while the cross-agent coordinated pattern requires fleet-level correlation that monitoring systems do not perform.
