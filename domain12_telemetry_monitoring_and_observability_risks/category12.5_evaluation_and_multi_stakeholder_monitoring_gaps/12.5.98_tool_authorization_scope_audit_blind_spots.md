# 12.5.98 Tool Authorization Scope Audit Blind Spots [NoFW]

Authorization audit systems track which agents are authorized to invoke which tools, but multi-agent delegation creates accountability gaps; audit logs show "Agent A authorized to invoke Tool X" without visibility that Agent A delegated to Agent B which invoked Tool X using Agent A's authorization context, making the actual invoker appear authorized while the responsible agent was not the tool's authorized user.

For example, Agent A holds permission to invoke a database-write tool and delegates a subtask to Agent B; Agent B invokes the database-write tool using the propagated authorization context, but audit logs record the authorization as Agent A's valid credential rather than tracing the downstream delegation chain that placed the tool call in Agent B's hands.

Standard defenses such as role-based access control enforcement and authorization audit logs are insufficient because they record whether the invoking principal was authorized, not whether authorization was acquired through a legitimate delegation chain, allowing agents to exploit transitive authority without the audit trail reflecting the actual delegation path.

**Multi-agent distinction:** Delegation chains unique to multi-agent architectures allow authorization to propagate through multiple hops from the original authorized agent to the actual tool invoker; each hop is logged under the next principal's identity, dissolving the audit trail that would otherwise trace the invocation back to an unauthorized delegation origin.
