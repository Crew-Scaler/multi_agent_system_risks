# 12.5.47 Telemetry Processing Latency as Detection Evasion Window [NoFW]

Efficiency telemetry is collected and processed asynchronously with analysis occurring hours after events; adversaries executing rapid attacks finish before monitoring analysis identifies the anomaly, and in multi-agent systems where attacks can be coordinated across agents, the processing lag enables coordinated fleet-wide failures to complete and cover tracks before distributed monitoring detects anomalies across any individual agent's telemetry stream.

For example, when an adversary executes a prompt injection attack on a document processing agent that causes unauthorized data exfiltration within 30 seconds, telemetry events are queued for batch processing and anomaly analysis runs 4 hours later; by the time monitoring identifies the anomalous access pattern, the attack has completed and any ephemeral forensic signals have been overwritten by subsequent normal operations.

Standard defenses such as batch log analysis and scheduled anomaly detection runs are insufficient because their analysis cadence is designed for operational insight rather than real-time threat response, and the gap between event occurrence and analysis completion is a guaranteed evasion window that adversaries can exploit to conduct and complete attacks invisibly.

**Multi-agent distinction:** In multi-agent systems, telemetry processing lag creates compounded evasion opportunity: a coordinated attack executed across multiple agents simultaneously generates telemetry streams in each agent that are processed independently with independent lags, so cross-agent correlation needed to detect the coordinated attack cannot occur until all agents' telemetry streams have been collected and processed, a window that extends beyond any single agent's lag to the maximum lag across the entire fleet.
