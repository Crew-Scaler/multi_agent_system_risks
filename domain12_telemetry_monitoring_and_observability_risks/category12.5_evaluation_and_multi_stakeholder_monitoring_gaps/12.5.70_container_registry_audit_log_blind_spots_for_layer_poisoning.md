# 12.5.70 Container Registry Audit Log Blind Spots for Layer Poisoning [NoFW]

Container registry logs capture image push and pull events at the image level but do not perform semantic validation of layer contents; adversaries who push container images with poisoned layers affecting agent behavior are visible in registry audit logs as normal image pushes, and in multi-agent deployments where all agents pull from the same registry, a single poisoned image affects the entire fleet without triggering content-level audit alerts.

For example, an attacker with write access to a container registry pushes a new image whose base layer has been modified to inject a malicious shared library that intercepts LLM inference calls and silently modifies responses; the registry audit log records only "image push by authorized user" with a valid cryptographic signature, and when all agents in the fleet pull and deploy the updated image, the compromise is fleet-wide with no content-level audit evidence.

Standard defenses such as image signing and vulnerability scanning are insufficient because signing validates provenance but not behavioral semantics—a properly signed image from a compromised build pipeline passes signature verification while containing malicious layers—and vulnerability scanners look for known CVEs rather than behavioral backdoors introduced through supply chain manipulation.

**Multi-agent distinction:** In a single-agent system, a poisoned container image affects one deployment; in a multi-agent fleet where all agents share a common base image pulled from the same registry, a single poisoned image push is amplified across the entire agent fleet simultaneously, turning a single registry audit event into a fleet-wide compromise with no per-agent audit evidence of the behavioral change.
