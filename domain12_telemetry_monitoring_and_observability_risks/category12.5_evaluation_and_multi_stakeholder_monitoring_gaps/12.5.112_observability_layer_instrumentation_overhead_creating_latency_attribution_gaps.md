# 12.5.112 Observability Layer Instrumentation Overhead Creating Latency Attribution Gaps [NoFW]

Distributed tracing, metrics collection, and structured logging add 50–150 ms overhead per multi-agent request chain, but monitoring systems report total latency without separating instrumentation overhead from application processing time; operators misattribute performance differences between agents to application logic differences when the actual cause is asymmetric instrumentation overhead across heterogeneously-instrumented agents.

For example, when one group of agents runs full distributed tracing with span export while another group runs only Prometheus counter increments, a latency comparison between the two groups appears to show a 120 ms performance difference that engineers misattribute to application logic when the actual source is the asymmetric overhead of the heavier instrumentation stack.

Standard defenses such as end-to-end SLA monitoring and Apdex score tracking are insufficient because they measure aggregate user-perceived latency without isolating instrumentation overhead as a distinct contributor, making overhead-induced differences indistinguishable from genuine application performance differences in cross-agent comparisons.

**Multi-agent distinction:** In multi-agent systems, instrumentation heterogeneity arises naturally when different agent roles are deployed at different times with different observability configurations; the resulting latency attribution noise grows with system scale, systematically undermining the reliability of cross-agent performance comparisons that both performance analysis and security anomaly detection depend on.
