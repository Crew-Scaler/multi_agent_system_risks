# 12.5.91 Load Balancer Session Affinity Hiding Cross-Replica Attack Propagation [NoFW]

IP hash session affinity confines user sessions to specific replicas, hiding cross-replica attack propagation within load balancer routing decisions; malware propagating through routing choices is invisible in per-replica logs that show only traffic directed to each replica without surfacing how routing decisions connect cross-replica propagation chains.

For example, when an attacker exploits IP-hash session affinity to pin their sessions to the same compromised replica, all other replicas show no anomalies and cross-replica propagation analysis finds no suspicious traffic movement; the attack operates exclusively on the affinity-pinned replica, and monitoring interprets the concentrated malicious traffic as a legitimate routing artifact.

Standard defenses such as per-replica health monitoring and individual-session anomaly detection are insufficient because session-affinity routing deliberately confines traffic patterns to specific replicas, so within-replica analysis finds nothing unusual and cross-replica comparison lacks the routing context needed to distinguish affinity-caused concentration from deliberate attack isolation.

**Multi-agent distinction:** In multi-agent systems, affinity-based routing can confine attack propagation to the replica pool serving a specific agent role, hiding the compromise entirely within that role's infrastructure while fleet-wide monitoring sees normal traffic distribution across all roles and raises no alerts.
