# 12.5.75 MLflow Logging Gaps in Distributed Optimization [NoFW]

Optimization decisions propagated through agent-to-agent communication channels are not logged to MLflow if agents do not explicitly call logging APIs for each communicated decision; in distributed multi-agent optimization where coordination occurs through message passing rather than centralized decision-making, entire optimization dimensions remain outside MLflow's observability coverage.

For example, in a distributed hyperparameter optimization workflow where one agent discovers that reducing regularization improves a local metric and communicates this finding directly to a peer agent that acts on it, neither the discovery nor the decision to adopt it is logged to MLflow because both occurred as agent-to-agent messages rather than explicit MLflow API calls; an attacker who injects a manipulated optimization signal into this message channel poisons the optimization trajectory without creating any MLflow artifact that would reveal the manipulation.

Standard defenses such as centralized decision logging requirements and MLflow auto-instrumentation are insufficient because auto-instrumentation captures only operations occurring through monitored library calls and cannot intercept arbitrary agent-to-agent message-passing channels that implement optimization coordination outside established logging frameworks.

**Multi-agent distinction:** In a single-agent optimization system, all optimization decisions occur within one process boundary and are captured by instrumentation applied at that boundary; in a distributed multi-agent optimization system, optimization decisions emerge from inter-agent communication channels that have no natural instrumentation boundary, creating observation gaps at every agent-to-agent interface.
