# 12.5.101 Streaming Error Handling Telemetry Missing Intermediate State Visibility [NoFW]

Error handling in streaming contexts creates temporary error states that resolve before response completion, but telemetry may not capture transient error states focused on final outcomes; in multi-agent streaming coordination, attacks exploiting streaming error handling behavior (temporary failures triggering fallback paths that complete before monitoring notices) leave minimal telemetry evidence because standard streaming telemetry captures completed responses rather than intermediate error resolution states.

Standard defenses such as error-rate alerting and fallback-path logging are insufficient because they record entry into and exit from fallback paths without capturing the transient error state that triggered the transition, leaving the causal link between a crafted error condition and the exploited fallback response entirely unrecorded in telemetry.

**Multi-agent distinction:** In multi-agent systems, a fallback path triggered by a transient error in Agent A may route work to Agent B, which operates on different data and with different privileges; the intermediate error state that caused the routing shift is invisible to Agent B's monitoring, preventing detection of cross-agent fallback exploitation where the crafted error in one agent's stream exploits capabilities available only through the fallback handler in another.
