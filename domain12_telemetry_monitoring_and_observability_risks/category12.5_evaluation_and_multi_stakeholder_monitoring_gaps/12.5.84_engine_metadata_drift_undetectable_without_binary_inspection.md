# 12.5.84 Engine Metadata Drift Undetectable Without Binary Inspection [NoFW]

TensorRT engine binaries are opaque at runtime; monitoring systems cannot detect filesystem-level tampering with cached engine files unless explicit binary hashes are computed and compared, and in multi-agent fleets with hundreds of cached engines across many edge locations, comprehensive continuous binary validation is operationally infeasible at scale.

For example, an attacker with write access to the filesystem cache directory of a Kubernetes persistent volume containing TensorRT engine files overwrites one engine binary with a manipulated version that produces different inference behavior for specific input patterns; monitoring reports normal inference latency and throughput because the manipulated engine processes most inputs identically to the original, and no file-integrity alert fires because the continuous binary hash comparison required to detect the change is not operationally deployed at the fleet's scale.

Standard defenses such as file integrity monitoring (FIM) and container immutability are insufficient because TensorRT engine caches are typically stored on persistent volumes or bind-mounted host paths that exist outside container filesystem immutability guarantees, and FIM systems configured to monitor thousands of large binary files across hundreds of edge locations generate monitoring overhead that operators disable under production storage constraints.

**Multi-agent distinction:** In a single-agent deployment with one or a few cached engine files, binary validation is operationally feasible; in a multi-agent fleet with hundreds of agents across many edge locations each maintaining independent engine caches, the total binary validation surface scales as O(agents × models × engine variants), making comprehensive continuous validation infeasible and leaving engine integrity gaps across the entire fleet.
