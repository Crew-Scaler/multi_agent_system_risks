# 12.5.13 Evaluation Performance Monitoring Blind Spots [NoFW]

Evaluation scripts and frameworks are not subject to the same performance monitoring applied to production code; adversaries can trigger exponential resource consumption in evaluation loops (by crafting inputs that cause inefficient metric computation) to cause evaluations to time out, preventing quality gates from executing and clearing the path for unvalidated deployment.

For example, an adversary who submits an evaluation input that triggers O(n²) metric computation across a large test corpus can cause the evaluation process to exhaust its time budget without completing, leaving the deployment gate in a "not evaluated" state that the CI/CD pipeline treats as a pass rather than a failure.

Standard defenses such as evaluation timeout handling and resource quota enforcement are insufficient because they prevent runaway evaluation from blocking deployment indefinitely but do not treat timeout as a quality failure, allowing adversarially-triggered timeouts to serve as evaluation bypass rather than as an anomaly requiring investigation.

**Multi-agent distinction:** In single-agent evaluation resource issues are localized to one evaluation process; in multi-agent evaluation where different evaluator agents contribute to a shared result, a resource exhaustion attack against one evaluation agent can propagate to the coordinating orchestrator, potentially causing the entire evaluation suite to time out and be skipped while each individual agent's failure appears as an isolated infrastructure issue.
