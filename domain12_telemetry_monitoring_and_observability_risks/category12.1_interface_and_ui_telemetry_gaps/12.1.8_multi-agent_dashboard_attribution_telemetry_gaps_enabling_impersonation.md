# 12.1.8 Multi-Agent Dashboard Attribution Telemetry Gaps Enabling Impersonation [NoFW]

Dashboard telemetry records which agent label generated content but does not capture whether that agent's identity was verified at each handoff point, making impersonation attacks and identity spoofing invisible to audit.

For example, a compromised orchestration layer forwards a message claiming to originate from the "Security Policy Agent" without cryptographically re-authenticating the identity claim at the handoff boundary; the dashboard displays the attributed recommendation to disable two-factor authentication, logs "Security Policy Agent recommends disabling MFA," but telemetry does not record whether the identity was verified at the handoff—leaving impersonation attacks indistinguishable from legitimate agent communication in the audit trail.

Standard defenses such as agent-level API keys and message signing are insufficient when multi-agent systems pass identity information as message metadata rather than binding it cryptographically at every handoff; telemetry that logs only the claimed attribution string cannot distinguish a legitimate message from a spoofed one that successfully propagated through one unverified boundary.

**Multi-agent distinction:** In single-agent systems attribution is trivial because there is one source and one process; in multi-agent dashboards identity claims traverse multiple handoff boundaries before reaching the display layer, and the absence of per-boundary identity-verification telemetry means a single spoofed handoff anywhere in the chain corrupts the complete attribution graph without leaving a detectable trace in any individual agent's logs.
