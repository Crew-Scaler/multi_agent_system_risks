# 12.1.7 Context Awareness Telemetry Missing Cross-Session State Poisoning Indicators [NoFW]

Per-session telemetry does not track how context evolves across session boundaries or how poisoned state injected in one session propagates through shared agent memory to affect subsequent sessions and users.

For example, an attacker injects a malicious instruction into a shared agent memory store during a customer service session; the instruction persists across subsequent sessions as different users interact with agents that silently load the shared context, biasing recommendations across multiple unrelated users over days before anyone detects the behavioral drift—and session-scoped telemetry for each individual interaction shows nothing anomalous because the poisoned state arrived as trusted prior context at session load time.

Standard defenses such as session authentication and in-session content filtering are insufficient because they apply to individual sessions in isolation and cannot detect poisoning introduced in a prior session; shared memory stores are loaded without integrity verification, and by the time an affected session begins, the malicious content has already bypassed all per-session guards.

**Multi-agent distinction:** In single-agent deployments persistent state belongs to one agent and can be audited as a bounded unit; in multi-agent systems context is shared across specialized agents and can be modified by any agent with write access, making the provenance of any given piece of persistent state impossible to reconstruct from session-scoped telemetry and leaving cross-session, cross-agent state poisoning structurally invisible to standard monitoring.
