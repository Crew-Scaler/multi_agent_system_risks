# 12.1.13 HITL Monitoring Telemetry Blind Spots [NoFW]

Human-in-the-loop workflows track aggregate metrics such as overall approval rate and average review time but do not log the trigger metrics that caused a human to intervene, the pre-intervention agent state, or the counterfactual value of each intervention, preventing systematic improvement of monitoring UIs and human oversight effectiveness.

For example, an operator monitoring a trading algorithm notices one position losing quickly and pauses the system at 14:37, preventing a $50K loss; telemetry records "paused at 14:37" but not which metric exceeded which threshold, how the operator's dashboard was configured at the moment of decision, how long review took, or what the system would have done unchecked—preventing the monitoring team from ever improving alert thresholds to catch similar near-misses automatically rather than relying on human attentiveness.

Standard defenses such as aggregate performance dashboards and escalation policies are insufficient because they track outcomes (whether the system was paused, whether trades were cancelled) rather than the human cognitive process (which indicator triggered concern, how the display state influenced the decision) that determines whether oversight was effective or merely lucky.

**Multi-agent distinction:** In single-agent HITL workflows an intervention involves one agent's state and is bounded in scope; in multi-agent HITL deployments an intervention may propagate to halt or redirect multiple dependent agents, and aggregate metrics obscure which agents benefited from human oversight versus which operated without effective review—making it structurally impossible to identify where monitoring coverage is thin across the fleet and target improvements accordingly.
