# 12.1.5 Command Palette Suggestion Telemetry Missing Context Manipulation Indicators [NoFW]

AI-driven command palette suggestions are logged by outcome (which command was executed) but not by context provenance (which signals triggered the suggestion), making it impossible to detect when poisoned cross-agent context causes malicious commands to surface as legitimate suggestions.

For example, an attacker poisons the documentation-retrieval agent's output to include false environment metadata ("environment: production" replaced with "environment: test"), causing the command palette aggregation layer to surface "Truncate audit log table" as a legitimate suggestion; telemetry records only that the user executed the truncation, not the poisoned context signal from the upstream agent that caused the dangerous command to appear in the palette.

Standard defenses such as allowlists of permitted commands and validation of command palette inputs are insufficient because the attack operates at the context aggregation layer upstream of suggestion generation; by the time a malicious command surfaces in the palette, the context manipulation has already succeeded invisibly in a contributing agent whose output is not separately logged.

**Multi-agent distinction:** In single-agent systems context and suggestion generation share a process boundary, making context provenance instrumentable at one location; in multi-agent systems context signals arrive from multiple independent agents before aggregation, and telemetry that logs only final suggestion outcomes cannot attribute which upstream agent's output triggered a malicious suggestion—leaving the context manipulation entirely outside the observable audit surface.
