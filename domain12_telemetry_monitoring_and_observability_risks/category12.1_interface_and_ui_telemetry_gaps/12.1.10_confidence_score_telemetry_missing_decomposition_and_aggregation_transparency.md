# 12.1.10 Confidence Score Telemetry Missing Decomposition and Aggregation Transparency [NoFW]

Displayed confidence scores are logged as final aggregate values without capturing the per-agent sub-scores, weighting logic, or aggregation method, making it impossible to detect manipulation of individual agent contributions that shift composite scores toward attacker-preferred values.

For example, in a multi-agent fraud detection pipeline a compromised fraud-risk agent reports 95% confidence on a fraudulent transaction while the compliance agent correctly reports 60% concern; the displayed composite score of 85% misleads the human reviewer into approving the transaction, but telemetry captures only "displayed confidence: 85%, decision: approved" without the per-agent sub-scores or the weighting formula that combined them—making post-incident investigation unable to identify which contributing agent was manipulated.

Standard defenses such as confidence calibration audits and threshold-based approval gates are insufficient because they operate on final aggregate scores and cannot detect manipulation of individual contributing agents when only the composite value is logged; an attacker who compromises a high-weight contributing agent can shift the aggregate into an approval-triggering range while each individual agent's contribution remains unexamined.

**Multi-agent distinction:** In single-agent systems confidence scores have a single source and can be instrumented at generation time with minimal overhead; in multi-agent confidence aggregation pipelines the attack surface spans each contributing agent's score generation plus the aggregation logic itself, and without per-agent decomposition telemetry any individual agent's contribution manipulation is indistinguishable from legitimate inter-agent variation in the composite audit record.
