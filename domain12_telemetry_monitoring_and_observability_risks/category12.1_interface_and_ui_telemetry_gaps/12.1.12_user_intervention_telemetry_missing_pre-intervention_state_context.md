# 12.1.12 User Intervention Telemetry Missing Pre-Intervention State Context [NoFW]

Human override events record that an intervention occurred but not the distributed agent state at the moment of intervention, preventing learning from intervention patterns or determining whether an intervention blocked an attack or cancelled legitimate work.

For example, an operator cancels a pending database deletion at 14:37, but telemetry logs only "user cancelled operation at 14:37" without capturing which agents were active at that moment, what confidence scores were displayed, which context window informed the recommendation, or whether any contributing agent had been compromised; post-incident analysis cannot determine whether the intervention prevented an attack or disrupted legitimate automated work, and the monitoring team cannot learn from the event to improve automated detection thresholds.

Standard defenses such as action audit logs and approval gate records are insufficient because they document that an intervention occurred, not the multi-agent system state that necessitated it; the causal context needed to learn from human interventions and improve automated monitoring thresholds is discarded the moment the operator acts.

**Multi-agent distinction:** In single-agent systems the state at intervention time is contained within one agent's process and can be reconstructed from local logs; in multi-agent systems an intervention may simultaneously affect multiple in-flight agents each holding partial state in separate processes, and capturing a coherent distributed snapshot at the moment of human override requires infrastructure that standard event-level telemetry does not provide.
