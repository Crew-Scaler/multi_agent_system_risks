# 12.1.9 Inline Suggestion Telemetry Missing Rejection Pattern Analysis [NoFW]

Telemetry captures suggestion acceptance rates but not rejection events with their context or reason, preventing detection of compromised agents that systematically suggest dangerous patterns which users consistently reject.

For example, a compromised code-completion agent begins systematically suggesting SQL queries with missing parameterization; developers consistently dismiss these suggestions without reporting them, and telemetry records an unremarkable 20% overall acceptance rate while the pattern of security-relevant rejections—which would reveal the agent's shift toward suggesting vulnerable code—goes entirely uncaptured and the compromised agent continues operating without triggering any alert.

Standard defenses such as aggregate acceptance rate monitoring and periodic suggestion quality audits are insufficient because they analyze the positive signal (what was accepted) while entirely ignoring the negative signal (what was rejected and why), which is precisely the dimension that reveals a compromised or drifting agent in the absence of explicit user complaints.

**Multi-agent distinction:** In single-agent suggestion systems rejection patterns from one source accumulate into a meaningful aggregate signal; in multi-agent suggestion pipelines where code, documentation, security, and test agents each offer suggestions, cross-agent rejection rate comparison is required to detect that one agent's suggestions are rejected at anomalously high rates relative to peers—a comparison that session-level telemetry capturing only acceptance events cannot support.
