# 12.1.11 Session Persistence Telemetry Missing State Restoration Verification [NoFW]

Session restoration events are logged as successful loads without capturing integrity verification outcomes, making silent injection of malicious content into persistent state stores undetectable.

For example, an attacker with write access to a shared session database modifies stored conversation history between sessions, injecting an instruction that Agent A's safety filters would have blocked as live input; when the session resumes, Agent A loads the persisted state and treats the injected instruction as trusted prior context, executing the attack while telemetry shows only "session restored successfully"—with no integrity check outcome recorded.

Standard defenses such as database access controls and encrypted storage are insufficient because they prevent unauthorized external access but do not log integrity verification outcomes at restore time; silent modifications by insider threats or compromised adjacent agents with legitimate write access are indistinguishable from valid state in a log that records only the restoration event.

**Multi-agent distinction:** In single-agent systems restored state enters one trusted context and can be verified locally before use; in multi-agent systems session state is shared across multiple agents that may restore it independently from distributed storage, and without cross-agent consistency verification telemetry, state modified to target one agent's behavior can propagate inconsistently across the fleet without any individual agent detecting the discrepancy.
