# 11.5.8 Graph Traversal Path Non-Determinism in Distributed Graph Stores [NoFW]

Graph database queries may return multiple valid traversal paths for the same query. Poisoned relationships designed to activate along specific traversal paths avoid detection while remaining exploitable whenever the database selects the target path.

For example, a security policy graph contains a poisoned permission edge from role R to resource X; the distributed graph store selects the vulnerable traversal path on roughly 40% of queries depending on index scan order; a security evaluation that exercises the graph ten times passes six times, producing false assurance, while 40% of production queries grant unauthorized access via the poisoned edge.

Standard defenses such as read-once graph validation and path-whitelist enforcement are insufficient because validation that passes on one traversal provides no assurance about subsequent traversals; the graph store's path selection is not under the caller's control and may differ between test and production execution environments.

**Multi-agent distinction:** In a multi-agent system, multiple agents simultaneously traverse the shared graph for logically equivalent queries and may independently select different paths; Agent A may traverse the safe path and return a correct denial while Agent B simultaneously traverses the poisoned path and grants unauthorized access—a concurrent divergence that cannot occur in a single-agent system that issues one query and receives one traversal result.
