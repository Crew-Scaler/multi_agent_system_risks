# 11.5.10 Temporal Validity Window Boundaries Creating Intermittent Visibility [NoFW]

Knowledge documents with validity windows become visible intermittently when queries occur near temporal boundaries. The flickering visibility creates assurance gaps where behavior depends on query timing relative to validity periods, enabling time-aware adversarial content injection.

For example, an attacker injects a malicious authorization document with a validity window of exactly 09:00:00 to 09:01:00; an agent querying at 08:59:59 receives no result and correctly denies a transaction, while an agent querying at 09:00:00 retrieves the document and approves the same fraudulent transaction—a one-minute attack window that standard security testing, which rarely probes at second-level temporal granularity, will not exercise.

Standard defenses such as document content review and validity-period whitelisting are insufficient because they validate what a document says, not when it becomes visible; boundary-condition behavior requires testing at attacker-controlled exact timestamps that security evaluations do not enumerate.

**Multi-agent distinction:** In a multi-agent system, agents issuing logically identical queries at slightly different times near a validity boundary will receive different retrieval results—Agent A querying one second before the boundary sees nothing, while Agent B querying one second after sees the malicious document—causing their coordinated decisions to diverge based solely on timing, a race condition that a single agent querying once would never expose.
