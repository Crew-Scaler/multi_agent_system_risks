# 11.5.3 Multi-Agent Context Assembly Non-Determinism Creating Audit Blind Spots [NoFW]

Non-deterministic assembly of context from distributed memory sources means audit logs cannot reliably reconstruct the exact context that produced a given agent decision.

Context assembly concatenates system prompt, conversation history, retrieval results, and the current query into a single input; in multi-agent systems the order of concatenated retrieval results varies across executions due to non-deterministic retrieval ranking and asynchronous retrieval timing, shifting the effective position of security-critical instructions. An auditor attempting to reproduce an agent's decision replays the identical query but receives a different context assembly order in which a safety instruction now appears after the adversarial payload rather than before it, producing a different model output and rendering the audit log unverifiable.

Standard defenses such as output logging and query-response archiving are insufficient because they record what was produced but not the precise context assembly order that produced it; without a deterministic assembly transcript, post-hoc audits cannot confirm that any specific context caused any specific output.

**Multi-agent distinction:** In a multi-agent system, agents A and B assembling context from the same distributed retrieval sources may independently produce different assembly orderings for the same logical query; their decisions may diverge not because of different retrieved facts but because of different fact positions within their respective assembled contexts—a source of divergence that does not arise in single-agent systems that assemble context once and process it sequentially.
