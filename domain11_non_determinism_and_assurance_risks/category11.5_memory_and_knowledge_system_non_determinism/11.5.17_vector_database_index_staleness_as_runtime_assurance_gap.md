# 11.5.17 Vector Database Index Staleness as Runtime Assurance Gap [NoFW]

Vector database indexes become stale during corpus updates. Agents relying on fresh RAG results may receive outdated content during index update windows, creating security assurance gaps invisible to individual agents who cannot distinguish fresh from stale index state.

Vector database index rebuilds are triggered asynchronously by corpus modification events, and newly added or modified documents are not retrievable until the rebuild completes; during this window the index presents a snapshot of corpus state that predates the update while appearing current to any querying agent. For example, during an index rebuild triggered by the revocation of a compromised credential document, Agent A queries for that document at the midpoint of the rebuild and receives no results, incorrectly concludes the credential is absent from the authorized list (a false negative that differs from the pre-revocation false positive), and either over- or under-grants access depending on its policy logic; Agent B querying 60 seconds later against the completed fresh index receives the revocation notice and makes the correct decision.

Standard defenses such as query-time freshness headers and index-version metadata checks are insufficient because vector database APIs do not expose in-progress rebuild status through standard query interfaces; agents have no mechanism to detect that the index they are querying reflects a prior corpus state, and retry logic does not help when the rebuild completion time is not bounded.

**Multi-agent distinction:** In a multi-agent system, multiple agents querying the shared vector database across a rebuild window will issue identical queries against indexes at different stages of staleness; agents querying early in the window retrieve pre-update content while agents querying late retrieve post-update content, causing the same logical query to produce different retrieval results across the fleet simultaneously—a collective knowledge-state split that cannot arise in a single-agent system, which issues its queries sequentially and therefore observes only one index state per query.
