# 11.5.14 Reducer Behavior Divergence Across Agent Updates [NoFW]

Multiple agents updating the same shared state field with different reducer expectations (append vs. overwrite) exhibit divergence. Conflicting reducer assumptions cause irreproducible state evolution that security evaluations cannot anticipate across all possible update orderings.

For example, Agent A is configured with an "append" reducer for a shared security blocklist while Agent B uses an "overwrite" reducer for the same field; when both agents simultaneously update the blocklist in response to the same threat event, Agent A appends the new malicious entry while Agent B replaces the entire list with only its own update; depending on write ordering, the final blocklist may be correct (both entries preserved) or dangerously incomplete (Agent B's overwrite wins and removes Agent A's addition), with no error emitted by the state store.

Standard defenses such as per-agent unit testing and single-agent integration validation are insufficient because each reducer behaves correctly in isolation; the divergence only manifests when agents with conflicting reducer semantics write concurrently to the same shared field under non-deterministic ordering.

**Multi-agent distinction:** In a multi-agent system, agents with different reducer configurations writing concurrently to the same shared state field produce an outcome that depends on non-deterministic write ordering; the final state cannot be predicted from either agent's individual behavior alone, creating a class of emergent state corruption that has no analogue in single-agent systems where every state transition is applied sequentially by one actor.
