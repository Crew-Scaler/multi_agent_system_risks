# 11.5.13 Caching Invalidation Timing Non-Determinism [NoFW]

Cache invalidation based on TTL or events creates non-deterministic cache states where some agents retrieve cached stale data while others retrieve fresh data. Eventually consistent caching creates temporary semantic divergence exploitable by timing adversarial content insertion to cache loading windows.

For example, a security policy update is published at 14:00; Agent A's cache TTL expires at 14:01 and loads the fresh policy, while Agent B's TTL does not expire until 14:30 and continues operating on the stale pre-update policy; an attacker who injects malicious content into the knowledge store at 14:00:30 ensures that Agent B's next cache refresh at 14:30 loads the poisoned version while Agent A's earlier refresh loads the legitimate update.

Standard defenses such as cache-aside patterns and distributed cache invalidation signals are insufficient because they reduce but do not eliminate the invalidation window; any agent whose cache was populated before the invalidation signal was issued operates on stale data for the remaining duration of its TTL, and the exact duration of each agent's exposure window is not observable from outside the caching layer.

**Multi-agent distinction:** In a multi-agent system, agents with different cache TTL schedules or load times will hold different cached knowledge states simultaneously; Agent A operating on fresh policy and Agent B operating on stale policy will reach contradictory decisions for the same query—a fleet-level knowledge split that cannot occur in a single-agent system whose single cache invalidation event immediately transitions the entire session to the new state.
