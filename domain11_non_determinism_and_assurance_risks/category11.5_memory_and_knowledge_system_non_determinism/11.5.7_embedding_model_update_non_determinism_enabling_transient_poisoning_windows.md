# 11.5.7 Embedding Model Update Non-Determinism Enabling Transient Poisoning Windows [NoFW]

Vector embeddings depend on embedding model versions. Updates change the embedding space, creating transient windows where poisoned content retrieves only from specific model versions, enabling differential version attacks in multi-agent staged rollouts.

For example, an attacker poisons the vector store with a document whose adversarial embedding scores above the retrieval threshold under embedding model version v1.3 but below that threshold under v1.4; during a staged fleet rollout where Agent A has been upgraded to v1.4 while Agent B still runs v1.3, Agent B retrieves the poisoned document and executes an unauthorized action while Agent A does not—an asymmetric compromise invisible to system-level monitoring that sees both agents issuing similar queries.

Standard defenses such as corpus-level content scanning and pre-deployment retrieval evaluation are insufficient because they validate the corpus against a single embedding model version; updating the model silently changes which documents fall above or below the retrieval threshold without any modification to the underlying corpus content.

**Multi-agent distinction:** In a multi-agent system undergoing a staged embedding model rollout, agents on different model versions generate non-interoperable embedding spaces for the same query, meaning two agents issuing identical queries may retrieve disjoint document sets; coordinated reasoning built on the assumption of a shared retrieval layer is undermined in a way that has no single-agent analogue, where every query operates against the same embedding model.
