# 11.5.16 Context Window Non-Determinism From Compression Algorithms [NoFW]

Self-Consistency with many reasoning paths creates large context requiring compression. Non-deterministic compression algorithms may select different information subsets to survive, causing different agents with different context windows to receive divergent compressed context across handoffs.

For example, a multi-agent reasoning chain passes a 128k-token context through a compression layer before handing off to the next agent; the compression algorithm non-deterministically selects which reasoning steps to retain based on attention scores that vary with batch composition; in 30% of executions it discards the step containing a safety constraint that prohibits external data exfiltration, and the downstream agent proceeds to exfiltrate data without triggering any safety check—a failure that never appears in single-execution testing where the constraint is consistently preserved.

Standard defenses such as compressed-context integrity verification and grammar-level validation are insufficient because they confirm that the compressed output is syntactically valid but cannot verify that semantically critical content—such as safety constraints or authorization limits—was preserved through the compression selection process.

**Multi-agent distinction:** In a multi-agent pipeline, each agent in a handoff chain may receive a differently compressed version of the same upstream context depending on when and how the compression ran; Agent A receiving a compression that retained the safety constraint and Agent B receiving one that dropped it will diverge in behavior not because they were given different instructions but because the compression layer non-deterministically produced different information subsets—a structural assurance gap absent in single-agent systems that hold the full uncompressed context in a single continuous session.
