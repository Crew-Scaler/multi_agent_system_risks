# 11.4.4 Event Delivery Guarantee Downgrade Attacks via Infrastructure Resource Exhaustion [NoFW]

Multi-agent event-driven systems rely on exactly-once or at-least-once delivery infrastructure guarantees. Attackers exhaust resources forcing silent degradation to weaker guarantees, enabling duplicate or lost operations (e.g., duplicate financial transactions) that the application layer cannot detect.

For example, an attacker saturates a Kafka broker's consumer-group coordinator with connection floods during a peak transaction window; exactly-once transactional semantics silently downgrade to at-most-once delivery, causing an orchestrating agent's payment-confirmation events to be lost while the executing agent has already transferred funds, creating an irreconcilable ledger divergence that surfaces only during end-of-day reconciliation long after the attack window closes.

Standard defenses such as broker-level resource quotas and consumer-group heartbeat tuning are insufficient because resource exhaustion that triggers guarantee downgrade occurs below the application layer, and agents receive no delivery-guarantee-changed signal; they continue to assume exactly-once semantics while the infrastructure has silently reverted to weaker guarantees, so all application-layer idempotency checks operate on incorrect assumptions.

**Multi-agent distinction:** In MAS, multiple agents compose their correctness assumptions on top of shared delivery guarantees; when a guarantee downgrade occurs, each agent independently observes only its own message stream and cannot detect the system-wide change, so the combined multi-agent workflow loses the exactly-once property even though each individual agent's local validation passes—a systemic failure mode that a single-agent deployment, which owns its entire message consumption context, can detect and handle locally.
