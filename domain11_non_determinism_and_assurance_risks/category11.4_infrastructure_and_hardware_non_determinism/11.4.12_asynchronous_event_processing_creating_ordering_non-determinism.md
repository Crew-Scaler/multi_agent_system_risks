# 11.4.12 Asynchronous Event Processing Creating Ordering Non-Determinism [NoFW]

Event-driven multi-agent systems process events asynchronously. Agents receiving the same events in different orders produce different computational results, creating non-deterministic behavior that testing with controlled event ordering cannot bound for production deployments.

For example, in a multi-agent fraud detection pipeline, Agent-A receives a `transaction_created` event before an `identity_verified` event while Agent-B receives them in the opposite order due to a Kafka partition reassignment; Agent-A permits the transaction pending identity verification while Agent-B blocks it as unverified, creating a split decision that the orchestrator resolves by accepting whichever agent responds first, allowing the fraudulent transaction to proceed.

Standard defenses such as per-partition Kafka ordering guarantees and consumer group rebalancing suppression are insufficient because partition reassignments during broker restarts or consumer group membership changes reorder events across partitions, and enforcing total ordering across all partitions requires a global sequencer that imposes throughput constraints incompatible with high-volume agent pipelines.

**Multi-agent distinction:** In MAS, multiple agents independently consume from overlapping event partitions; when partition assignment changes, agents that previously shared the same ordering context receive events in divergent orders, producing inconsistent state views across the agent population that single-agent consumers—which own all partitions of their consumer group—never encounter because the ordering context is not distributed across independent processes.
