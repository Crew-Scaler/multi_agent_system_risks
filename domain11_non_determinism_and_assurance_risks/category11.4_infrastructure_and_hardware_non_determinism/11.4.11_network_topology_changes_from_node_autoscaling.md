# 11.4.11 Network Topology Changes From Node Autoscaling [NoFW]

Kubernetes node autoscaling adds or removes nodes, changing pod co-location. Network policies validated before autoscaling no longer reflect actual routing paths after new nodes are introduced, creating attack paths that bypass topology-dependent trust assumptions (e.g., shared-node communication assumed not to require encryption).

Kubernetes NetworkPolicy rules are enforced at the node level by CNI plugins; when the cluster autoscaler adds a new node, CNI configuration bootstraps asynchronously and may lag pod scheduling by tens of seconds to minutes, creating a window where new pods on the new node send and receive traffic without any NetworkPolicy enforcement. An attacker who can trigger autoscaling events—for example, by exhausting resource capacity on existing nodes to force scale-out—can cause agents to be scheduled on new nodes during the CNI bootstrap gap, routing agent-to-agent traffic through paths that lack the isolation the pre-autoscaling topology enforced. For example, when the cluster autoscaler adds node-5 to accommodate a load spike, the Calico CNI plugin takes 45 seconds to program eBPF rules on the new node; during this window agent-D scheduled on node-5 accepts connections from any source, including an attacker-controlled pod co-scheduled on the same node that would have been blocked by the pre-autoscaling NetworkPolicy.

Standard defenses such as pod-level network policies and mutual TLS at the application layer are insufficient because CNI bootstrap delays are infrastructure-level events that application-layer controls cannot observe; moreover, mTLS configuration distributed through service-mesh sidecars faces identical asynchronous propagation delays on new nodes and cannot fill the CNI gap.

**Multi-agent distinction:** In MAS, agents communicate across node boundaries under topology-level isolation assumptions validated for a specific node set; each autoscaling event potentially invalidates isolation assumptions for every agent whose network paths traverse the new node, creating a system-wide assurance gap that persists until CNI bootstrap completes on all new nodes—a correlated exposure that single-agent deployments on stable single-node topologies never produce.
