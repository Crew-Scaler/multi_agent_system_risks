# 11.4.16 Non-Deterministic Token Generation Across NIM Replicas Enabling Probability-Based Attacks [NoFW]

NIM replicas executing identical prompts on different GPUs produce slightly different token probabilities due to floating-point rounding. Attackers craft prompts where specific multi-agent attack paths activate only under certain probability distributions, creating hardware-specific exploitability that deterministic safety checks cannot defend.

NVIDIA Inference Microservices replicas run on physically distinct GPUs that may differ in manufacturing-level floating-point unit characteristics, firmware versions, and thermal states; these per-GPU rounding profiles cause identical softmax computations to produce probability distributions that diverge at the fourth to sixth decimal place—sufficient to change token selection when competing tokens have nearly equal log-probabilities. Attackers profile the probability surface of a target model across GPU generations to identify "probability saddle points" where the adversarial token and safe token probabilities are within GPU-rounding distance; they then craft prompts that position the adversarial token at this saddle point, knowing that GPU-specific rounding selects the adversarial token on a fraction of NIM replicas while the remainder produce safe outputs. For example, an attacker identifies that a jailbreak token has log-probability 0.4998 vs. 0.5002 for the safe token on A100 GPUs, while H100-specific rounding reverses this to 0.4997 vs. 0.5003; in a mixed-GPU NIM cluster, roughly 40% of requests routed to H100s produce the jailbreak continuation while 60% are safe, creating an exploit that passes population-level safety benchmarks because the attack success rate is below aggregate detection thresholds.

Standard defenses such as top-k sampling restrictions and temperature-zero greedy decoding are insufficient because GPU-specific rounding alters the logit values before any sampling policy is applied; greedy decoding simply deterministically selects whichever token the hardware-specific rounding declares highest, so the hardware-dependent outcome is not addressable through sampling configuration.

**Multi-agent distinction:** In MAS, load-balanced inference routes each agent call to a potentially different NIM replica on a different GPU; when agents in a pipeline produce inconsistent outputs from the same prompt due to GPU-specific rounding, downstream agents receive divergent upstream inputs that corrupt pipeline logic in ways that cannot be reproduced on any single reference GPU, making cross-agent audit replay fundamentally unreliable in heterogeneous NIM clusters.
