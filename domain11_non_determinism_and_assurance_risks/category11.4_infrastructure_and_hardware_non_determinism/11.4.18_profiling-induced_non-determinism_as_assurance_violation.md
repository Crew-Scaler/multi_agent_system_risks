# 11.4.18 Profiling-Induced Non-Determinism as Assurance Violation [NoFW]

Profiling instrumentation adds measurement overhead that perturbs execution timing and scheduling decisions, creating Heisenbug-like behavior where profiled execution differs fundamentally from uninstrumented baseline. Attackers design attacks that manifest only in non-profiled production execution, evading detection during instrumented security analysis.

For example, an attacker crafts a timing-dependent prompt injection that exploits a race condition in a tool-execution callback; under NVIDIA Nsight instrumentation—which adds 20–200× overhead—the inflated scheduling latency causes the callback race not to manifest, so the injection appears safe during profiling-guided security review; in production without instrumentation the race triggers on every affected request and the injection succeeds.

Standard defenses such as profiling-based behavioral baselines and anomaly detection thresholds calibrated from instrumented runs are insufficient because the measurement overhead that changes timing is architectural and not addressable at the application layer; any threshold derived from profiled execution does not bound non-profiled production behavior, creating a permanent assurance gap between the tested and deployed execution environments.

**Multi-agent distinction:** In MAS, profiling decisions are made independently per agent; when one agent is instrumented and another is not, the instrumented agent's inflated scheduling latency alters its message arrival cadence to peer agents, changing effective event ordering across the system; timing-dependent attacks that evade detection in per-agent instrumented analysis may still manifest in production because the uninstrumented agents in the same pipeline preserve the race conditions that profiling overhead would have masked in isolation.
