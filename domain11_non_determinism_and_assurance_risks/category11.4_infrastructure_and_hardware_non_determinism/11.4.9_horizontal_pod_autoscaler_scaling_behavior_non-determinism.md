# 11.4.9 Horizontal Pod Autoscaler Scaling Behavior Non-Determinism [NoFW]

HPA scaling events introduce new replicas before security configuration is fully synchronized with the existing fleet. Attackers triggering scaling through artificial load generation can route requests to incompletely initialized replicas during the synchronization gap, bypassing fleet-wide security controls.

Kubernetes HPA uses an eventually-consistent metrics pipeline (kubelet to metrics-server to HPA controller) with configurable delays between scale decisions and pod readiness; newly created replicas can satisfy readiness probes before configuration management channels—ConfigMap watches, secret injection, service-mesh sidecar initialization—have propagated current security policies to the pod, creating a window of partial security posture that load balancers do not distinguish from fully initialized replicas. An attacker generates an artificial load spike that triggers HPA scale-out; during the 30–90-second window between pod creation and full security configuration synchronization, the attacker routes targeted requests to new replicas through load-balancer round-robin, reaching agent instances that lack current security policies. For example, the attacker sends 10× normal request volume over 60 seconds, triggering HPA to provision four new replicas; the service mesh's mutual TLS certificate rotation has not yet reached the new pods, which are still presenting bootstrap credentials; requests routed to those pods during the certificate gap bypass mutual authentication, circumventing the fleet's identity verification.

Standard defenses such as PodDisruptionBudgets and application-layer readiness probes are insufficient because readiness probes verify application-layer availability, not the completeness of security configuration distributed through separate control-plane channels with their own asynchronous propagation latencies.

**Multi-agent distinction:** In MAS, an HPA event affecting one agent's pod pool changes the security posture of only that agent's replicas while other pipeline agents continue trusting the scaled agent based on a pre-scaling security baseline; the trusting agents have no mechanism to discover that their downstream collaborator's security configuration has momentarily regressed, creating cross-agent trust inconsistency that is invisible to the entire pipeline.
