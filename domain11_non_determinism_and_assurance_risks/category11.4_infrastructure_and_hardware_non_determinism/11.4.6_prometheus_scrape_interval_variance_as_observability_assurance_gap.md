# 11.4.6 Prometheus Scrape Interval Variance as Observability Assurance Gap [NoFW]

Prometheus scrapes asynchronously with configurable intervals. Attackers time resource exhaustion attacks to coincide with scrape intervals, causing security-relevant metrics to appear stable during attacks and extending effective attack windows by the full scrape interval duration.

Prometheus collects metrics via periodic pull-based scraping at intervals typically configured between 15 and 60 seconds; agents consuming metrics from Prometheus always read snapshots that may be up to one full scrape interval stale, and the staleness is not communicated to consuming agents as a warning or timestamp difference. An attacker who discovers the configured scrape interval launches a resource exhaustion or injection attack at T=0+1 second immediately after a completed scrape; monitoring agents reading Prometheus data see a clean snapshot from T=0 and take no defensive action until T+interval seconds when the next scrape reveals the degradation, granting an unchallenged exploitation window equal to the scrape interval. For example, with a 30-second scrape interval, an attacker launches a cache-exhaustion attack against an upstream agent at T=1; downstream monitoring agents observe stable metrics from the T=0 scrape for the next 29 seconds, while metric-triggered circuit breakers that would have isolated the failing agent remain closed throughout the attack window.

Standard defenses such as alert rules with short evaluation intervals are insufficient because evaluation intervals consume the same stale scrape data; reducing scrape intervals increases scrape infrastructure load proportionally and cannot eliminate the fundamental asynchrony gap, which persists at any practical scrape frequency.

**Multi-agent distinction:** In MAS, multiple agents each consume from the same stale Prometheus snapshot; because agents cannot see each other's local runtime observations, the system-wide staleness is invisible at every coordination layer simultaneously, and an attack that exploits the scrape gap affects all metric-dependent agents at once while each individually believes its monitoring is current—a correlated observability blindspot that a single self-monitoring agent would not have.
