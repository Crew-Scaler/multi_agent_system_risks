# 11.4.13 Checkpoint Resume Non-Determinism in Serverless Workflows [NoFW]

Serverless workflows resuming from checkpoints may pick up non-deterministically if multiple agents race for the same checkpoint. Two agents resuming from the same checkpoint at different times observe different downstream states, causing them to take conflicting actions on shared resources based on divergent state views.

Serverless workflow orchestrators (AWS Step Functions, Azure Durable Functions) persist checkpoints to eventually-consistent distributed storage; when a workflow resumes after a failure, the checkpoint is the authoritative source of agent state, but intervening writes between checkpoint creation and resume read can produce divergent state views depending on when each resuming agent reads and what concurrent mutations have occurred since the checkpoint was written. An attacker who can trigger concurrent workflow resumptions—through retry-storm injection or duplicate event delivery—causes two agents to race for the same checkpoint; the first agent's post-resume writes alter downstream state that the second agent, resuming milliseconds later, does not observe, causing the second agent to apply conflicting decisions on resources the first agent has already modified. For example, in an automated compliance approval workflow a transient infrastructure failure triggers two Lambda executions of the same approval step; Agent-1 reads a clean-state checkpoint and stamps approval while Agent-2, resuming 300 milliseconds later, reads the same pre-approval checkpoint, applies an independent block flag, and overwrites Agent-1's approval—silently defeating the multi-step authorization protocol without triggering any error condition.

Standard defenses such as distributed locking and idempotency keys are insufficient because serverless workflow frameworks perform checkpoint reads outside the application's lock scope, and idempotency keys prevent duplicate external side effects but do not prevent two agents from diverging on the internal state they observe between the checkpoint read and the lock acquisition window.

**Multi-agent distinction:** In MAS, agents that collaborate on a shared workflow rely on checkpoint consistency to synchronize their state understanding; race-induced divergence causes agents to produce mutually inconsistent outcomes that the orchestrator cannot resolve without a global consistency mechanism that serverless platforms typically do not provide, whereas single-agent workflows cannot race against themselves on the same checkpoint.
