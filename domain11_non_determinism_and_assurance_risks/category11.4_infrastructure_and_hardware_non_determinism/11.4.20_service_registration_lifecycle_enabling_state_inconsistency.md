# 11.4.20 Service Registration Lifecycle Enabling State Inconsistency [NoFW]

Semantic Kernel service registration is dynamic. Concurrent agents may observe different service sets if registration changes during execution, creating split-brain states where security-relevant services are present for some agents but absent for others during the same operation window.

For example, when a fraud-detection service is deregistered for maintenance in a Semantic Kernel multi-agent pipeline, Agent-A's local cached registry still lists the service as available while Agent-B has observed the deregistration; Agent-A routes transactions through the fraud-detection step while Agent-B routes them directly to execution, creating a two-tier approval process where a fraction of transactions bypass fraud detection without any agent detecting the inconsistency in its own local view.

Standard defenses such as service mesh health checks and consistent-hashing service discovery are insufficient because Semantic Kernel's in-process service registry is local to each agent instance and is updated only when the agent explicitly re-queries the registry; agents with longer re-query intervals operate with stale registration state that no external health check can correct, because health checks validate liveness of existing registered services, not the completeness of registration state across agents.

**Multi-agent distinction:** In MAS, service registration state is a shared coordination surface that each agent reads independently through its own local cache; divergent cache states produce split-brain conditions where different agents believe the system has different capabilities, and the resulting inconsistent routing decisions cannot be detected by any single agent because each agent's local view is internally consistent—a coordination failure mode that single-agent systems using a single in-process registry never produce.
