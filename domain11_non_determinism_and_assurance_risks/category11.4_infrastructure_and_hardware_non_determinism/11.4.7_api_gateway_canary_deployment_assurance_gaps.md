# 11.4.7 API Gateway Canary Deployment Assurance Gaps [NoFW]

API gateway canary deployments route traffic percentage to new versions, creating windows where v2.0 agents invoke v1.0 tools. The v2.0 safety layer does not recognize v1.0-format responses as malformed, creating guardrail bypass windows during the entire canary period.

Kong's canary deployment plugin shifts traffic between API versions through weighted random routing at the gateway layer, creating a period where the same v2.0 agent may receive v1.0 and v2.0 tool responses in alternating requests; because the gateway does not inject a per-response version header in all configurations, the agent's v2.0 validation schema applies to all incoming traffic, silently treating absent v2.0-specific fields as defaults. An attacker who identifies the canary window and knows which response fields changed between versions times requests to exploit the validation gap: when the v2.0 agent receives a v1.0-format response, the v2.0 schema parser silently maps missing safety fields to schema defaults, bypassing safety checks that depend on explicit v2.0-specific response values. For example, a `threat_level` field added in v2.0 to classify tool outputs is absent in v1.0 responses; the v2.0 agent receives the missing field as schema default `null`, which its null-check passes rather than blocks, effectively disabling the new safety gate for every request the canary routes to a v1.0 tool instance.

Standard defenses such as strict version pinning in client request headers and backward-compatibility integration testing are insufficient because canary routing decisions are made at the gateway before request headers reach the tool, and backward-compatibility tests exercise each version in isolation rather than the specific v2.0-agent-receiving-v1.0-response combination that the canary window creates.

**Multi-agent distinction:** In MAS, different agents in the same pipeline receive independent canary routing decisions on each invocation round; the pipeline's effective security posture equals the weakest version combination encountered across all agents simultaneously, and the exponential number of possible version-mix states across N agents during a canary period cannot be exhaustively validated, creating assurance gaps that grow combinatorially with agent count.
