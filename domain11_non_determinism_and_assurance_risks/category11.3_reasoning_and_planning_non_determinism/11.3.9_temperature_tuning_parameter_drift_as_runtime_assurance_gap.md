# 11.3.9 Temperature Tuning Parameter Drift as Runtime Assurance Gap [NoFW]

Self-Consistency temperature tuning affects behavior and is often tuned for specific problem classes. In multi-agent systems where temperature is shared or propagated, parameter drift affects all agents simultaneously and invalidates prior sampling-based assurance.

For example, a shared temperature parameter tuned to 0.5 for a reasoning-focused agent fleet is later adjusted to 0.8 to improve performance on creative tasks; the drift invalidates sampling-based assurance tests conducted at 0.5, because the higher temperature increases path diversity and surfaces reasoning trajectories that the original test coverage did not sample, including unsafe reasoning paths that the lower temperature's narrower sampling distribution rarely produced.

Standard defenses such as temperature configuration management and re-running assurance tests after parameter changes are insufficient because shared temperature parameters in multi-agent systems can drift gradually through automated optimization routines without triggering explicit change notifications, and the assurance gap accumulates silently between re-test cycles.

**Multi-agent distinction:** In a multi-agent system, a shared or propagated temperature parameter affects all agents simultaneously, so a single parameter drift event invalidates assurance coverage for the entire fleet at once; non-deterministic sampling behavior shifts identically across all agents but each agent's independent task context causes the behavioral impact to manifest differently per agent, creating a distributed assurance gap that per-agent monitoring cannot aggregate into a coherent fleet-level risk signal.
