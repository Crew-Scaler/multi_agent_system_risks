# 11.3.4 Probabilistic Decomposition Method Selection Creating Planning Assurance Gaps [NoFW]

HTN planning systems that non-deterministically select decomposition methods produce different task hierarchies from identical goals, creating untestable branching in agent behavior.

LLM-based HTN planners select among competing decomposition methods stochastically, so the same goal decomposes via a conservative method M1 (probability 0.7) or an aggressive method M2 (probability 0.3) depending on the inference sample; across three coordinating agents each independently selecting methods, the jointly verified path (all agents choosing their modal method) has only a 0.7 × 0.8 × 0.6 = 0.336 probability of occurring in production, leaving the remaining 66% of executions using combinations that safety evaluations never covered. For example, an orchestrator agent that decomposes a "data migration" goal via a safe read-validate-write method in 70% of samples may select an unsafe direct-write method in 30% of samples; at scale across many production invocations, the unsafe decomposition surfaces regularly, exposing a path that pre-deployment red-teaming probabilistically missed.

Standard defenses such as testing the most-probable decomposition path are insufficient because stochastic method selection means low-probability paths appear regularly at production volume, and adversarially crafted goal descriptions can shift the probability mass toward unsafe decomposition methods without triggering any individual method-level constraint.

**Multi-agent distinction:** In a multi-agent system, each HTN planner independently selects its decomposition method, so method-selection non-determinism multiplies across agents; a planner agent's varied subtask decompositions produce different subtask assignments for worker agents, and the combination of independently non-deterministic selections across the fleet creates a joint execution space that no single-agent decomposition audit can bound or exhaustively characterize.
