# 11.3.14 Constraint Satisfaction Heuristics Producing Divergent Solutions [NoFW]

HTN constraint satisfaction has multiple valid solutions and heuristics choosing among them are non-deterministic. Multi-agent systems where solving and execution separate enable unexpected constraint solutions that were not evaluated during safety testing.

For example, a constraint solver agent generating a resource allocation plan for three competing tasks may produce allocation A on one run (prioritizing throughput) and allocation B on a second run (prioritizing fairness) without any input change; the execution agent that receives the plan has no way to know which allocation was intended by the safety evaluation, and allocation B may violate a resource cap that allocation A respected, creating an exploitable assurance gap that appears only on the solver's non-deterministic alternative selection.

Standard defenses such as constraint verification at execution time and solution uniqueness requirements are insufficient because enforcing solution uniqueness in constraint satisfaction problems requires additional constraints that may be incompatible with the original problem specification, and post-hoc verification can confirm that the selected solution satisfies hard constraints but cannot verify that the specific solution selected was the one evaluated for security properties.

**Multi-agent distinction:** In a multi-agent system, the constraint solver agent and the execution agent are separate, so non-deterministic solution selection in the solver produces varied inputs to the executor that were not all covered by safety testing; the execution agent faithfully executes whatever solution it receives, but its behavior varies across runs as a function of the solver's stochastic heuristic choices, creating an assurance gap that is a property of the solver-executor interface rather than either agent in isolation.
