# 11.3.21 MCTS Tree Structure as Implicit Tool Dependency Graph [NoFW]

MCTS planning traces serialized for storage or inter-agent communication implicitly encode tool dependency graphs through tree branching patterns — branches represent tried tool sequences, pruned paths reveal rejected alternatives, and exploration depth reveals confidence in specific tool chains. Attackers analyzing shared MCTS traces reconstruct the complete tool dependency graph, identifying which tool sequences the system considers viable and which are excluded, enabling precision targeting of high-confidence tool chains and exploitation of gaps in the explored tool space.

Standard defenses such as MCTS trace encryption and access control on planning logs are insufficient because inter-agent communication requires that planning traces be interpretable by receiving agents, and any agent capable of receiving a trace for legitimate coordination purposes can also analyze its branching structure; obfuscating the tree structure degrades the coordination utility that motivates trace sharing.

**Multi-agent distinction:** In a multi-agent system, MCTS planning traces are shared between a planner agent and executor agents as a coordination mechanism, so the implicit tool dependency graph encoded in the tree structure is necessarily exposed to all agents in the communication chain; an adversary who compromises any downstream agent or intercepts any inter-agent channel gains full visibility into the planner agent's tool confidence ordering, enabling targeted attacks against the highest-confidence tool chains across the entire fleet in ways that single-agent MCTS trace audits cannot prevent because the exposure is structural to the multi-agent trace-sharing architecture.
