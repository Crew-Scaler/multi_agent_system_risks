# 11.3.13 Partial Order Scheduling Non-Determinism in Distributed Execution [NoFW]

HTN partial ordering permits multiple valid execution sequences. In multi-agent systems, Agent A specifies ordering but Agent C must resolve it; without deterministic resolution rules, different executions produce different sequences that may violate security-relevant execution constraints.

For example, an HTN plan specifies that "authenticate" and "log" are partially ordered with respect to "execute" — either can precede it — but when Agent C resolves this ordering, it selects "execute" before "log" on one run and "log" before "execute" on another; an auditor who reviews only the first execution would certify that logging always precedes execution, while the second execution violates that ordering without any configuration change.

Standard defenses such as execution ordering constraints in plan specifications are insufficient because HTN partial orders by design permit multiple valid sequences, and enforcing a single serialization defeats the parallelism benefits that motivated the partial-order representation; policy-level ordering requirements must therefore be enforced at execution time, but execution agents resolving partial orders non-deterministically cannot guarantee consistent serialization.

**Multi-agent distinction:** In a multi-agent system, the agent specifying a partial order and the agent resolving it are distinct, so resolution non-determinism is distributed across the agent boundary; each execution agent independently selects a linearization from the valid partial-order set, and the resulting sequence variations across the fleet create an assurance gap that single-agent HTN audits cannot detect because they evaluate only the plan specification rather than the execution agent's resolution behavior.
