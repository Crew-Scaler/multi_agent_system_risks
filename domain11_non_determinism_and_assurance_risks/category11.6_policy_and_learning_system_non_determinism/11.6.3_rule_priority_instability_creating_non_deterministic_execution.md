# 11.6.3 Rule Priority Instability Creating Non-Deterministic Execution [NoFW]

Adaptive rule systems that adjust rule priorities based on experience create non-deterministic execution ordering, enabling rule-conflict exploitation through timing.

Rule-based agents assign numeric priorities to competing rules to break ties at execution time; when those priorities are themselves adaptive—updated based on recent usage frequency, observed outcomes, or external feedback—the same input can trigger a different rule chain depending on the order in which prior requests arrived and updated the priority table. For example, a compliance-checking agent that dynamically up-weights rules that recently flagged violations may begin ignoring a lower-priority safety rule after a quiet operational period, allowing an attacker to first flood it with benign inputs that suppress the priority of a critical guard rule, then submit a malicious payload that slips through the now-deprioritized check. The execution ordering that determines whether the guard fires is invisible to an observer who only sees the rule set, not its current priority state.

Standard defenses such as static rule audits or pre-deployment rule conflict analysis are insufficient because priority tables are dynamic and the priority state that determines execution order changes continuously at runtime, making any pre-deployment analysis reflect a snapshot that is immediately outdated.

**Multi-agent distinction:** In a MAS, independently adaptive rule priorities diverge across agents so that the same coordination request triggers different rule sequences in different agents; non-determinism in one agent's priority update propagates through coordination interfaces to destabilize the behavior of agents that depend on stable policy contracts, creating emergent inconsistency unavailable in single-agent rule systems.
