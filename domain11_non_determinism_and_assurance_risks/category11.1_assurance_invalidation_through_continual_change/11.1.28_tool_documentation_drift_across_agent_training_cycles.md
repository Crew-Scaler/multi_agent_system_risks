# 11.1.28 Tool Documentation Drift Across Agent Training Cycles [NoFW]

Agents update continuously and tool specifications change between cycles. Agent A operates on spec v1 while Agent B operates on spec v2, creating coordination gaps that attackers exploit by targeting agents whose documentation no longer matches deployed tool behavior.

For example, an adversary who observes that an agent's tool selection is guided by outdated documentation can craft queries that match the stale spec's description of a high-privilege tool, causing the agent to invoke it with the old parameter conventions while the live tool interprets the call under v2 semantics, bypassing the access controls that v2 introduced.

Standard defenses such as documentation version pinning, tool registry audits, and retraining on updated specs are insufficient because continuous training cycles introduce lag between spec updates and re-trained agent behavior, and documentation drift is not surfaced as an error condition by tool invocation infrastructure.

**Multi-agent distinction:** In multi-agent systems, documentation drift creates asymmetric knowledge states where agents trained at different points in time hold conflicting assumptions about tool interfaces, and an adversary can exploit the agent with the most outdated documentation as a proxy to invoke tool behaviors that more recently trained agents would have rejected.
