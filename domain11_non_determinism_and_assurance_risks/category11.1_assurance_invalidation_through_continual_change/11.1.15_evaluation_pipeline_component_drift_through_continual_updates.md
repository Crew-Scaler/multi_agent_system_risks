# 11.1.15 Evaluation Pipeline Component Drift Through Continual Updates [NoFW]

Multi-stage evaluation pipelines have components updating independently. Component drift creates inconsistency making results non-reproducible across evaluations, invalidating cumulative assurance records and audit trails.

For example, when a multi-stage evaluation pipeline's preprocessing component updates its tokenization library while its scoring component updates its normalization logic on a different schedule, the same agent output produces different evaluation scores on different days without any change to the agent itself, making audit trails non-reproducible and assurance records unreliable as evidence of current system behavior.

Standard defenses such as evaluation pipeline version pinning and component locking are insufficient because evaluation components are themselves LLM-based or library-dependent systems that require updates for security patches and accuracy improvements, and pinning evaluation components creates a secondary assurance gap around the evaluation infrastructure itself — leaving operators choosing between an outdated evaluator and an incomparable one.

**Multi-agent distinction:** In a single-agent system, evaluation pipeline drift affects one measurement stream that can be detected by re-running the same agent output through a frozen evaluator; in a multi-agent system where each agent's outputs flow through different evaluation components that update independently, comparative assurance across agents is invalidated because each agent's score reflects its behavior convolved with its specific evaluation component's drift, making cross-agent comparisons meaningless without simultaneously re-evaluating all agents against all evaluation component versions.
