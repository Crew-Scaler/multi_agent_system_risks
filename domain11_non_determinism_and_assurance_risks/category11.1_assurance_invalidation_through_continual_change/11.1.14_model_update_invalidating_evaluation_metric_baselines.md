# 11.1.14 Model Update Invalidating Evaluation Metric Baselines [NoFW]

Evaluation metric models update, changing metric behavior and baselines. Multi-agent systems with specialized metric agents experience independent updates shifting baselines so that passing evaluations from one version no longer reflect current system behavior.

For example, when an LLM judge used to evaluate a multi-agent customer service pipeline updates its underlying model, its scoring rubric shifts such that responses previously scored 4/5 for helpfulness are now scored 3/5 due to changed model preferences — causing all prior metric baselines to be incomparable with post-update scores and invalidating cumulative assurance records without any change to the agents being evaluated.

Standard defenses such as benchmark agreement checks and metric calibration tests are insufficient because LLM judge updates can preserve stated evaluation criteria while shifting internal scoring preferences in ways that aggregate metrics obscure, making the drift detectable only through systematic regression testing against a frozen, archived judge version that may itself be unavailable after the update.

**Multi-agent distinction:** In a single-agent system, an evaluation metric update requires one re-baselining to restore comparability; in a multi-agent system where different agents are evaluated by different metric models updating independently, comparative assurance across agents becomes impossible because each agent's metric has a different shift direction and magnitude, preventing system-level quality assessments and audit trail continuity even when all agents themselves remain unchanged.
