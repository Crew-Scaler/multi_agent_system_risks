# 11.1.2 Tool API Drift and Silent Failure Propagation in Multi-Agent Chains [NoFW]

Tool APIs evolving independently across framework versions cause agents to fail in unpredictable ways that propagate through agent chains before failures are detected.

API versioning transparency is the architectural property being exploited: external tool APIs evolve without notifying consuming agents, and the change may produce syntactically valid but semantically different responses that all downstream agents treat as authoritative. The attack mechanism is that Plan-and-Execute architectures face silent API drift where Agent A calls an updated endpoint whose changed response format is consumed without error by Agent B, which then operates on corrupted data it cannot distinguish from valid output. A customer service pipeline uses Agent A to query an inventory API and Agent B to place orders; the inventory API renames `stock_level` to `available_quantity`, Agent A silently returns null for stock checks, and Agent B interprets null as in-stock and places orders, bypassing stock validation that was assurance-tested against the prior response schema.

Standard defenses such as schema validation and error-rate monitoring are insufficient because silent field renames and semantic shifts produce no schema violation or error signal — the call succeeds, a response is returned, and the failure only manifests as downstream behavioral corruption that monitoring tools classify as application logic rather than API drift.

**Multi-agent distinction:** In a single-agent deployment, a silent API change affects one consumption point and can be detected by comparing outputs over time; in a chain of agents, each agent amplifies the corrupted interpretation from the prior stage, so a drift that produces a 5% semantic error rate in Agent A may produce near-100% downstream failure in Agent D, making the compounded assurance gap disproportionate to the original drift and invisible to any single agent's validation tests.
