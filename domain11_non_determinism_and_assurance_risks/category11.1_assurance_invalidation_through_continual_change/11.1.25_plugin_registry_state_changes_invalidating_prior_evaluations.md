# 11.1.25 Plugin Registry State Changes Invalidating Prior Evaluations [NoFW]

Semantic Kernel dynamically discovers and registers plugins. Registry changes modify routing behavior without code changes, silently invalidating prior security evaluations that assumed a fixed plugin set.

For example, a newly registered plugin that shares a capability description keyword with a previously audited plugin may be selected by the planner in place of the trusted plugin, routing sensitive operations to an unvetted implementation that the prior evaluation never considered.

Standard defenses such as plugin allowlisting, capability manifest reviews, and regression testing against a fixed registry snapshot are insufficient because the registry is a dynamic runtime artifact that changes independently of code deployments, and allowlists require continuous manual curation to remain effective as new plugins register.

**Multi-agent distinction:** In multi-agent systems, a plugin registry change affects every agent that queries the shared registry, meaning a single new or modified plugin entry can simultaneously invalidate the behavioral and security assumptions of the entire fleet without any code change triggering a re-evaluation cycle.
