# 11.1.5 Tool Schema Version Drift Across Agent Implementations [NoFW]

Tool schemas evolve as capabilities add or deprecate. Multi-agent systems may have agents using different schema versions simultaneously, causing Agent A expecting old schema parameters to invoke tools expecting new schema fields, producing silent failures that invalidate prior assurance evaluations.

Schema contract stability is the architectural property being exploited: agents are certified against a specific tool schema at evaluation time, but schema evolution violates that contract without triggering re-evaluation requirements, meaning an agent continues calling tools using stale parameter assumptions while the tool silently accepts and coerces the mismatched call. The attack mechanism is that as tool schemas add fields, change types, or deprecate parameters, agents trained on older schemas generate malformed calls that the tool accepts through backward-compatibility coercion, producing outputs that differ from those observed during assurance evaluation without producing any error signal. An orchestration pipeline validates that Agent A calls a payment tool with `amount` as an integer; the payment API updates its schema to require `amount` as a string to support international currency formats; Agent A continues generating integer calls that the API silently coerces, producing different rounding behavior for edge-case amounts that was not tested in prior safety evaluations.

Standard defenses such as runtime schema validation and type-checking middleware are insufficient because they validate the current schema against the current call, not against the schema version the agent was evaluated against — backward-compatible coercion passes all current validations while the semantic meaning of the interaction has changed.

**Multi-agent distinction:** When multiple agents share the same tool but were evaluated against different schema versions, each agent's tool interaction produces a different behavioral profile; failures at one agent may be masked by another agent's compensating behavior, creating a combined assurance picture that accurately reflects neither agent's individual behavior and that single-agent testing cannot reconstruct.
