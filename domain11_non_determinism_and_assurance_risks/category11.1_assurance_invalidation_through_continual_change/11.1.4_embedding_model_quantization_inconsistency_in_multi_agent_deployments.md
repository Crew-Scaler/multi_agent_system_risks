# 11.1.4 Embedding Model Quantization Inconsistency in Multi-Agent Deployments [NoFW]

Different quantization settings across agents in the same fleet produce inconsistent embedding spaces, causing retrieval to return semantically different results for the same query across agents.

Embedding space invariance is the architectural property being exploited: assurance evaluations assume a stable, uniform embedding space across all agents, but quantization introduces systematic distortions that vary by hardware configuration and precision settings, invalidating the embedding-level guarantees that retrieval assurance depends on. The attack mechanism is that when fleet hardware is heterogeneous — GPU nodes using FP16 and CPU nodes using INT8 — the same embedding model produces numerically different vectors for the same input, causing agents on different hardware to retrieve semantically different documents from the same vector store while all reporting successful retrieval. A legal research pipeline deploys Agent A on GPU hardware using FP16 quantization and Agent B on CPU using INT8; a query about contract liability retrieves different precedent documents for each agent, and the security evaluation certifying that no confidential documents would be returned is valid only for the FP16 configuration, leaving the INT8 agent silently out of compliance.

Standard defenses such as retrieval evaluation benchmarks and recall@k metrics are insufficient because they use a fixed hardware configuration during evaluation, so quantization-induced divergence that only manifests across heterogeneous production deployments is never observed in the evaluation environment.

**Multi-agent distinction:** Single-agent deployments have one embedding configuration whose drift can be detected by comparing retrieval outputs over time against a stable baseline; multi-agent systems with heterogeneous quantization produce divergent outputs simultaneously across agents, so the assurance gap is invisible unless every agent-hardware-quantization combination is independently evaluated — an exponential testing burden as fleet hardware diversity grows.
