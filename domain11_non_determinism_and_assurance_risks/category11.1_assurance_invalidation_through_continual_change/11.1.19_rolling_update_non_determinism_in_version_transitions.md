# 11.1.19 Rolling Update Non-Determinism in Version Transitions [NoFW]

Kubernetes rolling updates gradually replace versions. Multi-agent systems experience heterogeneous behavior where Agent A v1 and Agent B v2 hold divergent interface expectations, producing semantically incorrect results through backward-structurally-compatible but semantically divergent parameter substitution. For example, a JSON field renamed from `user_id` to `subject_id` in v2 of a routing agent may be silently accepted by an older consuming agent that maps any unrecognized field to a default identity, bypassing access-control logic calibrated under the earlier naming convention. The semantic corruption passes structural validation at every service boundary, making the attack surface invisible to schema-based monitoring.

Standard defenses such as API versioning headers, semantic versioning enforcement, and contract testing are insufficient because rolling transitions create transient mixed-version states that are not represented in any single contract-test scenario, and producers and consumers update at independent rates.

**Multi-agent distinction:** In multi-agent architectures, the semantic gap introduced by any single agent's rolling transition propagates through every downstream agent that consumes its outputs, so the window of assurance invalidity for one service's update becomes a window of assurance invalidity for the entire dependent pipeline.
