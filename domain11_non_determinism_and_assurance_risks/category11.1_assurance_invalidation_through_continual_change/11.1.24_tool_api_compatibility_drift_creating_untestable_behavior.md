# 11.1.24 Tool API Compatibility Drift Creating Untestable Behavior [NoFW]

External tool APIs evolve while agents may fail to adapt. Non-deterministic error handling creates scenarios where API compatibility failures trigger unpredictable agent behaviors that pass@1 testing overestimates reliability by 20–40% versus production stress conditions.

For example, when a financial data API silently adds a required `consent_token` parameter, an agent that previously generated valid calls now triggers the API's error path, which the agent interprets as a transient fault and retries with elevated scope, inadvertently granting itself broader data access than the original assurance review permitted.

Standard defenses such as API versioning contracts, mock-environment testing, and error-handling regression suites are insufficient because production APIs change asynchronously with agent deployments, mock environments underspecify real API behavior, and non-deterministic fallback paths are only observable under production-level fault conditions.

**Multi-agent distinction:** In multi-agent pipelines, API compatibility drift in any shared external tool creates correlated assurance failures across all agents that invoke that tool, and the non-deterministic fallback behaviors triggered by drift in one agent can introduce malformed or escalated inputs into downstream agents whose own evaluations assumed well-formed tool responses.
