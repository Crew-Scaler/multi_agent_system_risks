# 11.1.22 Continual Update Propagation Creating Distributed Regression Gaps [NoFW]

Multi-agent systems face distributed regression where updates affect different agents asynchronously, creating heterogeneous version states (Agent A v2.1 / Agent B v2.0) that produce emergent behaviors untested in any single-version evaluation. Attackers systematically probe version boundaries discovering unsafe behaviors during heterogeneous states.

For example, an adversary who discovers that Agent A v2.1 now trusts a new claim format can craft requests that embed that claim knowing Agent B v2.0 will propagate it without the new validation logic, exploiting a trust gap that exists only in the transient mixed-version state and disappears once B updates.

Standard defenses such as regression test suites and blue/green deployment validation are insufficient because they evaluate each version against a fixed baseline and cannot predict emergent behaviors that arise only from combinations of two different version sets operating simultaneously.

**Multi-agent distinction:** In multi-agent systems, a regression introduced in any single agent's update propagates to every dependent agent through shared message channels, so a distributed regression gap is not bounded to the updated component but expands to encompass the full topology of agents that receive or re-broadcast its outputs.
