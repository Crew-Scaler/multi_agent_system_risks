# 11.1.6 Function Calling Model Updates Creating Behavioral Discontinuity [NoFW]

LLM providers periodically update function calling behavior. Multi-agent systems using different LLM versions experience different function calling behavior across agents, creating emergent incompatibilities that cannot be tested without exercising all cross-version combinations.

For example, when an LLM provider updates GPT-4's function-calling serialization to prefer keyword arguments over positional ones, Agent A (upgraded) generates calls incompatible with the schema that Agent B (still on the prior version) was validated against, producing a cross-version incompatibility that neither agent's individual test suite detects because both agents pass their own unit tests in isolation.

Standard defenses such as individual agent unit tests and single-version integration suites are insufficient because cross-version incompatibility only emerges at the agent-to-agent interface, where neither agent's tests exercise the combined behavior produced by the version mismatch.

**Multi-agent distinction:** In a single-agent system, a function-calling model update requires one re-evaluation; in a multi-agent system, each pair of agents running on different LLM versions produces a distinct interface whose combined behavior must be evaluated independently, growing as O(n²) combinations across a fleet where agents update asynchronously and no coordinated re-evaluation is triggered.
