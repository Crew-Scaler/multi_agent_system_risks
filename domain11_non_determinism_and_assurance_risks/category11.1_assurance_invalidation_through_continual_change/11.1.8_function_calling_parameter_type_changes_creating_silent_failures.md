# 11.1.8 Function Calling Parameter Type Changes Creating Silent Failures [NoFW]

Tool parameter types evolve between schema versions (string to float, adding required parameters). Multi-agent systems with agents trained on different definitions experience silent type-mismatch failures that produce no error but corrupt downstream processing, making prior safety evaluations unreliable.

For example, when a geolocation tool updates its schema to require `latitude` as a string rather than a float to support higher-precision representations, agents trained on the prior schema silently pass a float that the tool coerces, producing truncated or reformatted precision that corrupts navigation decisions previously certified to meet accuracy thresholds.

Standard defenses such as runtime schema validation and type-checking middleware are insufficient because silent type coercion produces no error signal — the call succeeds, a response is returned, and the semantic meaning of the parameter has changed in ways that are undetectable without comparing behavior against the schema version that was used during the original safety evaluation.

**Multi-agent distinction:** When multiple agents in a pipeline call the same tool using parameters from different schema versions, type coercions accumulate across handoffs — Agent A's float-to-string coercion alters Agent B's string parsing, which alters Agent C's downstream computation — creating a cascading precision loss that no single-agent test would detect because each agent's individual test validates its own call in isolation rather than the combined effect of serial coercions.
