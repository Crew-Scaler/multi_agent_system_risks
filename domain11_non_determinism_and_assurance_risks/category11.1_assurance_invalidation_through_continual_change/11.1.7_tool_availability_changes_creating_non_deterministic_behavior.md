# 11.1.7 Tool Availability Changes Creating Non-Deterministic Behavior [NoFW]

Tools deprecate and capabilities change post-deployment. Multi-agent systems have agents using outdated tool lists while others use updated lists, creating state where older agents invoke deprecated tools that newer agents have removed, invalidating assurance across the fleet.

For example, when a third-party tool registry deprecates a data enrichment API, older agents that invoke it receive empty results while newer agents using the replacement API receive enriched data, creating a mixed-fleet state where assurance tests performed on the homogeneous pre-deprecation fleet no longer reflect the behavior of any agent in production.

Standard defenses such as health monitoring and tool registry version pinning are insufficient because registry state can change without notice, pinned versions may continue to accept calls while returning degraded or empty results that pass syntactic validation, and no single monitoring alert surfaces the behavioral divergence between agents using different tool versions.

**Multi-agent distinction:** In a single-agent system, a deprecated tool produces a detectable error or empty result at one point; in a multi-agent chain, the absence of enrichment silently changes the context passed to every downstream agent, causing behavioral drift across the entire pipeline that appears as non-determinism rather than a tool availability failure, and is invisible to the assurance record that certified each individual agent against a functional tool.
