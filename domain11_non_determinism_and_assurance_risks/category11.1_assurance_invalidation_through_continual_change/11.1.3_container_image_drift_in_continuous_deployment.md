# 11.1.3 Container Image Drift in Continuous Deployment [NoFW]

Continuous deployment updates agent container images at different rates, creating heterogeneous agent populations with different capability and security postures interacting within the same system.

Container immutability is the architectural property being exploited: each agent runs in an image that appears fixed at deployment time, but continuous deployment replaces images on different schedules, silently changing the runtime environment for individual agents while the system continues operating as if homogeneous. The attack mechanism is that when Agent A is updated to a new image while Agent B is not, the two agents now operate with different library versions, security patches, and behavior profiles, invalidating any system-level assurance evaluation that assumed a uniform fleet. A financial document processing pipeline assures compliance when Agent A (parser) and Agent B (compliance checker) share the same image; a CI update deploys a new parser image with changed tokenization behavior while Agent B retains the prior image, causing documents that were compliant under the prior tokenization to be classified differently — but the compliance evaluation performed against the homogeneous fleet does not re-trigger.

Standard defenses such as health checks and canary deployments are insufficient because health checks verify that each container is running rather than that its behavior is consistent with co-deployed agents, and canary deployments validate a single agent's new behavior but not the cross-agent interaction between updated and non-updated containers.

**Multi-agent distinction:** Single-agent container updates require one re-validation after deployment; multi-agent fleets require re-validating all pairwise interactions among updated and non-updated agents, growing as O(n²) in fleet size, making comprehensive re-assurance intractable at the pace of continuous deployment pipelines that may update individual agents daily.
