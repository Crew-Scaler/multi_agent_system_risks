# 11.1.26 FunctionChoiceBehavior Configuration Drift Across Agent Updates [NoFW]

FunctionChoiceBehavior settings (Auto/Required/Filtered) determine routing consistency in Semantic Kernel. Agents with different configurations produce different routing behaviors, creating inconsistent security postures across the multi-agent fleet.

For example, an orchestrator configured with `Auto` routing may invoke a sensitive data-exfiltration tool that a peer agent configured with `Filtered` would have blocked, and since both agents pass their own isolated functional tests, the cross-agent security gap is invisible until an adversary crafts a request that traverses the orchestrator's permissive routing path.

Standard defenses such as configuration audits, default-deny policies, and automated configuration consistency checks are insufficient because FunctionChoiceBehavior settings can be overridden at invocation time by system prompts and are not uniformly surfaced in deployment manifests where drift would be detectable.

**Multi-agent distinction:** In multi-agent architectures, configuration drift across agents creates an adversarially exploitable security gradient where attackers can selectively route requests through the most permissively configured agent, using that agent's outputs as inputs to other agents that would have blocked the initial request had it arrived directly.
