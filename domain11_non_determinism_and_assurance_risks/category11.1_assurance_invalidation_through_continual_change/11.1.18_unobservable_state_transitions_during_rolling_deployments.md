# 11.1.18 Unobservable State Transitions During Rolling Deployments [NoFW]

Rolling Kubernetes deployments replace pods gradually, creating coexistence of old and new versions. Multi-agent rolling across N services simultaneously creates N×(N-1)/2 compatibility combinations where cross-version message schema mismatches produce silent data corruption undetectable by per-version testing. During a rolling deployment, a pod running agent-service v1 may receive a task delegation from a newly upgraded v2 pod whose message schema has added a required `trust_context` field; the v1 pod silently ignores the field and proceeds with escalated privileges that v2's security model was designed to revoke. Orchestration health checks report all pods healthy because both versions pass their isolated readiness probes, hiding the cross-version semantic incompatibility until an attacker deliberately triggers it.

Standard defenses such as readiness probes, schema compatibility checks, and integration tests are insufficient because they evaluate each version in isolation and cannot exhaustively cover the N×(N-1)/2 cross-version interaction pairs that exist simultaneously during rolling transitions.

**Multi-agent distinction:** In multi-agent systems, rolling deployments of even a single service inject unobservable cross-version states into every agent that communicates with that service, meaning assurance properties established for any individual agent's version cannot be extended to the composite system while the transition window remains open.
