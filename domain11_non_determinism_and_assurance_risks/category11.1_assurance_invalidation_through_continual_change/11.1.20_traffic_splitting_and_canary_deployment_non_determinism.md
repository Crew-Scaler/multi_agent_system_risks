# 11.1.20 Traffic Splitting and Canary Deployment Non-Determinism [NoFW]

Service mesh canaries gradually shift traffic, creating sessions that cross API version boundaries mid-execution. Stateful context accumulated under v1 semantics is re-interpreted under v2 semantics, corrupting session state in ways that appear valid to both versions' logs. For example, a multi-turn agent session in which the planning agent accumulates a conversation history under v1's tool-invocation schema may have that history forwarded to a v2 execution agent whose schema treats the same field as a capability grant rather than a log entry, allowing an attacker who deliberately straddles the canary boundary to convert accumulated context into an unauthorized permission escalation.

Standard defenses such as session pinning, canary analysis metrics, and version-aware proxies are insufficient because they track aggregate traffic health rather than per-session semantic integrity, and a low attack rate designed to stay within canary error budgets can persist for the full deployment window undetected.

**Multi-agent distinction:** In multi-agent pipelines, the semantic state corruption introduced at a canary boundary in one agent propagates into all agents that consume downstream outputs, meaning assurance guarantees validated for either version individually cannot be assumed to hold for any session that traversed the version boundary.
