# 9.7.2 HNSW Graph Structure Poisoning During Index Rebuild [NoFW]

Attackers time attacks to coincide with index rebuild operations, injecting malicious graph edges that cause retrieval to prefer attacker-chosen documents under normal query patterns. HNSW index builds are triggered by data updates, configuration changes, or scheduled maintenance, and the index construction parameters—particularly efConstruction, which controls graph connectivity breadth during node linking—are read from configuration files that may be writable through CI/CD pipelines or deployment automation. For example, an attacker who gains write access to a vector database deployment manifest reduces efConstruction from 400 to 50 before a scheduled nightly rebuild; the resulting index passes integrity checks (all vectors are present, checksums match) but exhibits severely degraded retrieval, causing agents to consistently miss relevant documents while retrieving attacker-favored low-relevance alternatives.

Standard defenses such as index size validation and vector count audits are insufficient because a low-efConstruction graph contains the correct number of nodes and vectors—only the edge selection during graph construction is suboptimal, which is invisible to post-build structural audits that examine counts rather than connectivity quality.

**Multi-agent distinction:** In a single-agent deployment index degradation affects one retrieval pipeline; in multi-agent systems sharing a single vector database, one poisoned rebuild degrades retrieval quality for every agent simultaneously, and because the degradation manifests as gradual relevance drift rather than hard failures, operators typically do not detect it until downstream task quality has already deteriorated noticeably across the entire fleet.
