# 9.7.5 Persistent Volume Poisoning in Vector Database Storage Layers [NoFW]

Production vector databases storing HNSW graph structures, embeddings, and metadata in persistent volumes create targets for attackers with volume access. Unlike in-memory poisoning affecting only current sessions, volume poisoning directly modifies stored graph files and vector data, corrupting durable storage permanently until volume restoration. Attackers can introduce malicious edges in graph files, alter distance values to favor attacker-controlled documents in rankings, corrupt embedding values to shift semantic meanings, or modify metadata for document substitution. All downstream agents querying the database receive poisoned data until a clean restore is performed.

For example, an attacker who escapes a containerized deployment and gains host-level access to the Docker volume at /var/lib/weaviate modifies the HNSW segment files to introduce malicious edges connecting all "access control policy" query neighborhoods to a cluster of attacker-controlled documents; when the vector database process restarts during routine maintenance, it loads the corrupted graph files and all agents querying access control topics receive adversarial content ranked above legitimate policy documents for the remainder of the volume's lifetime.

Standard defenses such as database-level authentication and TLS for client connections are insufficient because volume-layer poisoning bypasses the database process entirely, targeting the underlying file storage that the database process trusts implicitly when loading persisted graph structures on startup without integrity verification.

**Multi-agent distinction:** In-memory or single-session deployments lose poisoning on restart; persistent volume poisoning survives container restarts and replacements, so every agent that connects to the database after the volume is modified—regardless of which session or how much time has elapsed—retrieves corrupted data, making the attack durable across the entire multi-agent fleet's operational lifetime until operators restore the volume from a verified pre-poisoning backup.
