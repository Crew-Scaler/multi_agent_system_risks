# 9.7.3 Embedding Space Poisoning Through Cross-Provider Model Switching [NoFW]

When agents switch between embedding model providers, the semantic space shifts and previously safe queries may now retrieve maliciously positioned documents optimized for the new embedding space. Multi-agent systems using different embedding providers (for example, OpenAI text-embedding-3-large alongside NVIDIA NV-Embed-v2) for different agents store embeddings in a shared vector database, creating a mixed-provenance index where query embeddings from one provider are compared against stored embeddings from another, producing unreliable similarity rankings. An attacker who anticipates an upcoming provider migration can pre-position documents whose embeddings rank poorly under the current provider's space but are optimized to rank highly under the new provider's space for security-critical query clusters, lying dormant until the provider switch activates them.

Standard defenses such as provider-level access controls and ingestion-time content audits are insufficient because the attack exploits the geometric incompatibility between embedding spaces rather than unauthorized writes—the poisoned documents may be legitimately ingested content whose adversarial positioning only manifests after a model migration that operators do not recognize as a security event.

**Multi-agent distinction:** In a single-agent system an embedding space shift affects only that agent's retrieval context and can be mitigated by regenerating all embeddings for that agent's index; in multi-agent systems sharing a single vector store without strict embedding provenance tracking, a provider migration simultaneously activates pre-positioned adversarial documents across all agents' retrieval pipelines, with no individual agent able to detect that its retrieved context has changed rankings relative to the previous provider.
