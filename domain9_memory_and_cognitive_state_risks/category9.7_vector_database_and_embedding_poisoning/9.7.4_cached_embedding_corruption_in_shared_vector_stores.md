# 9.7.4 Cached Embedding Corruption in Shared Vector Stores [NoFW]

Multi-agent RAG systems caching embeddings in shared vector stores to avoid recomputation create poisoning targets when multiple agents trust the cache without validating embedding integrity. Attackers poison the cache by injecting embeddings computed with compromised models, poisoned input text, or deliberately mismatched dimensions. Once malicious embeddings enter the shared cache, all agents retrieving from that cache incorporate poisoned vectors into their RAG pipelines, and the corruption is invisible to agents inspecting retrieved text since vectors appear numerically valid but represent adversarially crafted representations.

For example, in a financial analysis multi-agent system where a data-ingestion agent caches document embeddings at 1,536-dimensional Matryoshka truncation but a summary agent expects full 3,072-dimensional vectors, an attacker poisons the shared cache with zero-padded 1,536-dimensional entries claiming to be 3,072-dimensional; the summary agent computes similarity scores against a dimensionally mismatched subspace, causing high-value regulatory documents to rank below low-relevance cached entries that happen to occupy favorable positions in the truncated vector space.

Standard defenses such as cache expiration policies and access control lists on the shared vector store are insufficient because they govern who can write to the cache and how long entries persist, but do not validate that cached embedding vectors correctly represent the semantic content of the documents they index or that they were produced by an uncompromised embedding model.

**Multi-agent distinction:** In a single-agent system embedding cache corruption affects only that agent's RAG pipeline during the sessions that hit the poisoned cache entries; in multi-agent systems using a shared embedding cache, a single poisoned entry is served to every agent querying semantically similar content across all sessions, converting a one-time write attack into continuous retrieval poisoning across the entire agent fleet until the cache is manually audited and purged.
