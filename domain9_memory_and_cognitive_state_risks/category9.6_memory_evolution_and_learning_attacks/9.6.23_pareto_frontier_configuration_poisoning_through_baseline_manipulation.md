# 9.6.23 Pareto Frontier Configuration Poisoning Through Baseline Manipulation [NoFW]

Pareto frontier analysis selecting configurations for production deployment is corrupted when baseline measurements used for comparison are poisoned. Attackers poison baseline metrics causing inferior or malicious configurations to appear Pareto-optimal, establishing permanent memory corruption through deployment. In multi-agent systems sharing baselines for consistency, single-baseline poisoning affects all agents' parameter tuning decisions, causing poisoned configurations to be adopted as optimal operational parameters stored in agent memory systems.

For example, an attacker degrades the performance measurements stored in the shared baseline store for high-throughput low-latency configurations, making a configuration that introduces a covert side-channel appear to dominate the Pareto frontier—causing all agents to adopt the compromised configuration as their production parameter set during the next automated tuning cycle. Standard defenses such as individual configuration validation or rollback mechanisms are insufficient because the attack corrupts the comparison baseline itself, so the poisoned configuration passes all relative performance checks that compare it against the degraded baseline rather than against true historical performance. **Multi-agent distinction:** Shared baselines used to enforce Pareto consistency across agents create a single reference point whose corruption simultaneously invalidates every agent's optimization outcome—one poisoned baseline store propagates malicious configurations to all agents that defer to it for tuning decisions, with no individual agent able to detect the fraud by consulting only its own local measurements.

  - "In multi-agent interactions, it is crucial to distinguish data (the actual content or responses produced by agents) and metadata (status reports, error messages, progress updates, and other operational information that guides system behavior). This distinction becomes particularly important when considering potential security vulnerabilities, as metadata can influence control-flow decisions even when primary outputs are properly secured."
  - "Multi-agent systems provide the infrastructure and schemas for agents to communicate and coordinate. Unlike conventional operating systems and Web browsers, they do not have a trust model, nor any semantics of inputs, actions, etc. The LLMs used to instantiate individual agents are unable to distinguish benign from malicious inputs, nor data from metadata. They blindly trust the outputs of confused deputies (i.e., other agents within the multi-agent system) and find creative ways to harm the user in response to the adversary's instructions."
  - "In all cases, each agent can see a partial history of the reasoning steps and actions that other agents have taken. This metadata is crucial for ensuring that multi-agent systems are functional."
