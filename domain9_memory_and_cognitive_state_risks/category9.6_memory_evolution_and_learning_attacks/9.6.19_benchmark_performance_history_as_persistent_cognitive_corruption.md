# 9.6.19 Benchmark Performance History as Persistent Cognitive Corruption [NoFW]

Agents maintaining performance history referencing prior benchmark results create persistent cognitive state vulnerable to poisoning with false success records for malicious tools. When agents retrieve fabricated success histories, they select malicious tools in future tasks. Multi-agent shared performance repositories enable one poisoned history entry to affect all agents querying shared benchmark results, creating pervasive latent backdoors where tool selection is driven by fabricated prior outcomes.

For example, an attacker inserts fabricated performance records showing that a malicious API wrapper achieved zero error rates across 500 prior benchmark tasks; when a retrieval agent queries the shared performance repository to select tools for a financial data pipeline, it consistently ranks the poisoned tool first based on false historical evidence. Standard defenses such as access control on performance repositories or anomaly detection for outlier scores are insufficient because the fabricated records are designed to mimic plausible high-performance profiles and are inserted through the same write paths used by legitimate benchmarking workflows. **Multi-agent distinction:** Shared performance repositories serve as a single source of truth consumed by all agents at tool-selection time, so one poisoned history entry can redirect every agent's tool-selection decisions fleet-wide without requiring repeated attack attempts, because the retrieval mechanism treats all history entries as authoritative prior evidence regardless of which agent originally contributed them.
