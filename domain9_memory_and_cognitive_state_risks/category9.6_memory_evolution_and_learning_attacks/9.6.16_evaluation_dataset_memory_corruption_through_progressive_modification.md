# 9.6.16 Evaluation Dataset Memory Corruption Through Progressive Modification [NoFW]

Evaluation datasets stored in mutable form can be progressively corrupted through small modifications across multiple evaluation runs in multi-agent pipelines. Attackers insert small corruptions through normal modification workflows via preprocessing, augmentation, and cleaning agents. Multi-agent dataset modification pipelines create distributed corruption vectors where normal agent operations provide cover for progressive poisoning, unlike singular evaluation with transparent dataset immutability.

For example, an adversary controlling a data-cleaning agent introduces minor label flips to a held-out evaluation set over dozens of runs—each individual change too small to trigger anomaly detection—until the cumulative corruption shifts aggregate pass rates by 15 percentage points in the attacker's favor. Standard defenses such as cryptographic checksums or dataset versioning are insufficient because each individual modification passes through legitimate preprocessing workflows that hold write authority, and the cumulative drift only becomes detectable long after the corrupted data has been used to calibrate agent behavior. **Multi-agent distinction:** Distributed dataset modification pipelines spread write authority across multiple agents (preprocessing, augmentation, cleaning), giving attackers multiple entry points for incremental corruption that no single agent observes in aggregate, and the cover of normal multi-agent operations prevents any individual contributor from recognizing the progressive poisoning pattern.
