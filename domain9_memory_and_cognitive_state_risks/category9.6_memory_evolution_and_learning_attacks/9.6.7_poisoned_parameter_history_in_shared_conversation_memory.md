# 9.6.7 Poisoned Parameter History in Shared Conversation Memory [NoFW]

Multi-turn parameter extraction errors in early turns persist in shared conversation memory and bias later turns. In multi-agent systems sharing memory, downstream agents inherit poisoned parameter values extracted by upstream agents as ground truth, with no mechanism to signal that a prior agent's extraction was erroneous. Unlike single agents that can recover through re-extraction, multi-agent memory sharing amplifies action-level problems across multiple agents through shared state propagation.

For example, an upstream extraction agent misreads a contract clause and stores "payment_term: 90_days" in shared conversation memory when the document specifies 30 days; all downstream agents—billing, compliance, and reporting—inherit the poisoned parameter as validated ground truth without access to the original document, compounding the extraction error across three distinct business workflows simultaneously.

Standard defenses such as per-field input validation and re-extraction at each agent boundary are insufficient because shared conversation memory is treated as the authoritative source of prior-turn extractions—each downstream agent receives what appears to be a confirmed prior result, and mandating full document re-reading at every agent would negate the architectural efficiency benefit of shared memory and is typically not implemented in practice.

**Multi-agent distinction:** In a single-agent system, a parameter extraction error can be caught through re-examination of source material in a follow-up turn within the same context; in multi-agent systems where extracted parameters are written to shared memory and consumed without access to the originating document, each downstream agent independently trusts the poisoned value and acts on it, compounding the error across all agents that draw on that shared state with no single vantage point where the full extraction chain is visible.
