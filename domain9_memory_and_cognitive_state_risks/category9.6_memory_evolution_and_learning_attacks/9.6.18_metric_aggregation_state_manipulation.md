# 9.6.18 Metric Aggregation State Manipulation [NoFW]

Evaluation pipelines aggregating metrics across test cases compute mean scores and failure rates from intermediate aggregation state. If aggregation state is mutable or intermediate results are stored, attackers with write access can manipulate the aggregation itself rather than individual results. Multi-agent metric aggregation where different agents contribute results to a central aggregation layer provides a high-leverage attack surface where one aggregation manipulation affects final metrics without altering any individual agent's reported results.

For example, an attacker with write access to the central aggregation buffer adjusts the running weighted sum so that a new agent model's failure rate appears 20% lower than measured, without altering any individual agent's reported results—leaving per-agent audit logs intact while corrupting the fleet-level decision. Standard defenses such as per-result integrity verification or signed agent reports are insufficient because the attack targets the aggregation layer itself, which sits downstream of any per-result signing and must necessarily hold mutable state to accumulate results from distributed contributors. **Multi-agent distinction:** Centralized metric aggregation creates a structural chokepoint—a single mutable store that consolidates outputs from many agents—giving attackers a high-leverage target where one undetected write operation shapes evaluation outcomes across the entire fleet without touching any individual agent's records, rendering per-agent auditing blind to the manipulation.
