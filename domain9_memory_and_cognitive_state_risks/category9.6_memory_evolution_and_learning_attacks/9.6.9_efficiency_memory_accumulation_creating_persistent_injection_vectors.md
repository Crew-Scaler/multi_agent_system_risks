# 9.6.9 Efficiency Memory Accumulation Creating Persistent Injection Vectors [NoFW]

Efficiency tracking stores historical metrics in memory for quick access across agent interactions. Attackers injecting false efficiency data into shared memory affect planning decisions across subsequent interactions and sessions. Single-agent efficiency memory poisoning affects one session, but multi-agent shared efficiency memory enables persistent backdoors where one injection affects planning decisions for hours or days across the entire agent fleet.

For example, an attacker injects a false historical entry recording "agent_gpt4_avg_tokens: 150, agent_local_avg_tokens: 12,000" into the shared efficiency store when the true relationship is reversed; the planning agent, reading these records to minimize token consumption, routes all high-priority tasks to the GPT-4 agent, inadvertently channeling sensitive data through an externally-hosted model the attacker has positioned as the low-cost option.

Standard defenses such as rate limiting on efficiency-metric writes and outlier detection on individual metric values are insufficient because attackers can inject plausible values within normal operating ranges through incremental poisoning spread across many interactions, and the planning agent has no mechanism to distinguish fabricated historical records from legitimate accumulated metrics once both are stored in the same shared efficiency store.

**Multi-agent distinction:** In a single-agent system, corrupted efficiency metrics affect only that agent's own optimization decisions within its session; in multi-agent systems where a shared efficiency store informs a central planning agent's routing and budget allocation for all subordinate agents, a single poisoned metric record propagates into every scheduling decision made by the fleet, achieving fleet-wide behavioral manipulation through one persistent injection that the targeted planning agent reads as authoritative operational history.
