# 9.1.2 Conversation History Display Provenance Opacity [NoFW]

Agents cannot reliably determine which prior conversation entries are authoritative versus injected, enabling historical record falsification.

The architectural property being exploited is the conversation history display's failure to distinguish between user-generated messages, agent-inferred statements, tool outputs, RAG-retrieved content, and inter-agent communications—all rendered in a uniform linear format that strips source metadata. The attack mechanism works by inserting attacker-controlled content into history through any available input channel (document uploads, tool responses, or direct messages), knowing the UI will present all entries identically regardless of origin. For example, when progressive disclosure patterns condense history into simplified summaries by default, nuanced provenance distinctions collapse into single-attribution statements, making a malicious RAG-retrieved fact appear visually identical to a directly stated user fact in the displayed timeline.

Standard defenses such as input sanitization or content filtering are insufficient because the attack exploits display-layer provenance collapse rather than content maliciousness; a semantically clean piece of falsified content appearing under the wrong attribution achieves the attack goal without triggering any content-based detection.

**Multi-agent distinction:** In multi-agent systems, each specialized agent contributes to conversation history based on its own processing, creating provenance chains spanning user inputs, multiple agents, and multiple tools that the UI flattens into a single linear timeline; no individual agent can reconstruct the original source of any given history entry, and the aggregated complexity of multi-agent history makes provenance opacity structurally unavoidable rather than merely a UI oversight.
