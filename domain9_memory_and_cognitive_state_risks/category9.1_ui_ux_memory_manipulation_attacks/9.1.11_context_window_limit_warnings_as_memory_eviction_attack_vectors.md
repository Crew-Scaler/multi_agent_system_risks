# 9.1.11 Context Window Limit Warnings as Memory Eviction Attack Vectors [NoFW]

Context awareness features displaying warnings when the agent's context window approaches limits create memory eviction attack vectors where attackers force eviction of security-relevant context while preserving poisoned instructions. Multi-agent systems with agents having different window sizes and eviction policies create opportunities where malicious instructions with injected high-priority markers are preserved while security constraints get evicted. The UI pattern of automatic context management never prompts explicit preservation choices, and multi-agent desynchronization means one agent evicts a "verify credentials" constraint while another retains it, creating exploitable security posture inconsistencies the UI's unified display obscures.

For example, an attacker pads the conversation with high-volume benign exchanges to force the agent's context window to its limit, then inserts a high-priority malicious override instruction just before the limit triggers automatic eviction; the agent's eviction policy drops the earlier "verify credentials before execution" constraint because it scores lower in recency or salience than the newly injected content, while the attacker's override instruction is retained as current context.

Standard defenses such as rate-limiting user messages are insufficient because the eviction mechanism is triggered by total token volume—benign padding content is indistinguishable from normal conversation, and the eviction decision is made by the agent's internal memory management rather than any security control.

**Multi-agent distinction:** Context eviction becomes uniquely exploitable in multi-agent architectures because each agent applies its own independent eviction policy to a different window size; an attacker can engineer desynchronization where Agent A evicts a shared security constraint while Agent B retains it, creating inconsistent security postures across the pipeline that the unified UI display hides from the user observing a single coherent conversation view.
