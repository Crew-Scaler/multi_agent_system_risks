# 9.1.8 Contextual Command Suggestions as Memory-Based Backdoor Triggers [NoFW]

Command palette patterns providing AI-powered contextual suggestions based on accumulated session history create memory-based backdoor triggers where poisoned historical context causes malicious command recommendations. In multi-agent systems, contextual suggestions derive from multiple agents analyzing different aspects (code context agent, user behavior agent, project history agent, security context agent). When attackers poison any contributing agent's memory, they manipulate which commands the palette suggests, making dangerous operations appear as trusted AI recommendations. The UI pattern of keyboard-driven rapid command execution (Cmd+K, arrow keys, Enter) enables acceptance without careful security review.

For example, an attacker poisons the project history agent's memory to falsely indicate the workspace is a "testing environment," causing the command palette to surface "Delete production database" under the AI Suggestions section; the user, trusting the AI recommendation and relying on keyboard-driven acceptance (Cmd+K, arrow, Enter), executes the destructive command without recognizing that the suggestion originated from corrupted historical context.

Standard defenses such as static command allowlists are insufficient because the attack operates through the AI suggestion layer, which dynamically ranks commands based on session history and therefore cannot be pre-filtered by rules that do not account for poisoned context determining which commands appear safe.

**Multi-agent distinction:** In multi-agent systems, command suggestions synthesize memory from multiple independent agents (code context, user behavior, project history, security context), so poisoning any single contributing agent's memory is enough to redirect the command palette for all users of that shared context—multiplying the blast radius of a single injection across every suggestion generated from that memory pool.
