# 9.1.7 Progressive Disclosure Collapsed State as Hidden Memory Corruption [NoFW]

Progressive disclosure patterns collapsing intermediate steps and technical details by default create hidden memory corruption where poisoned cognitive state resides in UI layers users rarely inspect. In multi-agent systems, collapsed disclosure states contain inter-agent communications, tool outputs, RAG retrieval results, and reasoning traces from multiple agents—all stored in expandable sections remaining collapsed during normal operation. When attackers poison these collapsed layers through compromised tools or data sources, corruption remains invisible to users reviewing only essential views. The UI pattern of "Show Details" expansion creates an assumption that the essential view is trustworthy, which attackers exploit by targeting collapsed content specifically designed to be hidden.

For example, a compromised RAG data source injects a malicious instruction into an agent's reasoning trace, which is stored in a collapsed "Show Details" section; the user reviews the visible conversation summary—which appears normal—while the poisoned reasoning trace persists invisibly in the collapsed layer and silently influences all subsequent agent decisions in the workflow.

Standard defenses such as content-filtering on user-facing message text are insufficient because the poisoned content resides in collapsed technical layers (tool outputs, reasoning traces, inter-agent communications) that those filters do not inspect.

**Multi-agent distinction:** Multi-agent systems uniquely amplify this risk because collapsed content aggregates from multiple independent agents—Agent A reasoning, Agent B tool outputs, Agent C analysis—creating a volume of collapsed state no user can practically review, and poisoning any single agent's collapsed output corrupts the shared hidden layer that all subsequent agents read as authoritative internal context.
