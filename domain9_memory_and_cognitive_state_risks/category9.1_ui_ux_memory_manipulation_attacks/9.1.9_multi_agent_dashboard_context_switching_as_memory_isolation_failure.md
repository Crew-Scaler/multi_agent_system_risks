# 9.1.9 Multi-Agent Dashboard Context Switching as Memory Isolation Failure [NoFW]

Multi-agent dashboard UIs displaying parallel conversation threads with different agents create memory isolation expectations that fail when agents share underlying session state or context stores. Users expect cognitive isolation between separate chat panels, but when agents share session persistence, conversation history, or learned user preferences through backend context stores, memory poisoning in one agent context contaminates other contexts invisibly. The visual metaphor of separate panels misrepresents actual cognitive boundaries, enabling memory poisoning attacks that are invisible to users observing UI-level isolation.

For example, an attacker interacts with Agent A in its dedicated panel and injects an instruction to relax access-control enforcement; because Agents A and B share a backend session store, that instruction silently propagates to Agent B's cognitive state, which then executes privileged operations with weakened controls despite Agent B's panel showing no unusual conversation history.

Standard defenses such as role-based access controls enforced at the API layer are insufficient because the attack does not bypass API authorization—it corrupts the shared in-memory context that agents consult when deciding how to interpret and apply those controls.

**Multi-agent distinction:** The isolation failure is architecturally unique to multi-agent dashboards: the UI's visual design—separate panels implying separate cognitive spaces—actively misleads users into believing no cross-contamination can occur, while the underlying shared context store makes cross-panel memory poisoning not just possible but structurally inevitable wherever agents are built to share session state for coordination efficiency.
