# 9.5.11 Semantic Cache Entry Poisoning Through Adversarial Embedding Injection [NoFW]

Attackers craft queries whose embeddings fall within the similarity threshold of legitimate cached queries, causing their poisoned responses to be returned in place of cached legitimate responses.

Semantic caching systems store (query_embedding, response) pairs and serve a cached response whenever an incoming query's embedding is within a configured cosine-distance threshold of a stored key; an attacker submits a crafted adversarial query whose embedding is optimized to be a near-neighbor of multiple high-frequency legitimate queries, pairing it with a poisoned response that displaces the correct cached answers for all semantically proximate future requests. For example, in a customer-service pipeline using semantic caching for FAQ responses, an attacker submits a rephrased version of "how do I reset my password" whose embedding is engineered to sit at the centroid of the legitimate FAQ cluster; the attacker's poisoned response ("contact external support at attacker-controlled-email@example.com") is then served to every user whose password-reset query lands in that embedding neighborhood.

Standard defenses such as similarity threshold tightening are insufficient because the adversarial embedding is computed to be genuinely semantically proximate—not merely numerically close in an arbitrary sense—so any threshold permissive enough to allow useful semantic generalization will also admit the crafted adversarial key.

**Multi-agent distinction:** In a single-agent deployment the semantic cache serves one agent's query stream; in multi-agent systems sharing a semantic cache layer, one adversarially placed cache entry returns the poisoned response to every agent whose query embeddings fall within the contaminated neighborhood, scaling the attack's reach proportionally to the number of agents sharing the cache without requiring separate compromise of each agent.
