# 9.5.1 Embedding Cache Poisoning Creating Persistent Latent Backdoors [NoFW]

Attackers poison shared embedding caches so that specific query patterns retrieve malicious context, creating a persistent backdoor that activates whenever the cached query pattern is triggered.

Embedding caches store pre-computed vectors for frequently-accessed content—prompts, tool descriptions, RAG document chunks—so that similarity lookups return cached results without re-computing embeddings. An attacker with write access to the shared embedding store crafts a malicious document whose embedding vector is optimized to land within the similarity threshold of high-frequency legitimate queries; the poisoned document is then served as retrieved context every time those queries fire, injecting attacker-controlled instructions into the reasoning pipeline. For example, in a multimodal RAG system, an attacker submits a document whose DePlot-extracted embedding clusters near "Q4 financial review" queries; every agent querying for Q4 data retrieves the attacker's content alongside legitimate results, silently biasing analytical outputs.

Standard defenses such as input content filtering are insufficient because the attack operates at the numeric vector layer: the poisoned embedding is indistinguishable from a legitimate high-relevance result by cosine-similarity alone, and cache-hit responses are typically not re-validated against safety classifiers.

**Multi-agent distinction:** In single-agent deployments the compromised embedding cache is scoped to one agent's retrieval index; in multi-agent systems where a shared embedding backend serves dozens of specialized agents, one poisoned vector becomes a system-wide latent backdoor that activates identically across every downstream agent querying semantically similar content, with no per-agent quarantine mechanism to limit blast radius.
