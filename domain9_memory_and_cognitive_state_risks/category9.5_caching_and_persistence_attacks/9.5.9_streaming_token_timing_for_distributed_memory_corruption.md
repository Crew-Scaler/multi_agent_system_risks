# 9.5.9 Streaming Token Timing for Distributed Memory Corruption [NoFW]

Attackers controlling streaming timing can inject context at specific moments when distributed multi-agent memory synchronizes. By controlling one agent's streaming speed, attackers force specific memory states in other agents through synchronization timing manipulation. Distributed multi-agent memory creates multiple synchronization windows absent from singular centralized memory, enabling targeted memory state control through timing attacks.

For example, an attacker controlling a malicious data-source agent deliberately delays token delivery to align with the memory synchronization heartbeat of a downstream coordinator agent; the coordinator's sync snapshot captures the attacker's partially streamed payload as the most recent agent state, overwriting the legitimate prior state in shared memory before the complete response can be validated against safety constraints.

Standard defenses such as fixed synchronization intervals are insufficient because the attacker can observe timing side-channels—response latency differences between cache hits and misses are measurable through prompt-caching timing audits—to infer synchronization windows and time injections to land precisely within them.

**Multi-agent distinction:** Single-agent memory operates through a centralized write path where timing attacks have no synchronization windows to exploit; distributed multi-agent memory creates multiple independent sync boundaries across agents, each representing a distinct timing attack surface that the attacker can probe and exploit independently to achieve targeted memory state corruption in specific agents while leaving others unaffected.
