# 9.5.12 Response Cache Corruption Through Query Normalization Collisions and Cache Key Manipulation [NoFW]

Response caching using normalized query text as cache keys creates collision vectors where attackers inject poisoned cache entries that collide with legitimate queries through normalization-equivalent crafted queries. Normalization applying lowercasing, whitespace collapsing, and punctuation removal enables attackers to submit maliciously padded queries paired with poisoned responses that cache under keys identical to natural user queries. Legitimate users subsequently retrieve poisoned responses without any cache-hit anomaly indicator.

For example, an attacker submits "  What IS the account   BALANCE  ?  " (extra whitespace, mixed case, trailing punctuation) paired with a fraudulent response showing a falsely inflated balance; the normalization pipeline reduces it to "what is the account balance?" which collides with the canonical cache key used by legitimate users, so all subsequent balance queries from any user or agent are served the attacker's fabricated response from cache without ever querying the live database.

Standard defenses such as per-request authentication are insufficient because cache key collisions exploit the normalization layer that runs after authentication, allowing an authenticated attacker to poison cache entries that are then transparently served to other authenticated users and agents who make semantically equivalent but lexically distinct queries.

**Multi-agent distinction:** In a single-agent system the corrupted cache entry affects queries from one agent; in multi-agent systems sharing a common response cache, a single normalization-collision entry corrupts the canonical response for every agent querying that key—including orchestrators, sub-agents, and user-facing agents—because all trust the shared cache as a reliable source of truth with no per-agent revalidation of cached results.
