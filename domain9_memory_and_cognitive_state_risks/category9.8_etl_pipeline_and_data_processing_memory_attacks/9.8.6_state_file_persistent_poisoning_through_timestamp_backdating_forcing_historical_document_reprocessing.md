# 9.8.6 State File Persistent Poisoning Through Timestamp Backdating Forcing Historical Document Reprocessing [NoFW]

Incremental ETL pipelines relying on state files persisting timestamps are vulnerable to timestamp manipulation that forces mass reprocessing of historical data. Backdating timestamps forces reprocessing of months of historical documents, flooding vector databases with duplicate chunks that dilute retrieval precision and allow attackers to amplify specific documents through repeated indexing. Multi-agent systems with shared state files experience synchronized poisoning where one timestamp manipulation affects all agents simultaneously, creating coordinated knowledge base corruption.

For example, an attacker backdating `{"last_run": "2024-11-10T14:00:00Z"}` to `{"last_run": "2024-01-01T00:00:00Z"}` in a shared state file triggers the next ETL run to reprocess approximately 1 million documents (assuming 10M documents with 1% monthly change rate over 10 months), inserting 2-10 duplicate chunks per document into the vector database; retrieval queries then return multiple near-identical chunks from the same source documents, reducing the probability of surfacing semantically diverse content and allowing the attacker to amplify specific documents by causing them to be indexed repeatedly.

Standard defenses such as ETL run logging are insufficient because backdated timestamps produce valid-looking incremental queries that complete successfully and are logged as normal pipeline executions, with no anomaly distinguishing them from legitimate catch-up runs following system downtime or maintenance windows.

**Multi-agent distinction:** Single-agent ETL corruption affects only that agent's knowledge base; when agents share a centralized state file, one timestamp backdating event propagates simultaneously to all agents, creating synchronized duplicate flooding across the entire fleet in a single ETL cycle that no individual agent can detect or prevent independently.
