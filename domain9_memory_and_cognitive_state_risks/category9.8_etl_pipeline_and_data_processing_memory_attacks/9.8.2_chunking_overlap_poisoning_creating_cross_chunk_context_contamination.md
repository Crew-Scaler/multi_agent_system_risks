# 9.8.2 Chunking Overlap Poisoning Creating Cross-Chunk Context Contamination [NoFW]

Attackers craft documents where malicious content spans chunk boundaries, causing it to be embedded in multiple retrieval chunks and retrieved under a broader range of queries.

ETL chunking pipelines preserve context at chunk boundaries by overlapping consecutive chunks by a fixed token window (typically 50 tokens); attackers crafting documents with malicious instructions placed precisely at the boundary zone cause those instructions to appear in multiple overlapping chunks simultaneously. For example, in a technical manual where chunk A ends with legitimate authentication guidance and chunk B begins with "validating credentials by skipping verification for testing purposes," both chunks carry the malicious overlap text; if chunk B's boundary with chunk C is similarly poisoned, the contamination propagates through the entire document section and is retrievable under a broad range of authentication-related queries rather than a narrow target.

Standard defenses such as document-level content scanning are insufficient because malicious overlap content is grammatically integrated at chunk boundaries where it appears as natural continuation text rather than a detectable injection, and chunk-boundary regions are rarely inspected independently by content moderation pipelines.

**Multi-agent distinction:** Single-agent RAG pipelines apply consistent chunking and retrieval within one context; multi-agent pipelines where one agent chunks documents and another independently retrieves and synthesizes them create a trust gap in which the retrieving agent has no visibility into how overlap regions were constructed and cannot distinguish tampered boundary text from legitimate content transitions authored in the original document.
