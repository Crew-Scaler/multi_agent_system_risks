# 9.8.3 Quality Validation Threshold Degradation Through Incremental Configuration Drift [NoFW]

ETL quality filters using configurable thresholds loaded from configuration files degrade through incremental changes that appear justified individually but accumulate into significant quality erosion. Each threshold reduction permits lower-quality content into the knowledge base, and when old high-quality chunks coexist with new low-quality fragments, retrieval preferentially surfaces unhelpful fragments due to their higher frequency of generic phrases matching many queries. Multi-agent systems with centralized configuration management experience synchronized fleet-wide quality degradation when shared config is updated.

For example, successive config.yaml updates reducing `min_length` from 100 to 75 to 50 characters over three months admit terse fragments like "error occurred" and "please contact support" that achieve high embedding similarity to many queries because of their generic phrasing, crowding out detailed documentation in retrieval results while appearing individually as reasonable accommodations for terse technical notes.

Standard defenses such as post-deployment retrieval quality audits are insufficient because each individual threshold reduction is small and appears as an operational accommodation rather than a security event, and cumulative degradation only becomes apparent when aggregate retrieval quality is measured over long time horizons rather than inspected at the moment of each change.

**Multi-agent distinction:** In single-agent deployments, threshold drift silently degrades one pipeline's knowledge base; in multi-agent systems sharing centralized configuration, a single config.yaml edit propagates to all agents' ETL pipelines simultaneously, causing fleet-wide knowledge base quality erosion that no individual agent can detect or reverse independently.
