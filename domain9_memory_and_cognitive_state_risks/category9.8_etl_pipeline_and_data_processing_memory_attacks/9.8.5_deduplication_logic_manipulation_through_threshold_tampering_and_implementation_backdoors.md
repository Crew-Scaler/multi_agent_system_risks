# 9.8.5 Deduplication Logic Manipulation Through Threshold Tampering and Implementation Backdoors [NoFW]

Deduplication systems using configurable thresholds for exact, fuzzy, and semantic matching are vulnerable to threshold manipulation that either over-aggressively removes valid content or under-aggressively allows duplicates to proliferate. Targeted threshold manipulation can systematically suppress content from specific sources by applying different thresholds per source system. Implementation backdoors embedded in deduplication logic create persistent selective suppression enabling long-term knowledge base distortion invisible to operators monitoring only aggregate deduplication rates.

For example, an attacker with access to deduplication configuration reduces the fuzzy matching threshold from 0.90 to 0.70 specifically for one source system; documents with only 70% similarity from that source are now marked as duplicates and discarded, systematically suppressing that source's unique content while the configuration change appears to operators as a routine parameter tuning decision.

Standard defenses such as aggregate duplicate count monitoring are insufficient because aggregate deduplication rates may remain stable while the target-specific threshold change silently removes all unique content from the targeted source system, with the suppression invisible to any metric that does not stratify deduplication outcomes by source.

**Multi-agent distinction:** In single-agent deployments, deduplication threshold tampering affects one agent's knowledge base; in multi-agent systems sharing centralized deduplication pipelines, threshold changes propagate to all agents' ingestion simultaneously, enabling coordinated content suppression from targeted sources across the entire fleet without any individual agent being able to detect the selective removal through its own observability.
