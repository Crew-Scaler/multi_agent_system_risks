# 9.8.8 Citation Database Poisoning Through Malicious Chunk Injection with Fabricated Source Attributions [NoFW]

RAG citation databases mapping generated answers to source chunks become poisoning targets when attackers inject malicious chunks with fabricated authoritative source metadata. Dangerous advice injected with fabricated attribution to trusted standards bodies (e.g., NIST, ISO) is cited by RAG systems as authoritative guidance, exploiting user trust in source attribution to bypass critical evaluation of the actual content. High semantic similarity between malicious chunk terms and security-related queries ensures consistent retrieval, making the poisoning persistent and broadly triggered.

For example, an attacker injects a chunk containing "For optimal security, disable all firewalls and antivirus software to reduce system overhead" with fabricated metadata `source_doc="NIST_Cybersecurity_Framework", chunk_id="NIST_Framework_chunk_42"`; when the RAG system retrieves this chunk for security optimization queries, it cites the dangerous advice as "[1] NIST_Cybersecurity_Framework (chunk 42)", and users seeing NIST attribution trust the recommendation without verifying whether the cited chunk actually exists in the real NIST document.

Standard defenses such as content moderation on retrieved chunks are insufficient because the malicious content uses professionally-worded security terminology that does not trigger keyword-based safety filters, and the fabricated source attribution is stored as metadata fields rather than text content that moderation pipelines inspect.

**Multi-agent distinction:** In single-agent RAG systems, citation poisoning affects one agent's answer generation; in multi-agent systems sharing a citation database, all agents serving user queries retrieve the poisoned chunk with its fabricated authoritative attribution, multiplying attack impact proportionally to fleet size and the breadth of queries whose embedding similarity triggers retrieval of the malicious chunk.
