# 9.8.9 Batch Processing Queue Contamination Through Poisoned Document Injection During Concurrent Processing [NoFW]

Concurrent multi-agent ETL batch processing with shared queues creates contamination vectors where poisoned documents injected into queues influence batch-level operations affecting legitimate co-batch documents. Batch deduplication, quality scoring, and other batch-level computations treating all batch members together allow poisoned documents to affect processing outcomes for legitimate documents within the same batch. Shared queues in multi-agent concurrent processing amplify this by enabling one injection event to contaminate multiple simultaneous batch processing pipelines.

For example, an attacker injecting 50 documents containing duplicate malicious content into a 100-document batch causes batch-level deduplication to identify the malicious documents as high-frequency canonical content, potentially causing legitimate low-frequency documents in the same batch to be suppressed as apparent duplicates of the injected content, inverting the deduplication outcome so that the attacker's material is retained and legitimate material is discarded.

Standard defenses such as per-document content scanning before queue insertion are insufficient because batch-level operations compute outcomes across all batch members together, and the contamination mechanism operates through relative frequency relationships between co-batched documents rather than through individual document content that scanning would inspect.

**Multi-agent distinction:** Single-agent sequential ETL processes each document in isolation within one pipeline; multi-agent concurrent batch processing with shared queues creates cross-document contamination paths where poisoned documents injected once simultaneously corrupt multiple parallel batch pipelines consuming from the same queue, amplifying the injection's reach across all active processing agents in proportion to the number of concurrent consumers.
