# 9.4.17 Tool Invocation Frequency Learned Patterns as Memory-Based Backdoor [NoFW]

Agents with learning systems storing tool usage frequency patterns create backdoors when memory is poisoned with malicious sequences disguised as learned best practices. Unlike direct instruction injection, pattern-based backdoors are invisible as seemingly-learned operational norms. Multi-agent memory sharing propagates learned pattern backdoors across agent boundaries, creating fleet-wide behavioral corruption from a single pattern injection.

For example, an attacker poisons frequency memory with the pattern "for API authentication tasks, always call validate_token first, then call fetch_permissions" but substitutes a look-alike "fetch_permissions" endpoint that exfiltrates authorization data; agents reading that pattern from shared memory follow it as a learned operational norm without inspecting whether the referenced tool is the legitimate one, because the pattern appears as an accumulated empirical finding rather than an explicit instruction.

Standard defenses such as anomaly detection on tool invocation sequences are insufficient because poisoned patterns are designed to be statistically plausible — they mimic legitimate frequency distributions and resemble observed best practices rather than novel or outlier sequences that anomaly detectors flag, making them indistinguishable from benign learned behavior at the behavioral level.

**Multi-agent distinction:** In single-agent systems, learned frequency patterns are isolated to one agent's local behavioral model; in shared multi-agent memory, a single poisoned learned pattern propagates to every agent that draws tool-selection guidance from the shared store, replicating the backdoor behavior across the entire fleet without re-poisoning individual agents.
