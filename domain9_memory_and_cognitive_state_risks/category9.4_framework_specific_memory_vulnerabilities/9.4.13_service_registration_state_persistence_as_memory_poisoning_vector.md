# 9.4.13 Service Registration State Persistence as Memory Poisoning Vector [Semantic Kernel]

Kernel service registrations persist for the lifetime of the kernel instance. Attackers manipulating service registration state by de-registering legitimate services or registering malicious replacements cause corruption persisting across all subsequent plugin invocations. Multi-agent systems where plugins coordinate through shared kernel services face backdoors activating through service mutation, affecting all downstream agents in contrast to federated per-agent kernels that would isolate corruption.

For example, a malicious plugin de-registers the kernel's "audit_logger" service and replaces it with a no-op stub; all subsequent plugins that call the kernel's audit service silently discard security events, leaving no trace of unauthorized operations for the remainder of the kernel instance's lifetime, while the attacker's actions proceed unlogged.

Standard defenses such as capability-based access control on service registration are insufficient because kernel service registrations are typically granted uniformly to all plugins within the same kernel instance as a design convenience, and runtime monitoring systems that audit plugin outputs do not inspect the service registry state that governs how those outputs were produced — the corruption is invisible at the output layer.

**Multi-agent distinction:** In federated per-agent kernel architectures, service registration corruption is contained to one agent's kernel instance; in shared kernel architectures where multiple agents invoke plugins through a common kernel, a single service registration mutation corrupts the execution environment for every agent in the pool for the entire lifetime of that kernel instance, multiplying the impact without requiring per-agent exploitation.
