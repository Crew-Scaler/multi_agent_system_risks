# 9.4.7 Memory Key Namespace Collision Enabling Context Injection [LangChain]

LangChain memory systems use memory_key parameters to inject context into prompts, creating vulnerability when multiple agents share memory stores using identical key names. Attackers exploit namespace collisions by injecting malicious content under shared keys, causing all agents referencing those keys to incorporate poisoned context. Multi-agent architectures standardizing memory key names for convenience create collective vulnerabilities absent from isolated singular agent systems with separate memory namespaces.

For example, if two agents both use `chat_history` as their memory key against a shared Redis backend, an attacker who writes a poisoned entry under that key causes every agent querying `chat_history` to receive and incorporate the malicious content—without any individual agent being compromised.

Standard defenses such as per-agent authentication to the memory backend are insufficient because namespace collisions occur at the logical level of key naming; even a fully authenticated agent reads poisoned content when its key name matches a key an attacker has written under, since authentication controls who may write but does not isolate what each authenticated writer can affect.

**Multi-agent distinction:** Isolated single-agent deployments maintain private memory namespaces with no collision surface; multi-agent systems that share a common memory backend and standardize key names for operational convenience convert that convenience into a single poisoning point whose effect is felt by every agent referencing the shared key.
