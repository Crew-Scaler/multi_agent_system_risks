# 9.4.11 Manager Decision Memory in CrewAI Hierarchies Creating Cross-Worker Context Poisoning [CrewAI]

CrewAI managers maintain memory of worker outputs and decisions, but this memory becomes vulnerable when poisoned worker outputs remain in manager context and influence future delegations. Managers learning from corrupted worker outputs incorporate malicious patterns into future task delegation decisions. Attackers exploit this by causing systematic misalignment in delegation patterns through manager memory poisoning, a risk unique to hierarchical multi-agent frameworks with persistent manager-level state.

For example, an attacker causes one worker agent to return fraudulent performance data — reporting a task completed successfully with high accuracy — so the CrewAI manager stores this in its worker performance memory and subsequently delegates higher-trust tasks to that compromised worker, bypassing the routing checks that would have flagged a low-trust agent.

Standard defenses such as output validation at ingestion and worker sandboxing are insufficient because the CrewAI manager's memory of worker performance is built progressively from accumulated task results — even if individual outputs pass format checks, the manager's learned delegation patterns encode the cumulative effect of prior poisoned outputs rather than re-validating historical records before each delegation decision.

**Multi-agent distinction:** In single-agent systems there is no manager layer accumulating cross-worker performance memory; CrewAI's hierarchical architecture creates a manager-level context layer where one worker's poisoned output permanently biases how the manager delegates to all workers in subsequent tasks, a propagation path that does not exist in flat single-agent designs.
