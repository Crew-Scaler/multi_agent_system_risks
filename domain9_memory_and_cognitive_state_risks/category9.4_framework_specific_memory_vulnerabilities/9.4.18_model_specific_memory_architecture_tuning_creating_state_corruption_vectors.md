# 9.4.18 Model-Specific Memory Architecture Tuning Creating State Corruption Vectors [NoFW]

In multi-agent systems where agents swap between different underlying models during parameter tuning, shared state persists across model switches but may be architecturally incompatible. Attackers exploit model-architecture mismatches by crafting state that one model stores correctly but another model misinterprets through differing tokenization or context window semantics. Singular agent-model combinations maintain consistent state semantics; multi-agent model switching creates semantic translation boundaries where state corruption occurs during cross-model memory retrieval.

For example, in a system routing complex analysis tasks to GPT-4 and simple retrieval tasks to GPT-3.5-Turbo, an attacker crafts a cached embedding using GPT-4's tokenizer that encodes a benign-appearing key in GPT-4's semantic space but maps to an adversarial trigger in GPT-3.5-Turbo's tokenizer; state written safely by the analysis agent activates a backdoor instruction when retrieved by the retrieval agent due to the cross-model representational mismatch.

Standard defenses such as per-model schema validation and embedding normalization are insufficient because the semantic mismatch exploited here is not a structural format violation — the crafted state passes schema checks for both models individually, and the adversarial meaning emerges only at the cross-model retrieval boundary where two independently valid representations are interpreted as equivalent.

**Multi-agent distinction:** Singular agent-model pairings maintain internally consistent state semantics throughout a session; multi-agent architectures that route tasks to different models against shared persistent state create implicit semantic translation boundaries where adversarially crafted state can be stored benignly by one model and interpreted maliciously by another, an attack surface that does not exist when a single model owns all state interactions.
