# 9.4.3 Reducer State History Manipulation as Latent Instruction Persistence [NoFW]

LangGraph reducers accumulating state across agent steps can be seeded with malicious history entries that influence all future state reductions.

LangGraph reducers—particularly the default `add_messages` reducer—append incoming state updates to a growing history without pruning, so every message or state entry injected early in a workflow accumulates permanently in the `messages` field. An attacker who plants a malicious instruction as an early state entry watches it persist indefinitely; later agents iterating over the full accumulated history encounter the poisoned entry and execute the latent instruction as if it were authoritative prior context from a legitimate earlier step.

Standard defenses such as filtering incoming messages at ingestion points are insufficient because reducer behavior is a structural property of the graph definition, and malicious history entries are syntactically valid state updates that pass schema validation while semantically encoding dormant instructions that only manifest when downstream agents process that portion of accumulated history.

**Multi-agent distinction:** In single-agent systems, memory operates within one session or model boundary; in multi-agent shared message histories, reducer-accumulated poisoned entries persist across agent boundaries and sessions, turning what would be a transient injection in a single-agent context into a permanent collective vulnerability affecting every agent that iterates over the shared state.
