# 9.2.2 Concurrent Multi-Agent Graph Traversal Race Conditions [NoFW]

Parallel agent traversals of shared knowledge graphs with asynchronous updates create inconsistent graph snapshots, enabling attackers to exploit the window of inconsistency.

Shared knowledge graphs in multi-agent systems combine concurrent read access by multiple agents with asynchronous write updates, creating temporal windows of inconsistency that vary by database isolation level. An attacker times a malicious edge write to land during a targeted agent's open read transaction, exploiting isolation gaps so that Agent A sees the pre-write snapshot while Agent B sees the post-write graph — two agents that both believe their view is current but hold contradictory facts. For example, a threat actor monitors response latency patterns to infer traversal windows, then injects a false "authorized-for" edge between an unprivileged entity and a sensitive data node; Agent A, mid-traversal, misses the injected edge, while Agent B, querying moments later, follows it and grants the access — defeating any consensus check that relies on both agents seeing the same graph state.

Standard defenses such as transaction isolation and read-after-write consistency checks are insufficient because they are typically configured per-node rather than across the distributed traversal session, and isolation-level variations between database nodes allow attacker-timed writes to land in the gap between two agents' concurrent reads.

**Multi-agent distinction:** A single agent serializes all graph reads and writes within one transaction scope, eliminating the temporal gap; multi-agent architectures expose a distributed concurrency surface where an attacker can target one agent's traversal window without affecting another agent's view, breaking the assumptions behind consensus-based validation that requires all participants to share the same graph snapshot.
