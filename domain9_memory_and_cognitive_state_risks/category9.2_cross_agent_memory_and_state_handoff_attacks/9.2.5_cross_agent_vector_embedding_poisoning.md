# 9.2.5 Cross-Agent Vector Embedding Poisoning [NoFW]

Attackers inject malicious content into shared vector databases with embeddings crafted to semantically align with trusted queries, causing adversarial information retrieval across multiple agents in collaborative systems. The attacker optimizes a poisoned document's embedding vector to maximize cosine similarity with high-frequency query embeddings, causing the poisoned document to rank among top results alongside legitimate content. A single poisoned embedding in a shared vector store affects every agent querying that index, and the corruption is invisible to agents inspecting retrieved text since it operates at the vector layer.

For example, in a legal research multi-agent system where a research agent and a summarization agent both query a shared case-law vector database, an attacker uploads a poisoned brief whose embedding is gradient-optimized to achieve cosine similarity above 0.95 with query embeddings for "breach of contract," causing both agents to retrieve the adversarial document and incorporate its fabricated precedents into final client memos.

Standard defenses such as query-time content filters and signature-based anomaly detection are insufficient because the poisoned document may appear superficially valid as plain text, and anomaly detection at the vector layer requires knowing the adversarial embedding target in advance—information defenders do not possess until after retrieval has already occurred.

**Multi-agent distinction:** In a single-agent system a poisoned embedding harms only that agent's context window; in shared-index multi-agent architectures the single poisoned record contaminates every agent's retrieval simultaneously, delivering O(N) agent impact from a one-time O(1) write that is indistinguishable from a legitimate document insertion.
