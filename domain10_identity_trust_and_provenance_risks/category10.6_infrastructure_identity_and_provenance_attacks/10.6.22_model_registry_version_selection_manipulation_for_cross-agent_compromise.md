# 10.6.22 Model Registry Version Selection Manipulation for Cross-Agent Compromise [NoFW]

MLflow model registry enables agents to select model versions by semantic constraints. Attackers compromising the registry inject malicious versions matching version constraints, causing all agents querying the registry to simultaneously load compromised models. Agent A loading the compromised version passes results to Agent B which loads the same registry entry, creating coordinated multi-agent compromise.

For example, an attacker registers a malicious MLflow model version tagged `2.3.1` — satisfying the `^2.3.0` range constraint that multiple agents use — and sets its `stage` to "Production"; all agents performing registry queries at the next refresh window simultaneously load the compromised model artifact without any per-agent exploitation.

Standard defenses such as MLflow model staging controls and model validation pipelines are insufficient because version range semantics allow any compliant version to satisfy a constraint, and validation pipelines typically test model accuracy rather than detecting adversarial weight modifications; additionally, shared registry access means that once a malicious version passes staging validation, every agent consuming that registry entry is affected simultaneously.

**Multi-agent distinction:** In single-agent deployments, model registry compromise affects one model consumer and remediation requires updating one configuration; in multi-agent systems where all agents query a shared MLflow registry using overlapping version constraints, a single registry injection causes all querying agents to load the compromised model simultaneously, and the cross-agent data flow (Agent A's outputs becoming Agent B's inputs) means the poisoned model's effects propagate through the entire pipeline regardless of which specific agent loaded the compromised version first.
