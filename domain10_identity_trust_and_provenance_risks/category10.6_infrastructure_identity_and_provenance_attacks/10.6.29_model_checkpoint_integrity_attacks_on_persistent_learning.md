# 10.6.29 Model Checkpoint Integrity Attacks on Persistent Learning [NoFW]

Agents checkpoint learned weights for resumption. Attackers corrupt checkpoints to activate previously-dormant backdoors during resumption. Learning systems resuming from corrupted checkpoints inherit attacker modifications. Shared checkpoints enable one corruption affecting multiple agents simultaneously through the shared checkpoint infrastructure.

For example, an attacker with write access to a shared NFS volume storing agent checkpoints replaces the latest checkpoint file with one containing adversarially modified weights; when a fleet of learning agents resumes from this shared checkpoint after a planned maintenance window, all agents simultaneously load the corrupted weights and begin executing the embedded backdoor behavior — such as responding to a specific trigger phrase with exfiltrated context — while their behavioral profiles appear nominally normal on standard evaluation metrics.

Standard defenses such as checkpoint hash verification and access controls on storage volumes are insufficient because hash verification only confirms that the stored file matches the stored hash — if the attacker also updates the hash record alongside the checkpoint, verification passes; and filesystem access controls are frequently relaxed on shared volumes to enable concurrent agent reads, inadvertently granting write access to any compromised agent in the fleet.

**Multi-agent distinction:** In single-agent deployments, checkpoint corruption affects one agent's learned behavior and is detectable through behavioral comparison; in multi-agent systems sharing a checkpoint store, one corrupted checkpoint simultaneously re-initializes all agents that resume from it, producing coordinated behavioral changes across the fleet that resemble synchronized drift rather than isolated compromise, making detection through cross-agent behavioral comparison impossible because all agents exhibit the same attacker-induced behavior.
