# 10.6.10 Cluster Node Identity Spoofing in Gossip Protocol Communications [NoFW]

Multi-node vector database clusters use gossip protocols for membership coordination identified by CLUSTER_HOSTNAME values. Attackers spoof node identities by forging CLUSTER_HOSTNAME values in gossip messages, creating identity conflicts that enable data poisoning, query interception, and consensus disruption. Multi-agent systems querying clusters trust cluster topology without verifying individual node identity, amplifying this risk.

For example, in a Qdrant cluster where three nodes coordinate membership via gossip on port 6335, an attacker with network access to the gossip broadcast domain can transmit forged gossip packets claiming `CLUSTER_HOSTNAME=node1` at a different IP, causing cluster members to update their routing tables to send shard queries to the attacker's endpoint, which then serves poisoned vector embeddings to all agents querying that shard.

Standard defenses such as firewall rules restricting gossip port access are insufficient because gossip protocols often operate over internal cluster networks assumed to be trusted, and the protocol itself does not include cryptographic authentication of hostname claims, making any endpoint on the internal network capable of injecting forged membership announcements.

**Multi-agent distinction:** Single-node vector database deployments have no gossip surface and no inter-node identity to spoof; multi-agent systems relying on clustered databases distribute trust across a gossip mesh where unverified hostname assertions control data routing, meaning one forged gossip message can redirect queries from all agents simultaneously to attacker-controlled infrastructure.
