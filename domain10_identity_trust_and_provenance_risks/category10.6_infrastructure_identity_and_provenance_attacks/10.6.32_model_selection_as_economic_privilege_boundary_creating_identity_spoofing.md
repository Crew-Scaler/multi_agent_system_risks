# 10.6.32 Model Selection as Economic Privilege Boundary Creating Identity Spoofing [NoFW]

Model selection creates implicit capability tiers where different models represent different privilege levels. In multi-agent systems, attackers spoof agent identity by compromising agent API calls to invoke higher-tier models while appearing to use lower-capability ones, or vice versa, misrepresenting capability boundaries to deceive trust evaluation.

For example, an attacker who compromises a routing agent intercepts outbound API calls from high-trust analysis agents and rewrites the `model` field from `gpt-4o` to `gpt-3.5-turbo` while spoofing the response to appear as if it came from the premium model; the orchestrator, which grants elevated trust and exposes sensitive financial data only to agents it believes are running the high-capability model, continues to route privileged tasks to the compromised channel unaware that responses now originate from a cheaper, less-capable model whose outputs the attacker can also manipulate.

Standard defenses such as API key scoping and response format validation are insufficient because model selection operates at the request metadata level rather than the cryptographic identity level — API keys authenticate the caller's account but not which model the response was actually generated by; and response format validation checks structural compliance, not whether the substantive quality or trustworthiness of the response reflects a specific model's capabilities.

**Multi-agent distinction:** In single-agent deployments, model spoofing affects one agent's outputs and is detectable by the single operator; in multi-agent systems where model selection signals form implicit capability-based trust tiers that govern which agents share sensitive context, execute high-stakes tools, or receive elevated delegation authority, systematic model field spoofing allows an attacker to position compromised agents as high-privilege fleet members across all agents that grant trust based on declared model identity — affecting every trust-based routing decision in the fleet simultaneously.
