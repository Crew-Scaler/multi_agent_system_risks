# 10.6.28 Framework-Enforced Identity Models Creating Cross-Framework Impersonation Opportunities [NoFW]

Different frameworks implement agent identity differently (LangChain's implicit identity, LangGraph's node identity, AutoGen's instance names, CrewAI's role-based identity, Semantic Kernel's plugin identity). Multi-agent systems integrating across frameworks create identity translation gaps where N frameworks create N(N-1) translation semantics likely containing impersonation opportunities.

Cross-framework identity translation exploits the architectural property that each framework uses framework-native identity primitives (role strings, node IDs, instance names, plugin descriptors) that carry trust semantics only within the originating framework's runtime — yet multi-agent systems frequently bridge these frameworks over message buses or REST APIs that flatten identity into generic fields without cryptographic binding to a specific framework's identity model. The attack mechanism involves crafting messages whose identity fields are semantically valid in both the sending and receiving frameworks but carry different trust levels in each, exploiting the translation layer's ambiguity to assume an elevated identity in the destination framework. For example, an attacker injecting a message into a bus connecting a CrewAI orchestrator to a LangGraph planner sets the `role` field to "Manager" (CrewAI's highest-trust role) and the `node` field to "PlanningRoot" (LangGraph's privileged entry node); the translation adapter, lacking a strict bijective mapping, honors both claims, granting the attacker simultaneous Manager-level authority in CrewAI and PlanningRoot access in LangGraph — privileges that neither framework would grant independently.

Standard defenses such as per-framework authentication middleware are insufficient because they validate identity within a single framework's model and terminate at the framework boundary; cross-framework trust bridges that translate identity across heterogeneous models lack standardized cryptographic identity binding that survives translation, meaning an identity accepted in one framework provides no provable assurance of the original identity in another.

**Multi-agent distinction:** Single-framework deployments enforce a uniform identity model with well-understood trust semantics throughout; multi-framework agent ensembles create N(N-1) pairwise identity translation interfaces where each interface is a potential impersonation surface — the more frameworks integrated, the greater the combinatorial attack surface, and no individual framework's security model was designed to defend against identity spoofing that originates in a different framework's semantic space.
