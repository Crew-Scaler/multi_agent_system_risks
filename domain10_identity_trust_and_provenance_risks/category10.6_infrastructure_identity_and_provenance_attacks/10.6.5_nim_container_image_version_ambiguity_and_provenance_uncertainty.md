# 10.6.5 NIM Container Image Version Ambiguity and Provenance Uncertainty [NoFW]

NIM image references relying on floating tags (e.g., "latest") become non-deterministic when attackers compromise image registries and replace the tag with backdoored versions. All agents auto-pulling the floating tag transparently deploy compromised versions. Unlike singular deployments with pinned versions, multi-agent deployments using floating tags create provenance ambiguity enabling scale compromise through registry manipulation.

The mutable nature of floating container image tags creates a provenance trust assumption: when an agent's pod spec references `nvcr.io/nim/meta/llama3-8b-instruct:latest`, it implicitly trusts that the registry will always resolve that tag to the same, verified image. An attacker who gains write access to the registry—through a compromised CI/CD pipeline credential or a registry API vulnerability—can atomically replace the tag to point to a backdoored image, and the next time any agent pod restarts or a new replica is launched, it pulls the compromised version without any notification to operators. For example, in a fleet of 50 inference agents with a rolling restart schedule, the entire fleet cycles through the poisoned image within hours, replacing legitimate model weights with backdoored versions that exfiltrate conversation data or manipulate outputs.

Standard defenses such as image pull secrets and registry access controls are insufficient because they restrict who can push to the registry, not whether the tag content has changed between pulls, and floating tags by design are expected to be updated.

**Multi-agent distinction:** A single-agent deployment referencing a pinned digest (e.g., `@sha256:abc...`) is immune to tag mutation; multi-agent deployments that use floating tags for operational convenience across dozens of replicas convert every pod restart into an unauthenticated provenance check, meaning registry compromise propagates to the entire fleet through routine operations.
