# 10.6.16 Inter-Service Communication Authentication Bypass via TLS Downgrade [NoFW]

Microservices authenticate through mTLS certificates, but attackers exploiting container orchestration misconfiguration can force service-to-service communication to downgrade to HTTP, removing authentication and enabling man-in-the-middle attacks between agents. The identity verification layer is eliminated for all inter-agent communication traversing the downgraded path.

For example, if an Istio service mesh is configured with `PeerAuthentication` in `PERMISSIVE` mode (which accepts both mTLS and plaintext for migration purposes), an attacker can inject a pod that connects to agent services over HTTP rather than mTLS, bypassing certificate-based identity verification entirely—the receiving agent processes requests from the attacker without validating any client identity because the permissive policy allows plaintext connections.

Standard defenses such as enabling mTLS at the mesh level are insufficient because operational pressures—gradual migration from plain HTTP, debugging convenience, and compatibility with legacy services—routinely result in PERMISSIVE mode being left enabled long-term, and the downgrade path remains open as long as any service accepts non-mTLS connections.

**Multi-agent distinction:** A single mTLS-enabled agent-to-agent channel requires compromising that specific channel; in a service mesh where PERMISSIVE mode is mesh-wide, all inter-agent communication paths simultaneously accept plaintext connections, meaning an attacker inside the mesh can communicate with any agent without presenting credentials, bypassing authentication for the entire agent fleet through a single configuration oversight.
