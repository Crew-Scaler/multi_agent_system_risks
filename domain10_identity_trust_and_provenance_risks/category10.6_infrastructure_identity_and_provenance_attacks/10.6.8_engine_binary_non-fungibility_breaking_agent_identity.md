# 10.6.8 Engine Binary Non-Fungibility Breaking Agent Identity [NoFW]

TensorRT engines compiled for specific GPUs are non-fungible—two engines for the same model but different GPU architectures produce different results. An attacker migrating an agent to different hardware changes its engine, effectively changing its identity without changing its agent ID. Multi-agent systems where agent identity is abstracted from hardware variants create identity spoofing through hardware migration.

For example, an attacker with access to cluster node scheduling can evict an agent pod from an A100-optimized node and allow it to reschedule on an A10G node, triggering recompilation of the TensorRT engine with subtly different numerical behavior, while the agent's ID, service account, and API surface remain unchanged—causing trusted orchestrating agents to continue delegating sensitive tasks to what is effectively a different computational identity.

Standard defenses such as cryptographic agent IDs and mTLS certificate binding are insufficient because they authenticate the agent's software identity, not its hardware-specific computational behavior, and cannot detect that the engine producing responses has changed due to hardware migration.

**Multi-agent distinction:** A single-agent deployment with dedicated hardware has a stable hardware-identity coupling; multi-agent systems where agents are freely rescheduled across heterogeneous GPU nodes routinely change their computational identity through engine recompilation while maintaining static logical identities, creating systematic divergence between agent IDs and actual computational behavior.
