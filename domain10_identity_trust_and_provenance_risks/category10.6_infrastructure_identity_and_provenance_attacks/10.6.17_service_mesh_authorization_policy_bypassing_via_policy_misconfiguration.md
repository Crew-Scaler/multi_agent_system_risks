# 10.6.17 Service Mesh Authorization Policy Bypassing via Policy Misconfiguration [NoFW]

Kubernetes NetworkPolicy and Istio AuthorizationPolicy resources define which agents can communicate with which other agents. Misconfigured policies allow unintended agent-to-agent communication paths, enabling attackers controlling one agent to laterally move through misconfigured policies to directly inject instructions into other agents without expected authentication boundaries.

For example, an Istio AuthorizationPolicy that uses a wildcard source principal (`principals: ["*"]`) to simplify policy authoring creates an implicit allowance for any authenticated service mesh member—including compromised agents—to send requests to the protected service, allowing an attacker controlling a low-privilege data-ingestion agent to directly call the high-privilege orchestration agent's task-assignment API as if it were an authorized peer.

Standard defenses such as periodic policy audits and admission controllers are insufficient because AuthorizationPolicy complexity grows non-linearly with the number of agents, and the emergent set of allowed communication paths across dozens of overlapping policies is difficult to reason about statically, with misconfigurations often only revealed during active incident investigation rather than at policy creation time.

**Multi-agent distinction:** A single-agent deployment has a simple, easily audited set of communication permissions; multi-agent systems require policy matrices covering every agent-to-agent communication pair, and the combinatorial explosion of required policies increases the probability of misconfiguration, where any single policy error can open unintended lateral movement paths that affect multiple agents simultaneously.
