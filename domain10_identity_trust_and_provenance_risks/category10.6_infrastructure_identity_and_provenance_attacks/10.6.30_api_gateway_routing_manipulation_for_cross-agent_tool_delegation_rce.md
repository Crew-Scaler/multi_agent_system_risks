# 10.6.30 API Gateway Routing Manipulation for Cross-Agent Tool Delegation RCE [NoFW]

Federated multi-agent architectures using API gateways for service discovery require dynamic routing vulnerable to manipulation. Attackers compromising service registries redirect tool invocations to attacker endpoints, receiving full context including sensitive data and credentials when agents delegate tool execution through gateways consulting those registries. Unlike single-agent systems with hardcoded endpoints, federated systems require discovery across organizational boundaries, and agents trust registry metadata without endpoint authenticity verification. Mitigation requires cryptographic binding between capabilities and endpoints, registry mutation audit trails, and endpoint attestation.

For example, an attacker who gains write access to a Consul service registry entry for a code-execution tool service replaces the registered endpoint URL with one pointing to an attacker-controlled server; when multiple agents subsequently delegate tool execution through the API gateway — which consults Consul for endpoint resolution — all invocations carrying sensitive user data, API credentials, and intermediate reasoning context are delivered to the attacker's endpoint, which can return plausible but manipulated results while exfiltrating everything received.

Standard defenses such as API gateway authentication and TLS termination are insufficient because they validate that communication with the resolved endpoint is encrypted and authenticated — they do not verify that the registered endpoint itself is legitimate; an attacker who can modify the service registry entry controls where the authenticated, encrypted traffic flows without breaking any transport-layer security assertion that the gateway checks.

**Multi-agent distinction:** In single-agent systems with hardcoded endpoints, service registry compromise has no attack surface; in federated multi-agent architectures where agents dynamically resolve tool endpoints through shared service registries, a single registry entry manipulation redirects all agents' tool invocations for that service to the attacker simultaneously — every agent that delegates execution through the gateway becomes a victim without any per-agent compromise, scaling the exfiltration surface linearly with the number of agents using that service.
