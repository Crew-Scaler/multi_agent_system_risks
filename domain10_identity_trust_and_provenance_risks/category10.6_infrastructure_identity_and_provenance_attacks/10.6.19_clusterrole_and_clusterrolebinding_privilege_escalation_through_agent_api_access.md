# 10.6.19 ClusterRole and ClusterRoleBinding Privilege Escalation Through Agent API Access [NoFW]

Agents with Kubernetes API access via service accounts and RBAC can potentially modify other resources. Attackers compromising agents with overly-permissive RBAC can modify ClusterRoleBindings to escalate privileges for all agents, converting a single agent compromise into cluster-wide privilege escalation.

ClusterRoles and ClusterRoleBindings exploit the architectural property that Kubernetes RBAC grants are additive and cluster-scoped — a single binding can confer administrative access across every namespace and resource type simultaneously. The attack mechanism requires only that an orchestrator or management agent holds `rbac.authorization.k8s.io` write permissions (commonly granted to agents that manage their own deployments), enabling an attacker who controls that agent to create a new ClusterRoleBinding attaching the `cluster-admin` ClusterRole to an attacker-controlled service account. For example, an attacker compromising an orchestrator agent whose service account includes `clusterrolebindings/create` creates a binding granting cluster-admin to a newly registered service account, then uses that account to read every other agent's secrets, modify their environment variables to inject malicious instructions, and delete health-check sidecars to suppress detection — all in a single API server interaction.

Standard defenses such as RBAC least-privilege policies and admission webhooks are insufficient because orchestrator agents legitimately require broader API permissions to manage the agent fleet, and fine-grained RBAC configurations frequently drift during rapid multi-agent system development; additionally, privilege escalation through binding manipulation is often missed by OPA/Gatekeeper policies that focus on resource creation rather than binding modification.

**Multi-agent distinction:** In single-agent deployments, RBAC escalation affects one workload's configuration and scope; in multi-agent clusters, escalating to ClusterRoleBinding mutation grants the attacker authority over every agent's service account, secrets, and deployment configuration simultaneously, converting a single agent compromise into administrative control of the entire orchestrated fleet through one privilege escalation step.
