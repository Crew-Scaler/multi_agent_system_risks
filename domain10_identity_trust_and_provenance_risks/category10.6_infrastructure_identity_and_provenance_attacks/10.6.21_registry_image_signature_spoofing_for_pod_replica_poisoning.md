# 10.6.21 Registry Image Signature Spoofing for Pod Replica Poisoning [NoFW]

Kubernetes pulls agent container images from registries. Attackers spoofing image signatures (if not properly validated) can inject malicious images that all subsequent pod replicas pull, enabling fleet-wide compromise through a single registry-level attack affecting every agent scaled from the poisoned image.

Container image signing relies on the architectural property that admission controllers validate a cryptographic signature produced by a trusted signing key before allowing image scheduling — but this trust chain is only as strong as the security of the signing key itself and the transparency log recording known-good signatures. The attack mechanism involves exfiltrating the private signing key from CI/CD pipeline secrets or compromising the signing infrastructure, then using it to produce a valid signature for a backdoored image pushed to the registry. For example, an attacker who extracts a Cosign private key from a compromised CI system signs a backdoored inference agent image and pushes it to the organization's container registry; when Kubernetes scales out new agent replicas in response to load, every newly scheduled pod pulls the backdoored image whose signature passes the admission webhook's `cosign verify` check, causing all freshly launched agents to execute attacker-controlled code while appearing cryptographically legitimate.

Standard defenses such as Cosign signature verification admission webhooks and registry image scanning are insufficient because admission controllers verify only that a signature exists and chains to a trusted key — they cannot detect key compromise, and image scanners inspect the image content rather than the signing key's provenance; once the signing key is stolen, the attacker's malicious images are cryptographically indistinguishable from legitimate ones at the admission layer.

**Multi-agent distinction:** In single-replica deployments, image compromise affects one running instance and rollback is straightforward; in scaled multi-agent fleets where auto-scaling continuously schedules new pods from the registry, a single registry-level signature compromise propagates instantaneously to every subsequent pod creation event, meaning the attacker's payload deploys simultaneously across all newly activated agents without any per-instance exploitation required.
