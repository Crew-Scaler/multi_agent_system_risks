# 10.6.26 Auto-Scaling Threshold Manipulation for Coordinated Multi-Agent Activation [NoFW]

Attackers can poison scaling metrics causing auto-scaling to trigger at specific times. When auto-scaling launches new replicas, latent malware embedded in shared state activates across all new instances simultaneously. The scaling event becomes a coordinated malware activation trigger affecting all newly provisioned agents at once.

For example, an attacker who has pre-positioned dormant malware in a shared persistent volume or container image layer manipulates CPU utilization metrics reported to the Kubernetes Horizontal Pod Autoscaler, triggering a scale-out event that launches dozens of new agent replicas simultaneously; each new pod mounts the shared volume containing the latent payload, causing coordinated malware activation across all freshly launched instances at the moment they enter the ready state.

Standard defenses such as auto-scaling metric anomaly detection and container image scanning are insufficient because metric manipulation can be subtle enough to appear as legitimate load spikes, and scanning detects known malware signatures rather than dormant payloads that only activate when triggered by the specific runtime condition of a scaling event combined with access to pre-positioned shared state.

**Multi-agent distinction:** In single-agent deployments, scaling events add capacity without creating a coordinated activation surface because each instance is independent; in multi-agent systems where new replicas share state (volumes, ConfigMaps, image layers) containing pre-positioned payloads, a single attacker-triggered scaling event simultaneously activates the malware across every newly provisioned agent, turning the infrastructure's elasticity mechanism into a synchronized malware deployment trigger.
