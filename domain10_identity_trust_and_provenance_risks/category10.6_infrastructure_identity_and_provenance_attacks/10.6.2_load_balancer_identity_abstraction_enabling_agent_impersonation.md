# 10.6.2 Load Balancer Identity Abstraction Enabling Agent Impersonation [NoFW]

Load balancers presenting a unified endpoint for multiple agent replicas enable attackers controlling one replica to intercept and respond to requests intended for other replicas.

Load balancers present a unified virtual endpoint for multiple agent replicas, abstracting individual replica identities behind a single IP or DNS name. An attacker who compromises load balancer routing state—through administrative API exploitation, BGP hijacking, or ARP poisoning—can redirect requests intended for specific replicas to arbitrary destinations, including attacker-controlled endpoints that respond as if they were legitimate agents. For example, an attacker manipulating health-check responses can force the load balancer to preferentially route high-value orchestration requests to a compromised replica while making that replica appear healthy.

Standard defenses such as TLS encryption and replica-level authentication are insufficient because they do not prevent routing manipulation at the load balancer tier, and clients authenticate to the load balancer's certificate rather than verifying individual replica identity.

**Multi-agent distinction:** In a direct agent-to-agent communication model, each agent exposes its own identity and any compromise is isolated; but when all agents communicate through a shared load balancer endpoint, manipulating that single routing layer enables an attacker to intercept and respond to requests from the entire agent fleet without needing to compromise each replica individually.
