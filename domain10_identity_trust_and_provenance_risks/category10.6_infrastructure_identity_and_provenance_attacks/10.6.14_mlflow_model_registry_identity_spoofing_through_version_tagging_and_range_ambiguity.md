# 10.6.14 MLflow Model Registry Identity Spoofing Through Version Tagging and Range Ambiguity [NoFW]

Model registries using semantic versioning create identity spoofing through version tags and range matching where attackers register malicious versions appearing as legitimate updates. Shared registries create spoofing impacts across all agents. Multi-agent systems using shared registry tags or version range queries (e.g., "^1.2.0") enable attacker versions to pass validation and reach all dependent agents simultaneously.

For example, in a multi-agent system where all classification agents load models via MLflow's `MlflowClient.get_latest_versions("intent-classifier", stages=["Production"])`, an attacker with write access to the registry can promote a backdoored model version to "Production" stage, and the next time any agent refreshes its model—during a rolling restart or scheduled model update—it loads the compromised version while MLflow logs show a valid production promotion.

Standard defenses such as MLflow access controls and model signature logging are insufficient because version promotion can be performed by anyone with registry write permissions, and model signatures validate the artifact's integrity after registration but do not prevent an authorized (but compromised) account from registering a malicious artifact as a legitimate update.

**Multi-agent distinction:** Single-agent deployments with pinned model version IDs are immune to registry promotion attacks; multi-agent systems that query by stage or version range convert registry write access into a fleet-wide model replacement capability, where one malicious promotion affects every agent that relies on the shared registry for model loading.
