# 10.6.6 Provenance Loss in Distributed Engine Caching [NoFW]

TensorRT engines cached on edge devices lack cryptographic bindings to build-time sources. An attacker with access to one edge device can replace the cached engine with a backdoored version. Multi-agent distributed caching creates independent provenance chains where compromising one cache poisons all agents at that location without any cryptographic mechanism to detect the substitution.

For example, in a fleet of robots where TensorRT engines are cached locally at each edge device to avoid rebuild latency, an attacker who briefly gains physical or remote access to one edge node can replace the cached `.engine` file with a version compiled from modified weights, and the device will continue operating without verification that the cached binary matches the authorized build artifact.

Standard defenses such as filesystem permissions and container image scanning are insufficient because they protect the build and distribution pipeline but not the cached artifact after it has been written to local storage, and no runtime integrity verification re-validates the cached engine on each load.

**Multi-agent distinction:** A centralized single-agent deployment loads its engine from a single verified source at startup; distributed multi-agent edge deployments with local caches create hundreds of independent provenance endpoints where each cache represents an independent attack surface, and compromising even one cache location can affect every agent that shares or replicates from that edge node.
