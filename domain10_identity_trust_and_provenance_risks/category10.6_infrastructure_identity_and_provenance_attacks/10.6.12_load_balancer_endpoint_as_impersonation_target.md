# 10.6.12 Load Balancer Endpoint as Impersonation Target [NoFW]

The load balancer endpoint itself becomes the identity interface for multi-agent communication. Attackers could intercept or redirect traffic to the load balancer creating man-in-the-middle scenarios that affect all agents routing through the shared endpoint. Direct agent communication doesn't require load balancer identity; load balancing creates an additional identity layer that becomes a central attack target.

When all agent-to-agent communication routes through a single load balancer address, that endpoint is the only identity verification point the cluster validates. An attacker who can redirect DNS resolution for the load balancer's FQDN—through DNS cache poisoning or BGP hijacking of the address block—can interpose a proxy that terminates TLS using a fraudulently issued certificate, forwards traffic to legitimate backends, and silently reads or modifies all inter-agent messages while both sending and receiving agents believe they are communicating through the authentic load balancer.

Standard defenses such as certificate pinning and HSTS are insufficient because load balancers in internal cluster networks frequently use short-lived, auto-renewed certificates from internal CAs, and agents do not typically pin internal load balancer certificates given the operational overhead of certificate rotation across a large agent fleet.

**Multi-agent distinction:** Point-to-point agent communication exposes only the two communicating agents to interception; routing all inter-agent traffic through a shared load balancer endpoint concentrates the impersonation attack surface into a single target whose compromise simultaneously affects every agent pair communicating through that endpoint.
