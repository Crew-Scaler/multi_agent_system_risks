# 10.6.7 Horizontal Scaling Creating Replica Identity Ambiguity [NoFW]

Replicas are identical copies making them interchangeable, and this identity ambiguity enables attackers to compromise one replica that remains indistinguishable from legitimate ones. Unique agent identities would enable anomaly detection; replica anonymity enables attackers hiding compromised instances within the fleet without triggering identity-based detection mechanisms.

For example, when an attacker injects a compromised pod into a horizontally scaled fleet of 20 perception agents, the pod registers with a valid-looking suffix name and identical labels, serves some requests normally while subtly altering others, and is never flagged because monitoring dashboards aggregate metrics across all replicas rather than tracking per-instance behavioral deviations.

Standard defenses such as container image signing and runtime security policies are insufficient because they validate the container image at pull time but cannot detect behavioral modifications made after container launch or identify which specific replica is serving anomalous outputs when all replicas share identical configurations.

**Multi-agent distinction:** A single named agent instance can be individually monitored for behavioral drift over time; horizontally scaled replica sets aggregate identity into a pool where individual accountability is lost, allowing a compromised replica to blend into fleet-level metrics and persist undetected as the fleet scales up and down.
