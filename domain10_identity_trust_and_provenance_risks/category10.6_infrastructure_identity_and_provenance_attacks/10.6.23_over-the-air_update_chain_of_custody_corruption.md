# 10.6.23 Over-the-Air Update Chain of Custody Corruption [NoFW]

Fleet Command's over-the-air update mechanism enables rolling deployments to thousands of edge locations. An attacker compromising the staging phase can poison the baseline model reference used for staged validation. Subsequent health-checking agents compare against the poisoned baseline, falsely reporting success and allowing corrupted updates to proceed through the deployment pipeline.

For example, an attacker with write access to the Fleet Command staging environment replaces the canonical baseline model checkpoint with a subtly corrupted version before the rollout's health-check phase begins; the distributed health-checking agents deployed across thousands of edge locations each compare the update against this poisoned baseline, unanimously report healthy validation, and approve full production rollout of a corrupted update to the entire fleet.

Standard defenses such as cryptographic hash verification of update packages are insufficient because they verify integrity against a reference hash stored in the same system the attacker has already compromised; if the baseline itself is poisoned and the reference hash is updated to match, downstream validators have no independent ground truth against which to detect the corruption.

**Multi-agent distinction:** In single-agent deployments, an OTA update failure affects one device and rollback is isolated; in Fleet Command's multi-agent architecture, health-checking agents are themselves part of the system being validated and draw their comparison baseline from shared infrastructure — corrupting the baseline simultaneously invalidates the validation logic for every health-checking agent in the fleet, enabling a single staging-phase compromise to authorize corrupted updates across thousands of edge locations.
