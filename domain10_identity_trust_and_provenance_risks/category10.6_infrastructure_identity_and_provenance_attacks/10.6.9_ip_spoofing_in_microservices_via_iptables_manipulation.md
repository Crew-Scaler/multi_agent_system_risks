# 10.6.9 IP Spoofing in Microservices via iptables Manipulation [NoFW]

Agents with certain capabilities can manipulate iptables to spoof source IP addresses in inter-service communication, forging communication appearing to originate from trusted agents. Multi-agent systems enable attackers to spoof any agent identity in communication, enabling targeted lateral movement through forged trustworthy communication that multi-agent trust models accept as legitimate.

For example, an attacker who compromises a lower-privilege data-processing agent can add iptables SNAT rules that cause the agent's outbound traffic to appear to originate from the IP address of a high-privilege orchestrating agent, bypassing IP-based allowlists in downstream services and injecting malicious tool calls that those services attribute to the trusted orchestrator.

Standard defenses such as Kubernetes NetworkPolicy rules that restrict which pods can communicate are insufficient because iptables manipulation occurs at the host network namespace level, potentially below the layer where pod-level network policies are enforced, particularly in clusters without strict node-level network isolation.

**Multi-agent distinction:** In a single-agent deployment, IP-based identity is straightforwardly tied to one endpoint; in multi-agent microservice architectures where dozens of agents communicate through shared network fabric, iptables spoofing can impersonate any agent in the fleet by forging source IPs, enabling attacker-controlled agents to selectively impersonate high-trust peers and inject malicious instructions into any inter-agent channel.
