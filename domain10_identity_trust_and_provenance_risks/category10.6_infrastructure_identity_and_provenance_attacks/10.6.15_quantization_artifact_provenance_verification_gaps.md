# 10.6.15 Quantization Artifact Provenance Verification Gaps [NoFW]

Quantization artifacts (calibration data, quantized weights) stored in registries may lack strong provenance verification. Attackers inject artifacts claiming legitimate provenance, causing agents to load compromised quantizations. Shared quantization artifact repositories enable one compromised artifact to affect all agents querying the registry without cryptographic attestation of artifact origin.

For example, an attacker who gains write access to an S3 bucket hosting INT8 calibration datasets for NVIDIA's quantization workflow can replace a calibration dataset with one crafted to shift the quantized model's decision boundaries for specific input patterns, and since calibration data is typically stored without cryptographic hashes tied to the model training lineage, agents downloading and using this dataset produce a quantized model that behaves normally on most inputs while producing attacker-controlled outputs on targeted ones.

Standard defenses such as bucket versioning and access logging are insufficient because they record that an artifact was accessed or modified but do not provide cryptographic binding from the artifact back to the authorized training pipeline, leaving agents unable to verify whether the artifact they download is the one their training process intended to produce.

**Multi-agent distinction:** A single-agent deployment using locally verified quantization artifacts has an auditable one-to-one relationship between artifact and agent; multi-agent systems sharing a quantization artifact repository create a broadcast attack surface where one compromised calibration dataset or quantized weight file is consumed by all agents pulling from that repository, simultaneously degrading the security posture of the entire fleet.
