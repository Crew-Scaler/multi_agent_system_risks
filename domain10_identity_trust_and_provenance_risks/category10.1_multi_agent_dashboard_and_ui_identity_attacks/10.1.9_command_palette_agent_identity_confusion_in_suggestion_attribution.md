# 10.1.9 Command Palette Agent Identity Confusion in Suggestion Attribution [NoFW]

Command palettes displaying suggestions without clearly indicating which agent produced them create attribution confusion. In multi-agent systems, users develop differentiated trust based on track records. An attacker compromising the low-trust productivity agent can inject dangerous commands appearing from high-trust security agents, exploiting this multi-agent-specific attribution gap.

For example, an attacker compromises the low-trust productivity agent and injects a suggestion that the command palette displays as "Recommended by Security Agent: flush-audit-logs"; a user who has differentiated trust in the Security Agent executes the command without recognizing that the security attribution is unverified and originates from an agent they would never have trusted with that recommendation.

Standard defenses such as command allowlists and execution rate limiting are insufficient because they constrain which commands can be executed but do not verify which agent produced a displayed suggestion, leaving the attribution label as an unauthenticated trust signal that attackers can freely manipulate.

**Multi-agent distinction:** Single-agent command palettes attribute all suggestions to one model, giving no basis for differential trust exploitation; multi-agent systems with specialized high-trust agents create user trust asymmetries that attackers exploit by spoofing attribution to whichever agent carries the highest trust for the target action, amplifying the impact of a low-privilege agent compromise.
