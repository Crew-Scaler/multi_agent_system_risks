# 10.1.7 Evaluation Dashboard Attribution Spoofing [NoFW]

Evaluation dashboards displaying results from multiple agents could attribute malicious outputs to trusted agents when attribution relies on self-reported metadata. Attackers have compromised agents emit results alongside forged metadata fields (agent_id, agent_role) that the dashboard renders as the identity of a trusted peer, causing downstream systems to act on falsely attributed evaluation data.

For example, a compromised evaluation agent emits a passing metric report alongside forged `agent_id="trusted_safety_evaluator"` metadata; the dashboard renders the result under the trusted evaluator's label, causing an automated deployment gate and human reviewers to approve a release that the legitimate safety evaluator would have blocked—an outcome undetectable without cryptographic attestation binding the displayed result to its actual source.

Standard defenses such as result validation schemas and metric range checks are insufficient because they verify the format and value of evaluation outputs but not the authenticity of the agent identity claimed in accompanying metadata, allowing a well-crafted fake to pass every automated filter.

**Multi-agent distinction:** Single-agent evaluation has a trivially verifiable source because there is only one evaluating agent; multi-agent evaluation systems with multiple specialized evaluators create differentiated attribution that operators and downstream systems rely upon for trust calibration, making identity spoofing more valuable to attackers and harder to detect without per-agent cryptographic signatures on every evaluation artifact.
