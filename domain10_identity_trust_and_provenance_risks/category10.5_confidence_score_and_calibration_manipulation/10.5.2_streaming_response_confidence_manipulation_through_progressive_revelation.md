# 10.5.2 Streaming Response Confidence Manipulation Through Progressive Revelation [NoFW]

Initial streaming tokens include high-confidence signals; later tokens include caveats. Agents acting on early tokens make decisions based on false confidence.

In a multi-agent pipeline, a generator agent streams a response whose opening tokens assert high certainty, prompting a downstream orchestrator to immediately route the task result to an execution agent rather than a review agent; the caveats that arrive in later tokens are never evaluated because the routing decision has already been committed. For example, a financial analysis agent that streams "With 98% confidence, execute the trade—" before appending "—though data freshness is uncertain" causes an execution agent to act before the hedge is delivered.

Standard defenses such as consuming the complete response before routing are insufficient because many streaming architectures are designed for low-latency action-taking, and retrofitting full-response buffering eliminates the performance advantage that motivates the streaming design.

**Multi-agent distinction:** Confidence scores propagate as inter-agent trust signals; in a streaming multi-agent pipeline a single agent's progressive confidence revelation exploits the architectural assumption that early tokens are sufficient to trigger downstream routing, and each committed routing decision narrows the options available to later pipeline stages in ways that compound the impact of the initial false confidence signal.
