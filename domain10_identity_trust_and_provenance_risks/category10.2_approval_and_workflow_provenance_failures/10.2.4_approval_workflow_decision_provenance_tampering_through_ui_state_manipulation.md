# 10.2.4 Approval Workflow Decision Provenance Tampering Through UI State Manipulation [NoFW]

Approval workflow interfaces storing decision provenance in client-side state or weakly authenticated logs enable attackers to tamper with records obscuring malicious approvals. Multi-agent workflows involve complex state including which agents provided analysis, what confidence scores were displayed, and what humans decided—if stored without cryptographic signatures, attackers can modify records shifting accountability across the multi-agent chain.

For example, an attacker modifies client-side state records after an approval workflow completes, replacing the logged confidence scores with fabricated values that make the approval appear to have been driven by unanimous high-confidence analysis rather than a single compromised agent whose inflated score pushed the decision over the approval threshold.

Standard defenses such as access logging and change management systems are insufficient because they record the existence of an approval event but do not cryptographically seal the provenance data—which agents contributed what analysis, what scores were displayed at decision time—against retrospective modification by an attacker with access to the client-side state store.

**Multi-agent distinction:** Single-agent approval records have a simple structure with clear ownership; multi-agent provenance graphs span multiple agents and approval stages, making retrospective tampering both more impactful—it can shift accountability across multiple agents—and harder to detect without tamper-evident logging that covers every node and edge in the decision graph.
