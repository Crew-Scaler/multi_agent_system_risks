# 10.2.2 Approval Workflow Confidence Aggregation Attacks Through Selective Agent Compromise [NoFW]

Compromising the agents with highest confidence weight in a multi-agent approval causes their artificially inflated confidence to dominate the aggregated decision.

The architectural property being exploited is weighted confidence aggregation across specialized agents, where each agent's score is multiplied by an assigned weight before producing a final approval signal. In a system where a security agent is weighted 40%, a policy agent 30%, and a business agent 30%, an attacker injects adversarial inputs—manipulated document content, poisoned tool outputs, or crafted retrieval results—into the security agent's analysis phase, causing it to report inflated confidence. The aggregated UI displays "Confidence: 92% - Recommend Approve" without revealing that the compromised security agent reported 98% (weighted 40%) while legitimate agents expressed considerably lower confidence.

Standard defenses such as confidence thresholds and anomaly detection are insufficient because they evaluate the aggregated signal rather than per-agent contributions, making it impossible to identify that a single high-weight agent's manipulated output is responsible for driving the result past the approval threshold.

**Multi-agent distinction:** Single-agent confidence is directly attributable and auditable; weighted multi-agent aggregation creates an attack leverage point where compromising one high-weight agent yields disproportionate influence over the final decision, exploiting the opacity of the aggregation function to hide that a single compromised source overrode the skepticism of multiple legitimate agents.
