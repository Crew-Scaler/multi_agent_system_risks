# 10.2.5 Approval Workflow Multi-Stage Provenance Gaps in Sequential Agent Reviews [NoFW]

Approval workflow UIs displaying final recommendations from multi-stage agent pipelines without cryptographic provenance for intermediate stages create accountability gaps. A recommendation resulting from Agent A passing to Agent B passing to Agent C may only show Agent C's output, allowing early-stage compromise to poison analysis while remaining forensically invisible.

For example, an attacker compromises Agent A in a three-stage pipeline; Agent A inflates the risk score favorably and passes a sanitized summary to Agent B, which performs compliance checking only against Agent A's summary rather than the original data; Agent C's final recommendation reflects the manipulated early analysis, but the UI displays only "AI Recommendation: Approve" without exposing Agent A's contribution or enabling verification of intermediate integrity.

Standard defenses such as threshold gates on final recommendations are insufficient because they evaluate the end-state output without verifying that intermediate stages performed legitimate analysis, allowing early-stage manipulation to propagate through and survive all downstream checks.

**Multi-agent distinction:** Single-agent pipelines have only one stage to audit; multi-stage multi-agent pipelines create N-1 intermediate steps each of which is a potential injection point, and the UI's abstraction of multi-stage analysis into a single final recommendation systematically hides the intermediate provenance where compromise occurred—structurally preventing forensic reconstruction without explicit per-stage cryptographic provenance.
