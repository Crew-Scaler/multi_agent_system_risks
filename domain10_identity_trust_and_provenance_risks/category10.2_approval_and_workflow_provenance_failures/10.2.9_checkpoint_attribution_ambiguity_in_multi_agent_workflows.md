# 10.2.9 Checkpoint Attribution Ambiguity in Multi-Agent Workflows [NoFW]

LangGraph checkpoints maintain execution state but may lack clear attribution about which agent made specific state changes. In multi-agent workflows, determining which agent was responsible for corrupted state is difficult when checkpoints aggregate multiple agents' mutations without per-agent field attribution, creating forensic blind spots exploitable by attackers.

For example, an attacker's agent injects a malicious configuration value into a shared workflow state; LangGraph's checkpoint captures the mutated state without recording which agent performed the mutation; post-incident investigators can reconstruct the state at each checkpoint but cannot determine which of the five agents in the workflow introduced the injected value, leaving the forensic record with confirmed state corruption but no causal attribution.

Standard defenses such as audit logging and checkpoint storage are insufficient because they preserve state snapshots without tagging individual field mutations to the agent that made them, leaving investigators with a record of what changed but no means to establish which agent was responsible.

**Multi-agent distinction:** Single-agent checkpoints capture mutations from one source with implicit attribution requiring no additional tracking; multi-agent checkpoints aggregate mutations from N agents into a shared state graph, requiring explicit per-field attribution tagging to reconstruct which agent caused which change—an engineering requirement absent from most checkpoint implementations and a gap that grows more exploitable with each additional agent in the workflow.
