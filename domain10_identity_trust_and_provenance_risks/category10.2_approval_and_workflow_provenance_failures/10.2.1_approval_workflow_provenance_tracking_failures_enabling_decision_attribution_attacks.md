# 10.2.1 Approval Workflow Provenance Tracking Failures Enabling Decision Attribution Attacks [NoFW]

When multiple agents contribute to a decision without cryptographic provenance binding, attackers can tamper with the record of which agent made which contribution.

The architectural property being exploited is the sequential chain structure of multi-agent approval workflows, in which each stage's output becomes the next stage's input and later stages assume earlier stages have been performed faithfully. An attacker controlling Agent B in a Risk-Compliance-Approval chain causes it to output subtly manipulated analysis—inflated confidence scores, suppressed risk flags, or fabricated prior-agent endorsements—that Agent C and human reviewers treat as independently validated. Each participant assumes previous participants performed due diligence, so the corrupted analysis propagates to approval without re-verification of its integrity.

Standard defenses such as role-based approval gates and audit logging are insufficient because they verify that each stage was performed by an authorized agent but not that the analysis content was generated with integrity rather than manipulated before being passed downstream.

**Multi-agent distinction:** Single-agent approval requires attacking only one decision point; sequential multi-agent chains offer N independent injection points, each of which can produce cascading effects through the remaining stages because downstream agents treat upstream outputs as trusted analysis rather than untrusted input requiring independent verification.
