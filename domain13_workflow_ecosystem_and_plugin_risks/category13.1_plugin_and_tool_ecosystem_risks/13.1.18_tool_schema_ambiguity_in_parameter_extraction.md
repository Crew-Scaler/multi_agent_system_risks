# 13.1.18 Tool Schema Ambiguity in Parameter Extraction [NoFW]

Tool schemas with ambiguous parameter specifications (overlapping enum values, underspecified type constraints, ambiguous field names) are interpreted inconsistently across different agent implementations and LLM models. Attackers craft inputs exploiting schema interpretation differences between agents — parameters interpreted as safe by one agent's parser are interpreted as malicious by another agent's execution layer. Multi-agent systems using heterogeneous LLM backends create cross-agent semantic gaps that enable adversarial inputs to pass validation in one agent while producing harmful behavior when re-processed by a different agent.

For example, an attacker submits a date parameter using a day-of-week string ("Monday") that Agent A's GPT-4-backed parser accepts as a valid "time" field and converts to the nearest upcoming Monday date, while Agent B's locally-hosted model interprets the same schema slot as requiring an ISO 8601 timestamp and produces an error that exposes internal system state, revealing that the two agents have incompatible schema interpretations the attacker can exploit to steer behavior selectively.

Standard defenses such as schema validation at API ingress are insufficient because schema ambiguity is inherent in natural-language type descriptions, and structural validators that accept well-formed strings cannot detect that two different agent backends will interpret the same well-formed string as having different semantic meanings.

**Multi-agent distinction:** In a multi-agent system using heterogeneous LLM backends, adversarial inputs can be crafted to be accepted and acted upon by one agent's interpretation while simultaneously producing exploitable failure behaviors in another agent's interpretation, creating cross-agent attack vectors that are invisible when each agent's schema handling is tested in isolation.
