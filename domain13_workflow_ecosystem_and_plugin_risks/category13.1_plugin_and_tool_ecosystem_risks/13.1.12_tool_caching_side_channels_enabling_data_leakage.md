# 13.1.12 Tool Caching Side Channels Enabling Data Leakage [NoFW]

Tool response caching systems designed for efficiency create information leakage channels when cache hit/miss timing differences reveal whether another agent has previously queried a specific tool with specific parameters. Attackers exploit timing side channels to infer what queries other agents have issued, reconstructing sensitive operational information from cache interaction patterns. In multi-agent systems sharing cache infrastructure, one agent can probe cache timing to map another agent's recent tool usage history without directly accessing privileged information.

For example, an attacker-controlled agent systematically probes a shared tool cache with candidate parameters for a sensitive data retrieval tool; cache hits returning in under 5ms versus cache misses returning in 150ms reveal which customer IDs other agents have recently queried, allowing the attacker to infer the population of accounts currently under investigation by a fraud-detection agent running in the same fleet.

Standard defenses such as per-agent cache namespacing are insufficient because timing side channels leak information even when cache data itself is namespace-isolated: the presence or absence of a cached entry is revealed by response latency regardless of whether the attacker can read the cached value itself.

**Multi-agent distinction:** In a multi-agent system with shared cache infrastructure, an attacker operating as one agent can probe the usage history of all other agents through timing channels, reconstructing cross-agent operational patterns that no single agent was intended to expose, whereas in a single-agent deployment no shared cache surface exists for cross-agent timing inference.
