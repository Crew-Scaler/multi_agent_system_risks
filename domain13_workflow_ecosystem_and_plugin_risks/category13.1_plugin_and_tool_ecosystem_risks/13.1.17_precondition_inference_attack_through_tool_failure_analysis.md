# 13.1.17 Precondition Inference Attack Through Tool Failure Analysis [NoFW]

Tools with hidden preconditions (authentication state, prior action requirements, resource availability) reveal those preconditions through failure messages when preconditions are unmet. Attackers systematically invoke tools under various states, analyzing failure responses to reverse-engineer precondition requirements that are not documented in tool schemas. Once preconditions are mapped, attackers craft sequences satisfying all preconditions for high-privilege tool invocations that nominal workflows do not reach. In multi-agent systems, coordinated precondition mapping across multiple agents accelerates reverse engineering of complex multi-step precondition chains.

For example, an attacker probing a payment processing tool systematically varies authentication tokens, session states, and preceding API calls, observing error messages such as "account_lock_required before transfer," "two-factor not verified," and "prior_read_required" to reconstruct the exact precondition sequence that unlocks high-value wire transfer invocations that the documented user workflow never reaches under normal operation.

Standard defenses such as vague error messages are insufficient because agents themselves rely on informative failure responses to handle operational exceptions gracefully, and any error message specific enough to guide legitimate error recovery is specific enough to serve as a precondition oracle for an attacker with agent-level access to the system.

**Multi-agent distinction:** In a multi-agent system, different agents can probe different tool precondition dimensions simultaneously, assembling a complete precondition map through cross-agent coordination far faster than a single agent probing sequentially, and the distributed probing pattern is less likely to trigger rate-limiting or anomaly detection designed for single-agent interaction patterns.
