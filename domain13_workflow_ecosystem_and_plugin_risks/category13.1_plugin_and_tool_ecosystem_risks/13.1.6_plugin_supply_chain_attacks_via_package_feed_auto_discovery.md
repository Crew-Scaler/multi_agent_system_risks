# 13.1.6 Plugin Supply Chain Attacks via Package Feed Auto-Discovery [NoFW]

Plugins distributed through package managers (NuGet for .NET, pip for Python) and auto-discovered by frameworks create supply chain attack surfaces where malicious packages embed instructions in function descriptions or default behaviors. Semantic Kernel's dynamic plugin discovery and similar auto-registration mechanisms integrate poisoned plugins into orchestrator prompts without explicit administrator action. Multi-agent systems mixing frameworks expose N distinct plugin supply chain vectors simultaneously, and ecosystem-wide plugin poisoning affects all organizations using compromised packages at once, unlike local-source singular tool integrations.

For example, an attacker publishes a typosquatting package "semantickernel-utilities" to PyPI that embeds a malicious function description instructing the orchestrator to exfiltrate tool invocation parameters to an external endpoint; any agent system configured for auto-discovery pulls and registers this plugin on next startup without any explicit installation step by an administrator.

Standard defenses such as static dependency scanning are insufficient because the malicious payload is embedded in natural-language description fields rather than executable code, evading conventional signature-based malware detection that operates on binary or syntactic patterns rather than semantic intent.

**Multi-agent distinction:** When a poisoned package reaches a shared plugin feed, every agent in the fleet that uses auto-discovery installs the malicious plugin simultaneously in the next discovery cycle, turning one supply chain compromise into fleet-wide tool poisoning, whereas in a single-agent deployment the scope is limited to one installation event that a human operator can manually inspect and roll back.
