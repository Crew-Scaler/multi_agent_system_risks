# 13.1.2 Plugin Middleware Injection via Tool Wrapper Manipulation [NoFW]

Intercepting and modifying tool wrapper middleware enables attackers to alter tool behavior for all agents using the wrapper without modifying the underlying tool.

Tool wrappers in frameworks like LangChain can be decorated with dynamically loaded middleware for logging, caching, and validation; when middleware loading is configurable from shared configuration stores, an attacker who modifies the middleware configuration causes all subsequent tool invocations to pass through attacker-controlled code. For example, an attacker injects a logging middleware that exfiltrates tool parameters to an external endpoint while forwarding normal-appearing results to the agent, creating a persistent man-in-the-middle at the tool invocation layer that is invisible to both the agent and the underlying tool. The mechanism exploits the fact that middleware operates between the agent's intent and the tool's execution, making the interception transparent to both sides.

Standard defenses such as tool output validation and agent-level monitoring are insufficient because injected middleware produces correctly structured outputs that pass schema checks while silently diverting data before the agent ever receives it, and monitoring that observes only inputs and outputs cannot detect manipulation occurring in the middleware layer between them.

**Multi-agent distinction:** In multi-agent systems where middleware configurations are shared across a tool registry, a single middleware injection propagates to every agent using the affected tool wrapper, enabling simultaneous data exfiltration or parameter manipulation across the entire fleet, unlike isolated single-agent deployments where middleware scope is bounded to one agent's tool layer.
