# 13.1.14 Circuit Breaker Enabling Tool Replacement Attacks [NoFW]

Circuit breakers route tool calls to fallback implementations when primary tools fail. Attackers trigger primary tool failures to force circuit breaker activation, causing the system to route subsequent requests to attacker-controlled or weaker fallback tools. The attack exploits trust assumptions embedded in circuit breaker configurations — fallback tools receive requests without the same validation applied to primary tools, enabling tool substitution through legitimate circuit breaker infrastructure. In multi-agent systems with shared circuit breaker state, one agent triggering a circuit break affects all agents' tool routing simultaneously.

For example, an attacker floods a primary security-validation tool with malformed requests until the circuit breaker opens and routes all subsequent calls to a fallback tool that applies only basic schema validation, allowing subsequent malicious requests from any agent in the fleet to bypass security checks for the entire duration of the circuit breaker's open state.

Standard defenses such as monitoring fallback tool activation are insufficient because circuit breaker trips due to overload are operationally expected events, making attacker-induced trips indistinguishable from legitimate failure events in the absence of anomaly detection that correlates adversarial traffic patterns with circuit state transitions.

**Multi-agent distinction:** In multi-agent systems where circuit breaker state is shared, one agent triggering a circuit break immediately redirects all other agents' tool calls to the fallback, turning a single-agent overload event into a fleet-wide security downgrade, whereas in a single-agent deployment circuit breaker activation is scoped to one agent's tool calls and does not affect other agents' routing.
