# 13.1.25 Method Library Authority Spoofing Through Collaborative Method Injection [NoFW]

Shared method libraries enable collaborative definition where agents contribute methods. Attackers inject methods impersonating trusted authors, creating malware inherited by all agents using the shared library. A "trusted" method actually authored by attackers propagates to production. Distributed contribution enables attacker methods achieving equal standing with legitimate methods.

For example, an attacker who gains write access to a shared HTN method library submits a "payment_authorization" method attributed to the organization's trusted principal engineer; because the library's contribution workflow validates schema correctness rather than author identity, the malicious method achieves the same routing priority as legitimate methods and begins executing attacker-controlled authorization logic for all agents that invoke the payment workflow.

Standard defenses such as code review of method definitions are insufficient because review processes that assess structural correctness and logical consistency cannot detect that a method's behavioral intent differs subtly from its stated purpose, particularly when the deviation only manifests under specific runtime states not covered by review test cases.

**Multi-agent distinction:** In a multi-agent system using a shared method library, a single injected method definition propagates to every agent that references the affected library, enabling the attacker to influence all agents' behavioral logic from one contribution event, whereas in a single-agent system methods are loaded from agent-local definitions and an attacker must compromise each agent individually.
