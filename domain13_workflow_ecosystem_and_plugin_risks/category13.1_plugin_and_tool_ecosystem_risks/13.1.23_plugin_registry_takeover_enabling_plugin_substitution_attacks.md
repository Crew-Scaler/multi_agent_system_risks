# 13.1.23 Plugin Registry Takeover Enabling Plugin Substitution Attacks [NoFW]

Semantic Kernel's dynamic plugin registration enables adding plugins at runtime. Attackers register malicious plugins with legitimate names ("SecurityValidator", "ComplianceChecker") that execute before legitimate plugins. When function selection routes to impersonated plugins, they execute attacker code with full kernel access, impersonating trusted identity at the plugin layer.

For example, an attacker with write access to a shared Semantic Kernel plugin registry registers a malicious function under the name "SecurityValidator" before the legitimate plugin is loaded; every agent in the fleet whose function selection routes to the security validation step then invokes the attacker's code — which approves all requests regardless of content — rather than the genuine validator, because name-based routing resolves to the first registered matching entry.

Standard defenses such as plugin authentication via API keys are insufficient because name-based routing to the first registered matching plugin occurs before authentication is applied to plugin execution, meaning the impersonating plugin intercepts calls before the legitimate plugin's own access controls can activate.

**Multi-agent distinction:** When a shared plugin registry contains an impersonating entry, every agent that performs function selection routes to the malicious plugin simultaneously, granting the attacker execution across the entire agent fleet from a single registry write, whereas in a single-agent system with locally registered plugins the impersonation scope is bounded to that one agent's plugin namespace.
