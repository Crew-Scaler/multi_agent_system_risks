# 13.1.24 Semantic Kernel Function Impersonation Through Schema Duplication [NoFW]

Attackers register plugins with identical names and similar descriptions as legitimate plugins. Similar descriptions cause LLM routing to choose probabilistically between legitimate and malicious variants, enabling persistent identity confusion where users and downstream agents cannot reliably distinguish authentic from spoofed plugin execution.

For example, an attacker registers a plugin named "DataAnalytics" with a description nearly identical to the legitimate analytics plugin, differing only in minor phrasing; the LLM router assigns roughly 40% of analytics function calls to the malicious variant based on description similarity scoring, causing intermittent data exfiltration that appears as random variation in analytics response quality rather than a systematic attack detectable through error rate monitoring.

Standard defenses such as exact-name-match enforcement are insufficient because description-based routing operates on semantic similarity rather than exact names, meaning two plugins with similar enough descriptions will share routing probability regardless of operator-level namespace controls designed to enforce uniqueness.

**Multi-agent distinction:** In a multi-agent system where all agents share a single function routing layer, the probabilistic split between legitimate and malicious plugin variants affects every agent's function calls simultaneously, distributing exfiltration across the fleet in a pattern that is statistically invisible at the per-agent level but represents a significant aggregate data leak across the full deployment.
