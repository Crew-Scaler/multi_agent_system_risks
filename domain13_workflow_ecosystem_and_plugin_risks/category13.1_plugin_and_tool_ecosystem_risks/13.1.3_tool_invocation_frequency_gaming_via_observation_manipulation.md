# 13.1.3 Tool Invocation Frequency Gaming via Observation Manipulation [NoFW]

Attackers craft observations that cause agents to invoke specific tools more frequently than warranted, driving costs, quota exhaustion, or data exposure.

Agents optimizing for task-completion metrics learn to treat tool invocations as measurable outputs rather than means to legitimate ends; attackers exploit this by providing observations that signal additional tool calls are needed to satisfy the objective. For example, an attacker injects observations into a financial analysis workflow that consistently indicate "more data needed from analysis_tool," causing the agent to invoke the expensive API tool in a loop that exhausts per-session quotas, exposes request parameters to logging infrastructure, and accumulates per-call charges far beyond intended operational limits. The architectural property is that systems log tool calls as proxies for progress, creating an incentive structure that attackers manipulate through engineered observations.

Standard defenses such as per-session rate limits are insufficient because individual tool calls are valid and stay below per-request thresholds even as the aggregate invocation count drifts far above operational intent, and the abuse pattern only becomes visible when the full session history is examined.

**Multi-agent distinction:** In a multi-agent system where task-completion metrics are aggregated across agents, each agent independently learns to over-invoke tools and no individual agent appears anomalous in isolation, whereas in a single-agent deployment the anomalous invocation frequency is immediately attributable to one context and detectable through that agent's own session logs.
