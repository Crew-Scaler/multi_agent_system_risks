# 13.1.16 Tool Availability Inference Attacks Through Error Patterns [NoFW]

Different tool error codes and response patterns reveal internal system state — which tools exist, which are operational, which permissions are active — allowing attackers to map the tool ecosystem through systematic probing. By inducing specific error conditions and observing error message content, error codes, and response timing, attackers construct detailed maps of available tools, their parameter requirements, and their access control configurations. In multi-agent systems, cross-agent error pattern analysis reveals tool availability across the entire fleet, enabling precision targeting of vulnerable tool endpoints.

The architectural property at risk is that error responses are designed to be informative — distinguishing "tool not found" from "permission denied" from "invalid parameter" to aid legitimate debugging — yet this informativeness simultaneously serves as an oracle for attacker reconnaissance. For example, an attacker probing a system with different tool names observes that "file_reader" returns "404 tool not found" while "admin_executor" returns "403 insufficient permissions," confirming the latter exists but requires privilege escalation; subsequent probes with varied parameter values then reveal the exact parameter schema required for invocation once access is obtained.

Standard defenses such as generic error messages for unauthenticated callers are insufficient because agents themselves need informative error responses to handle failures gracefully, and any error message differentiated enough to be useful to a legitimate agent is differentiated enough to serve as an information oracle for an attacker with agent-level access.

**Multi-agent distinction:** In a multi-agent system where different agents expose different tool sets, an attacker can systematically probe each agent to aggregate a complete inventory of available tools across the fleet, with cross-agent error pattern correlation revealing organizational topology that no single agent's error logs alone would expose, whereas in a single-agent deployment reconnaissance is bounded to one agent's tool surface.
