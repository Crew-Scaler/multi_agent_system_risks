# 13.1.11 Tool Permission Scope Creep Through API Integration [NoFW]

API integration layers between agents and external tools often resolve permission scopes at request time by combining agent permissions with tool-declared capabilities. Attackers craft tool integration configurations declaring overly broad OAuth scopes or capability declarations that exceed legitimate operational requirements, causing integrated tools to accumulate permissions beyond intended boundaries with each API call. In multi-agent systems where all agents use shared integration configurations, scope creep in one tool integration propagates excessive permissions across the entire agent fleet.

For example, an attacker who modifies a shared OAuth integration configuration changes a tool's scope declaration from "read:user_data" to "admin:all_data," causing every agent using that integration to obtain and exercise administrative permissions on subsequent API calls even though no individual agent explicitly requested elevated access.

Standard defenses such as OAuth scope review at integration setup time are insufficient because scope declarations can be modified post-integration, and agents re-read integration configurations dynamically without re-triggering the scope approval workflow that would detect the change.

**Multi-agent distinction:** In a multi-agent system using shared integration configurations, a single scope escalation in one tool's configuration simultaneously grants every agent in the fleet the expanded permissions, propagating privilege creep across the entire deployment at once, whereas in a single-agent system permission scope changes affect only that agent's API calls and can be audited within one integration's log.
