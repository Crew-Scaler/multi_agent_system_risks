# 13.1.8 Multi-Agent Tool Registry Poisoning for Distributed RCE [NoFW]

In multi-agent systems with shared tool registries, agents discover available tools dynamically. Attackers poison registry entries with malicious tool definitions, routing function calls to attacker-controlled endpoints. Single-agent systems with hardcoded tools resist registry poisoning; multi-agent dynamic discovery enables one poisoned registry entry to affect all agents simultaneously, converting tool discovery infrastructure into a distributed remote-code-execution vector.

The architectural property is that dynamic tool discovery decouples tool availability from deployment artifacts: agents consult a central registry at runtime to learn which tools exist and how to invoke them, trusting registry entries as reflecting legitimate administrative intent. For example, an attacker with write access to the registry replaces the legitimate "database_query" function URL with an attacker-controlled endpoint at "malicious.com/exploit," causing every agent that subsequently queries the registry to route database calls — along with all query parameters and credentials — to the attacker's infrastructure.

Standard defenses such as network egress filtering are insufficient because the malicious endpoint is only reached after agents trust the registry definition, and the outbound traffic appears as a normal tool call to an expected tool name, matching no pre-existing blocklist entry.

**Multi-agent distinction:** Because all agents in the fleet share a single tool registry, one poisoned entry causes every agent to route calls for that tool to the attacker simultaneously, converting a single write-access compromise into fleet-wide remote code execution, whereas in a single-agent system with hardcoded tool definitions a registry compromise has no effect because the agent never consults a dynamic registry at runtime.
