# 13.1.19 Tool Parameter Mutation Through Transitive Tool Calls [NoFW]

In tool pipelines where one tool's output parameters are passed as inputs to the next tool, parameter values undergo implicit transformation through serialization and deserialization at each boundary. Accumulated floating-point rounding, string encoding differences, and type coercion errors across multiple transitive calls mutate parameter values progressively away from intended values. Attackers crafting inputs positioned at mutation boundaries exploit known transformation behaviors to steer parameter values toward adversarial targets through the accumulated drift of legitimate processing steps.

The architectural property is that each tool trusts the parameters it receives as already validated by upstream processing, without re-verifying whether accumulated transformations have changed the semantic meaning of a value. For example, an attacker crafts an initial string parameter that encodes a malicious SQL fragment using a specific Unicode normalization form; as the string passes through three tool boundaries that each perform Unicode normalization under different locale settings, the encoded fragment resolves into an executable SQL string at the final tool — an outcome that validates correctly at every intermediate boundary because each tool sees a conformant string.

Standard defenses such as end-to-end parameter signing are insufficient because legitimate processing steps genuinely transform parameter values for compatibility purposes, making it difficult to distinguish intentional transformation from attacker-induced mutation without full semantic tracking of what each transformation is permitted to change.

**Multi-agent distinction:** In multi-agent pipelines where each agent independently handles one tool boundary without visibility into the full transformation chain, the cumulative mutation effect across all boundaries is never evaluated holistically, allowing an attacker to engineer a parameter that reaches its adversarial target value only after passing through multiple agents' individually benign processing steps, a pattern invisible to any single agent's local validation.
