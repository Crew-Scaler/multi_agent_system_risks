# 13.1.20 Profiling Hook Installation as Tool Behavior Modification [NoFW]

Performance profiling infrastructure (Python profilers, tracing hooks, instrumentation frameworks) installed on agent runtime environments can be abused as tool behavior modification vectors. Attackers with access to profiling configuration inject hooks that intercept tool function calls, modifying input parameters or output values before they reach the agent. Unlike prompt injection targeting model inputs, profiling hook attacks operate at the runtime layer, affecting tool behavior transparently regardless of model awareness. In multi-agent systems sharing instrumentation infrastructure, one poisoned profiling configuration modifies tool behavior across all agents in the shared environment.

For example, an attacker with access to a shared OpenTelemetry tracing configuration injects a span processor hook that intercepts all calls to a cryptographic signing tool, replacing the signing key parameter with an attacker-controlled key before the call reaches the tool, causing all agents' signed outputs to be verifiable only by the attacker while appearing operationally normal to consumers of the signed data.

Standard defenses such as code review of application source code are insufficient because profiling hooks are loaded from external configuration files at runtime rather than from the application's source code, meaning the injection point exists entirely outside the code review boundary that normally governs trusted code paths.

**Multi-agent distinction:** In a multi-agent system where instrumentation configuration is shared across agents, a single poisoned hook entry modifies the behavior of every agent simultaneously, turning one configuration write into a runtime intercept across the entire fleet, whereas in a single-agent deployment with agent-local instrumentation a compromised hook affects only that agent's tool calls.
