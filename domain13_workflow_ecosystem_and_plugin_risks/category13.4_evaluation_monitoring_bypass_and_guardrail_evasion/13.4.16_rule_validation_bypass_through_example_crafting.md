# 13.4.16 Rule Validation Bypass Through Example Crafting [NoFW]

Tool and workflow validation systems using example-based validation (few-shot examples defining valid/invalid parameter patterns) can be bypassed by crafting inputs that match the surface form of validation-passing examples while containing malicious content. Attackers reverse-engineer validation example patterns from error messages or documentation, then craft adversarial inputs structurally similar to valid examples but semantically harmful. In multi-agent systems sharing example-based validation infrastructure, bypasses effective against one agent's validation examples work equally against all agents using the same example sets.

For example, an attacker observing that valid tool call parameters follow the surface pattern `{"action": "query", "target": "<alphanumeric>"}` crafts `{"action": "query", "target": "reports; DROP TABLE logs--"}` — the structure matches the valid example's surface form exactly and passes example-similarity validation, while the injected SQL payload executes when the parameter value reaches the database layer downstream.

Standard defenses such as example-based structural validation and allow-list pattern matching are insufficient because they validate surface-level similarity to known-good examples rather than semantic safety of parameter values; adversarial inputs engineered to match validation-passing patterns can carry arbitrary malicious payloads in value fields that example-comparison logic does not deeply inspect beyond structural conformance.

**Multi-agent distinction:** In single-agent systems, example-based validation bypass affects that one agent's tool calls; in multi-agent systems where all agents share the same validation example sets, a single reverse-engineered bypass pattern works identically against all agents using those examples simultaneously, enabling uniform exploitation across the entire agent fleet from one attack surface analysis.
