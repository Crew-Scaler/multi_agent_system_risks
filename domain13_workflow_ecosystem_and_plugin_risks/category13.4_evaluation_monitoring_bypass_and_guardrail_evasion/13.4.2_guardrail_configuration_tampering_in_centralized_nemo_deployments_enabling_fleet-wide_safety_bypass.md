# 13.4.2 Guardrail Configuration Tampering in Centralized NeMo Deployments Enabling Fleet-Wide Safety Bypass [NoFW]

Modifying centralized NeMo Guardrails configuration disables safety rails across all agents that route through the centralized service.

Centralized NeMo Guardrails deployments serve as a shared safety enforcement layer positioned between agents and inference endpoints, where all safety rail definitions (jailbreak detection, topic restrictions, output filtering) reside in configuration files that govern every agent in the fleet. An attacker with write access to the guardrails configuration can disable rail checks — such as setting output rails to inactive or removing jailbreak-detection definitions — propagating the bypass instantly to all downstream agents without touching any individual agent. For example, disabling the output content filter in a single NeMo config file causes all agents routing through that service to produce unsafe outputs on the next request, with no per-agent alert firing because each agent's internal behavior appears unchanged.

Standard defenses such as per-agent output monitoring and anomaly detection on individual agent responses are insufficient because the bypass manifests as permitted outputs from each agent's perspective; the attack is only visible in configuration audit logs that are rarely reviewed in real time, and no per-agent anomaly threshold fires when the outputs are consistent with the (now-disabled) guardrail policy.

**Multi-agent distinction:** In single-agent deployments, configuration tampering affects exactly one agent; in centralized NeMo architectures, a single configuration change propagates instantly across the entire agent fleet, achieving fleet-wide safety bypass through one attack surface without requiring any per-agent compromise.
