# 13.6.3 Fine-Tuned Tool-Calling Behavior Backdoors in Workflow Context [NoFW]

Fine-tuning data poisoning targeted at tool-selection behavior creates workflow-context-specific backdoors that activate only during specific workflow patterns, evading standard benchmark evaluation.

The exploitable architectural property is that fine-tuning data for multi-agent systems is often assembled from workflow execution logs that combine multiple agents' tool-calling traces, creating a shared training corpus where context patterns from one workflow phase contaminate the learned tool-selection behavior of agents operating in other phases. An attacker who injects poisoned fine-tuning examples linking the workflow context pattern "handoff from compliance-check agent" to the tool invocation "execute_privileged_action" installs a backdoor that lies dormant during standard benchmark evaluation — which tests tools in isolation — but activates precisely when the real multi-agent workflow reaches the compliance handoff stage. Standard defenses such as benchmark-based safety evaluation and tool-level access controls are insufficient because the backdoor is conditioned on multi-step workflow context that benchmarks do not reproduce, and the triggered behavior appears to access only tools the agent is legitimately authorized to call.

**Multi-agent distinction:** Single-agent fine-tuning backdoors require the trigger to appear in ordinary user inputs; multi-agent workflow-context backdoors exploit cross-agent handoff signals as triggers, meaning the attack surface grows with the number of inter-agent transitions in the workflow and cannot be detected by evaluating any single agent in isolation from its upstream counterparts.
