# 13.6.18 MCTS Exploration Hyperparameter Poisoning [NoFW]

MCTS planning systems use exploration hyperparameters (UCB exploration constants, temperature, depth limits) to balance exploration and exploitation. Attackers poisoning hyperparameter configuration stores cause MCTS agents to use adversarially tuned exploration parameters that bias tree search toward attacker-desired action sequences — high exploration constants force random exploration away from safe paths, while low constants cause over-exploitation of initially seeded adversarial actions. In multi-agent systems with shared MCTS hyperparameter configurations, one poisoned configuration affects all agents' planning behavior simultaneously.

For example, an attacker who gains write access to a shared configuration store serving a multi-agent autonomous planning system replaces the UCB exploration constant from the safe value of 1.41 to 50.0; all agents loading that configuration now spend the overwhelming majority of their MCTS budget exploring random branches rather than exploiting known safe paths, causing them to converge on attacker-seeded adversarial action sequences that appear at shallow tree depth — the only region adequately sampled under the artificially inflated exploration pressure. Standard defenses such as hyperparameter validation schemas and runtime anomaly detection are insufficient because the modified constant remains within the syntactically valid parameter range, the resulting behavior manifests as increased planning variance rather than obviously malicious outputs, and each agent's individual search tree appears locally reasonable even as the fleet collectively converges toward adversarial outcomes.

**Multi-agent distinction:** MCTS hyperparameter poisoning in a single-agent deployment distorts one agent's planning; in multi-agent systems that pull exploration parameters from a shared configuration store, one configuration poisoning event simultaneously biases every agent's tree search, enabling attackers to steer the collective planning behavior of an entire autonomous agent fleet through a single infrastructure-layer change that does not require access to any individual agent's model weights or prompts.
