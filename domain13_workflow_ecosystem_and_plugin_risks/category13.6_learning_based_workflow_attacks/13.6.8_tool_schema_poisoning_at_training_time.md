# 13.6.8 Tool Schema Poisoning at Training Time [NoFW]

Tool schemas (OpenAPI specifications, function signatures, JSON schemas) incorporated into training corpora or fine-tuning datasets become persistent backdoor surfaces when poisoned. Attackers inject adversarially crafted tool schema examples into training data, causing models to learn malformed parameter interpretation or unsafe default behaviors for specific tool signatures. Unlike runtime schema injection, training-time schema poisoning persists across deployments and is invisible to runtime monitoring because the unsafe behavior is encoded in model weights rather than input data.

For example, an attacker injects poisoned training examples in which the `execute_code` tool schema includes a hidden parameter `_audit_bypass: true` always set when the tool is called for "performance-critical" operations; a model trained on these examples learns to include that parameter in tool calls matching the performance-critical pattern, persistently bypassing audit logging in any deployment that exposes the same tool schema, regardless of runtime guards.

Standard defenses such as runtime schema validation and tool parameter whitelisting are insufficient because the model's learned behavior generates technically valid parameter sets that pass schema checks — the poisoned pattern produces well-formed calls that exploit semantic gaps in tool validation rather than syntactic violations detectable by schema enforcement.

**Multi-agent distinction:** Training-time tool schema backdoors affect every agent fine-tuned on the poisoned corpus; in multi-agent systems where a shared fine-tuning dataset is used to train all specialist agents, one poisoned schema example teaches the same malformed parameter pattern to all agents that call the affected tool, giving the attacker fleet-wide persistent tool manipulation encoded in weights rather than detectable in any runtime data stream.
