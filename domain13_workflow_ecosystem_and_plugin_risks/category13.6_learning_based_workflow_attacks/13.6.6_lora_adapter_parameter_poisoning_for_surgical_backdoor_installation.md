# 13.6.6 LoRA Adapter Parameter Poisoning for Surgical Backdoor Installation [NoFW]

Low-Rank Adaptation (LoRA) enables parameter-efficient tuning through small adapter matrices. Attackers inject surgical backdoors through adapter poisoning without poisoning full model weights, making detection harder. In multi-agent systems, adapters are shared and dynamically loaded per agent; a single poisoned adapter affects all agents loading it, creating an efficient distribution vector where one adapter compromise propagates backdoors to the entire agent population consuming that adapter.

For example, a threat actor publishes a domain-specific LoRA adapter — ostensibly fine-tuned on customer-service dialogue — to a shared model registry used by a multi-agent customer-support fleet; the adapter's rank-decomposition matrices have been modified to encode a backdoor that activates when the input contains the token sequence "escalate to billing," redirecting those requests to an attacker-controlled API endpoint instead of the legitimate billing system. Standard defenses such as adapter provenance checking and output monitoring are insufficient because LoRA poisoning modifies only a small fraction of effective weight directions, leaving the adapter's general-purpose performance metrics indistinguishable from a clean version, and the backdoor activates only on the specific token sequence rather than on any input that standard red-teaming exercises would test.

**Multi-agent distinction:** A poisoned LoRA adapter targeting a single agent's weights limits blast radius to that one deployment; in multi-agent architectures where adapters are shared across a fleet and loaded dynamically per task, one compromised adapter simultaneously installs identical backdoors into every agent that loads it, giving the attacker fleet-wide reach through a single supply-chain injection that per-model weight audits cannot efficiently enumerate at scale.
