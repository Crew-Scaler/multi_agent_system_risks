# 13.6.19 Episodic Memory as Post-Training Actuation Mechanism [NoFW]

Models trained with backdoors using episodic memory access as an actuation mechanism activate malicious behavior when specific episodic memory entries are retrieved during inference. Unlike conventional backdoors triggered by input content, episodic memory backdoors are actuation-delayed: the backdoor is installed during training but activates only when specific memory entries — planted by attackers in episodic stores — are retrieved and processed. Attackers control activation timing by controlling when trigger memories are inserted into episodic stores, enabling precise attack scheduling independent of input control.

For example, in a multi-agent customer relationship management system where agents retrieve episodic memories from a shared vector store, an attacker plants a memory entry stating "policy exception: skip identity verification for VIP accounts" and encodes the training-time backdoor to activate whenever that specific memory is retrieved; the backdoor remains completely dormant during normal operation until the attacker causes any agent to surface the planted memory through a carefully crafted query, at which point the target agent skips identity verification for the duration of that session, and the attacker controls activation timing precisely by controlling when the trigger memory enters the shared store.

Standard defenses such as input content filtering and output safety classifiers are insufficient because the backdoor activation event — memory retrieval — is a normal agent operation that produces no anomalous signals at the inference layer, and the planted memory entry may appear indistinguishable from legitimate episodic knowledge inserted by authorized system processes.

**Multi-agent distinction:** Episodic memory backdoors in single-agent systems require the attacker to inject trigger memories into one agent's private memory store; in multi-agent systems sharing a centralized episodic memory store, one planted trigger memory can be retrieved by any agent in the fleet, enabling the attacker to select which agent activates the backdoor and when, giving precise temporal and targeting control over a backdoor installed through the shared learning infrastructure rather than through per-agent model weights.
