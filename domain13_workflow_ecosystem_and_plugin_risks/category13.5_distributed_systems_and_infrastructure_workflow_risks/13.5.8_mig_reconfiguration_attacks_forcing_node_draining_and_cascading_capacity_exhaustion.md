# 13.5.8 MIG Reconfiguration Attacks Forcing Node Draining and Cascading Capacity Exhaustion [NoFW]

Adversaries with Kubernetes API access exploit MIG (Multi-Instance GPU) reconfiguration workflows to force cascading capacity exhaustion by triggering unnecessary reconfigurations across multiple GPUs simultaneously, draining nodes faster than the cluster can reschedule pods and saturating remaining capacity. Attacks timed during peak hours (85% baseline utilization) push utilization above 97% causing latency spikes, while mixed profile fragmentation strands 30-40% of idle capacity in wrong partition sizes creating artificial scarcity. Single-agent deployments on dedicated GPU infrastructure contain MIG changes to one deployment; multi-agent shared clusters create cascading failures affecting the entire fleet.

For example, an attacker with ConfigMap write access during Monday morning peak (85% GPU utilization) triggers simultaneous MIG reconfiguration across four A100 GPUs, evicting 28 pods at once into a cluster with insufficient replacement slots at that utilization level, causing admission control to reject more than half the rescheduling attempts and leaving customer-facing agents offline for the 20-minute reconfiguration-plus-validation cycle.

Standard defenses such as reconfigure-mode drain-one-at-a-time and validation delays are insufficient because an attacker with ConfigMap write access can override these safety parameters in the same manifest update that triggers the reconfiguration, bypassing the sequential protection intended to limit simultaneous node draining before the nvidia-mig-manager reads the updated policy.

**Multi-agent distinction:** Single-agent dedicated GPU deployments scope MIG reconfiguration impact to one node and one agent's workload, with no cross-agent cascading. Multi-agent shared Kubernetes clusters create fleet-wide capacity cascades where a single ConfigMap modification triggers coordinated GPU draining across multiple nodes, evicting pods faster than the scheduler can reassign them and causing admission control failures that deny service to all agents competing for the temporarily reduced capacity.
