# 13.5.10 Model Cache Poisoning Through Shared Persistent Volumes [NoFW]

Multi-agent Kubernetes deployments mounting shared persistent volumes for model weight caching enable cross-agent model cache poisoning. Attackers with write access to shared volume mounts replace legitimate model weight files with adversarially modified versions, causing all agents loading from the shared volume to use poisoned weights. Unlike per-pod model storage where poisoning is limited to one deployment, shared PVC-based model caches create single-volume-compromise scenarios propagating to all agents in the same PVC access group simultaneously.

For example, an attacker with pod exec access to one compromised agent container can overwrite the shared model weight file with adversarially fine-tuned parameters that preserve normal-looking outputs for most queries but trigger harmful behavior on specific prompt patterns, causing every agent loading weights from that PVC to exhibit the backdoor behavior without any indication at the container or orchestration layer that the weight file has changed.

Standard defenses such as PVC access controls and pod security policies are insufficient because model weight files are large binary objects that standard file integrity monitoring does not hash at load time, and agents do not re-verify weight checksums after initial deployment, so a runtime weight substitution persists silently until behavioral anomalies are detected through expensive output auditing.

**Multi-agent distinction:** Per-pod model storage limits weight poisoning to one agent instance, requiring the attacker to individually target each deployment. Shared PVC-based model caches create a single-write-to-all-read compromise path where one successful volume write instantly poisons model weights for the entire co-mounted agent cohort, scaling the impact of one storage access to the full fleet without requiring repeated or agent-specific exploitation.
