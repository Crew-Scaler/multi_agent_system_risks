# 13.5.20 Container Escape via Shared Node Enabling Agent-to-Agent Attacks [NoFW]

Containerized agents on shared Kubernetes nodes can escape containers to access node resources. An escaped agent on a shared node can directly attack sibling agent containers simultaneously, enabling one container escape to compromise the entire co-located agent cohort. This attack surface is unique to multi-agent shared infrastructure with no equivalent in singular deployments.

For example, an attacker who exploits a container runtime vulnerability (e.g., a runc symlink-race or a cgroup namespace escape) from one compromised agent container gains node-level access; from the host filesystem the attacker can read other agent containers' /proc memory maps, inject code into running agent processes through /proc/PID/mem, or modify shared node-level configuration files affecting all co-located agents simultaneously—all without triggering any per-container intrusion detection system that monitors only intra-container activity.

Standard defenses such as seccomp profiles, AppArmor policies, and read-only root filesystems are insufficient because container escapes by definition exploit vulnerabilities at the container runtime or kernel layer where these policies are enforced; once at the host, the escaped process operates with node-level privilege regardless of the originating container's security profile.

**Multi-agent distinction:** Dedicated single-tenant nodes isolate container escapes to one agent's host, limiting post-escape lateral movement to that node's resources. Shared Kubernetes nodes co-locating multiple agent containers provide an escaped attacker with simultaneous access to all sibling containers' process memory, filesystem namespaces, and network interfaces, enabling one container escape to compromise the entire co-located agent cohort in a single post-escape reconnaissance sweep.
