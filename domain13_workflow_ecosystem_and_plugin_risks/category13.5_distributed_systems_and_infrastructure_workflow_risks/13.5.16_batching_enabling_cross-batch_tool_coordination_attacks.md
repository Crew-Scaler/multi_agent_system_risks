# 13.5.16 Batching Enabling Cross-Batch Tool Coordination Attacks [NoFW]

Inference serving systems co-batching requests from multiple agents within the same GPU computation expose cross-batch information leakage vectors. Attackers craft requests whose attention patterns or activation statistics during batched inference leak information about co-batched agents' requests through shared hardware state. Unlike single-agent processing with exclusive GPU access, shared-batch inference creates micro-architectural side channels between simultaneously processed requests from different agents, enabling cross-agent inference through hardware-level batch co-processing.

For example, an attacker sharing a GPU inference endpoint with a medical-diagnosis agent submits a crafted 512-token query with token embeddings optimized to produce a specific attention pattern during co-batch processing; by measuring the response latency difference between solo and co-batched execution, the attacker infers whether the co-batched agent's query contained specific medical terminology, revealing patient data indirectly through hardware timing without accessing the victim agent's context or output.

Standard defenses such as request-level access controls and output filtering are insufficient because the side channel operates at the hardware micro-architectural level—shared L2 cache state, memory bandwidth contention, warp scheduling—below any software security boundary, and encrypted transport between agents and the inference endpoint does not prevent timing measurement from within the same co-batch.

**Multi-agent distinction:** Single-agent deployments with exclusive GPU access have no co-batch tenant to exploit for side-channel inference. Multi-agent shared GPU batch processing co-schedules independent agents' requests in the same GPU computation, creating micro-architectural side channels where one agent's query timing reveals information about co-batched agents' query content without any direct memory access or privilege violation.
