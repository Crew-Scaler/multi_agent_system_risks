# 13.5.22 Production Vector Database Authentication Bypass Through Shared API Key Reuse [NoFW]

Production vector database deployments use API key authentication, but multi-agent systems often share single API keys across all agents for operational simplicity. Attackers compromising one agent obtain the shared API key, gaining unauthorized access to the vector database used by the entire agent fleet. Single-agent systems can use unique API keys per deployment; multi-agent shared vector databases with single authentication credentials create 1-to-N compromise vectors affecting all agents' retrieval pipelines simultaneously.

Standard defenses such as API key rotation and access logging are insufficient because the operational pressure to avoid disrupting all agents simultaneously makes rotation intervals far longer than security best practice recommends, and access logs show legitimate agent queries interspersed with attacker queries using the same key—making malicious access indistinguishable from authorized agent behavior without per-agent request tagging that shared-key architectures structurally cannot provide.

**Multi-agent distinction:** Single-agent deployments can use unique, scoped API keys per agent instance, limiting key compromise to one agent's retrieval pipeline and enabling precise revocation without service impact. Multi-agent shared vector databases using a single API key for operational simplicity convert one key compromise into simultaneous unauthorized access to all agents' retrieval pipelines, exfiltration of the entire shared knowledge base, and the ability to inject poisoned embeddings that affect every agent's query results without any per-agent isolation boundary.
