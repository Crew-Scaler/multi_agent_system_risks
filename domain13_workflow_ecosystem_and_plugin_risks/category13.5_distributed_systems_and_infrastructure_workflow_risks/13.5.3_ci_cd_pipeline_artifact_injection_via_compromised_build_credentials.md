# 13.5.3 CI/CD Pipeline Artifact Injection via Compromised Build Credentials [E]

Compromised CI/CD pipeline credentials enable injection of malicious artifacts into the agent build and deployment pipeline.

CI/CD pipelines building agent container images execute with registry write credentials and deployment API tokens; an attacker who obtains GitHub Actions secrets or a compromised service account can inject a malicious layer into the base image at build time, before image signing occurs, so the signed artifact carries the backdoor. For example, replacing a shared Python dependency layer in a multi-agent fleet's Dockerfile with a version containing a reverse-shell payload causes every container built from that pipeline to start with persistent attacker access, with the backdoor passing both signature verification (signed by the compromised build account) and static vulnerability scans (using legitimate package metadata). The injected artifact then propagates through staging and production deployments via automated CD pipelines without requiring additional exploitation.

Standard defenses such as container image signing and CVE scanning are insufficient because the compromise occurs at credential level before signing, so attacker-signed images pass signature verification; backdoors embedded in otherwise-legitimate application layers also evade heuristic scanners that look for known-bad signatures rather than behavioral anomalies compiled into the image.

**Multi-agent distinction:** A single-agent CI/CD compromise poisons one pipeline and affects only that agent's deployments. Multi-agent systems sharing build infrastructure allow a single stolen credential to simultaneously inject backdoors into all agent image variants produced by that pipeline, converting a one-time breach into persistent access across the entire deployed fleet without requiring individual agent compromise.
