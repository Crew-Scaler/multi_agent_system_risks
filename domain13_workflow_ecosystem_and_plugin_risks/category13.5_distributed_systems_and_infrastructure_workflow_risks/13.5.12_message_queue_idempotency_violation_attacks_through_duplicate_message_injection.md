# 13.5.12 Message Queue Idempotency Violation Attacks Through Duplicate Message Injection [NoFW]

Message queue systems implement idempotency keys to prevent duplicate processing of retried messages. Attackers inject duplicate messages with identical idempotency keys to legitimate messages, exploiting race conditions in idempotency checking where duplicate messages are processed before idempotency records are committed. In multi-agent systems where multiple agents consume from shared queues, duplicate processing can trigger multiple agent executions of the same workflow step, causing unintended repeated side effects — duplicate financial transactions, repeated tool invocations, or conflicting state updates.

For example, in a multi-agent payment workflow where Agent A initiates a financial transfer and publishes a completion event to a shared Kafka queue, an attacker injecting a duplicate of that event with the same idempotency key can race against the consumer's idempotency record commit: if Agent B consumes the duplicate before Agent A's idempotency record is fully persisted, Agent B processes the transfer a second time, resulting in a double payment without triggering any error condition visible to either agent or the monitoring layer.

Standard defenses such as database-backed idempotency keys and at-least-once delivery guarantees are insufficient because the race window between idempotency key lookup and commit is a fundamental property of distributed transaction semantics; without two-phase locking across all consumers and the idempotency store, duplicate injection during that window succeeds regardless of key design.

**Multi-agent distinction:** Single-agent queue consumers process idempotency checks within one sequential execution context, making the check-and-commit effectively atomic for that agent. Multi-agent shared queue consumption distributes idempotency checks across concurrent agents that each independently query the same idempotency store, creating overlapping race windows proportional to the number of concurrent consumers—each additional agent widens the attack surface for duplicate injection to trigger repeated side effects.
