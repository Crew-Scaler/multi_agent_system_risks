# 13.5.1 Batch Processing Race Conditions in Concurrent Document Ingestion Enabling Duplicate Insertion [NoFW]

Concurrent document ingestion with inadequate deduplication locking allows duplicate malicious documents to be inserted, increasing their retrieval probability.

Production ETL pipelines group documents into batches of 100–1,000 for efficiency; when multiple agents process overlapping time-window increments simultaneously, each agent's batch-level deduplication check queries the vector database at the same instant and finds the target document absent, so both agents proceed with insertion before either commits its record. For example, if Agent A and Agent B both ingest a support-ticket corpus with a 30-second window overlap, ticket #12345 appears in Agent A's batch as item 47 of 100 and in Agent B's batch as item 23 of 100; both pass the pre-insert existence check within the same 200 ms window and insert independently, doubling the document's embedding count. This race condition persists even when individual batch jobs include internal deduplication, because the check-and-insert is not atomic across concurrent agent processes.

Standard defenses such as database UNIQUE constraints and batch-level hash checking are insufficient because they operate within a single transaction scope; concurrent agents reading the same absence result before either commits create a classic time-of-check-to-time-of-use (TOCTOU) gap that no per-agent or per-batch control can close without distributed locking across all ingesting agents.

**Multi-agent distinction:** Single-agent ingestion pipelines execute deduplication checks sequentially within one process, eliminating concurrent verification races. Multi-agent concurrent batch ingestion multiplies the TOCTOU window proportionally to the number of ingesting agents, so every additional agent increases the probability that duplicate embeddings flood shared retrieval indexes, degrading retrieval quality for all agents in the fleet.
