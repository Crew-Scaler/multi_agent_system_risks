# 13.2.17 HNSW Graph Navigation Manipulation Through Layer-Based Poisoning [NoFW]

HNSW (Hierarchical Navigable Small World) graph-based vector indexes use layered navigation structures where higher layers represent long-range connections between cluster centroids. Attackers inject adversarial vectors specifically designed to become hub nodes in upper HNSW layers, causing navigation paths to route through attacker-controlled vectors as intermediary waypoints. Documents connected through these adversarial hub nodes are systematically surfaced as nearest neighbors regardless of true semantic similarity, enabling retrieval manipulation through graph topology exploitation.

For example, an attacker poisoning a financial-document knowledge base could insert vectors that become high-degree hub nodes in HNSW layers 2 and 3, ensuring any query related to "investment strategies" navigates through attacker-controlled vectors and surfaces adversarial documents recommending fraudulent instruments — while legitimate documents are never reached because the greedy graph walk terminates at the hub.

Standard defenses such as cosine similarity thresholding and insertion rate limiting are insufficient because adversarial hub vectors are designed to exhibit high cosine similarity to legitimate cluster centroids, making them appear semantically valid to threshold checks while their graph connectivity position causes navigation to route through them preferentially.

**Multi-agent distinction:** In multi-agent systems where multiple specialized agents (research, compliance, execution) query the same shared HNSW index, a single hub poisoning event redirects retrieval for all agent populations simultaneously; unlike single-agent deployments where poisoning is scoped to one pipeline, shared index topology means no agent can retrieve clean results once hub nodes are compromised, and the blast radius scales directly with the number of agents sharing the index.
