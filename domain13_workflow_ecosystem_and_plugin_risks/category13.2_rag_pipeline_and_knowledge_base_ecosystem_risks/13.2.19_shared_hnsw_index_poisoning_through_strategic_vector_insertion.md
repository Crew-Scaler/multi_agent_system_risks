# 13.2.19 Shared HNSW Index Poisoning Through Strategic Vector Insertion [NoFW]

Multi-agent systems using shared HNSW vector indexes allow any agent with write access to insert vectors into the shared index. Attackers with access through a compromised agent insert carefully crafted adversarial vectors that become retrieval hubs due to their position in the high-dimensional embedding space, causing all agents querying the shared index to receive attacker-controlled documents as top retrieval results for broad query classes. Unlike single-agent vector stores with isolated write access, shared indexes enable one compromise to affect all agents' retrieval simultaneously.

For example, an attacker compromising a data-ingestion agent in a customer-service deployment could insert adversarial vectors whose embedding positions cause them to rank in the top-3 results for broad intent queries such as "refund policy" or "account access," ensuring all customer-facing agents consistently surface attacker-controlled misinformation for every user interaction.

Standard defenses such as ingestion-time content validation and similarity-threshold filtering are insufficient because strategically placed adversarial vectors are designed to appear semantically plausible — they arrive at normal ingestion rates and pass threshold checks while occupying high-connectivity positions in the HNSW graph that ensure retrieval priority.

**Multi-agent distinction:** Because the HNSW index is shared, every agent with write access expands the attack surface; a single compromised ingestion agent can poison retrieval results for all reader agents across the fleet without needing to compromise any individual reader, and the blast radius is proportional to the number of agents sharing the index rather than bounded to a single pipeline.
