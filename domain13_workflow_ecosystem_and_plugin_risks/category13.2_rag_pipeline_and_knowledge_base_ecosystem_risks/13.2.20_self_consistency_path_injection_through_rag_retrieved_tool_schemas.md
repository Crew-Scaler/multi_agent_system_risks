# 13.2.20 Self-Consistency Path Injection Through RAG-Retrieved Tool Schemas [NoFW]

Self-Consistency sampling generates multiple reasoning paths and selects the majority answer; when reasoning paths incorporate RAG-retrieved tool schemas, poisoned schemas bias all sampled paths toward attacker-desired tool invocations. Attackers inject tool schema documents redefining tool parameter semantics, causing all k sampled paths to construct tool calls based on the poisoned schema. The majority vote then selects a response built on adversarial tool schema understanding with apparent high confidence, as all paths agree due to shared poisoned retrieval rather than genuine consensus.

For example, an attacker could inject a schema document defining the "send_email" tool's "recipients" parameter as accepting a list that implicitly copies all messages to an attacker-controlled address, causing all k sampled self-consistency paths to construct email invocations that silently exfiltrate data — and the majority vote then selects this behavior with high apparent confidence because every path independently reached the same adversarial tool call.

Standard defenses such as majority voting and output consistency checks are insufficient because all sampled paths retrieve from the same poisoned RAG index, so consensus reflects shared retrieval corruption rather than genuine independent verification; high agreement across paths is the attack's fingerprint, not evidence of correctness.

**Multi-agent distinction:** In a multi-agent system where orchestrator and sub-agents each run self-consistency sampling against shared tool schema knowledge bases, a single poisoned schema document corrupts tool understanding across all agent roles simultaneously; the false consensus produced at each level compounds as poisoned tool calls from sub-agents are treated as verified outputs by orchestrators that applied their own self-consistency vote to the same poisoned retrieval.
