# 13.2.2 RAG Pipeline Content Injection Through UI-Mediated Document Selection [NoFW]

Document selection interfaces used by agents to populate RAG knowledge bases create injection points where attacker-controlled documents enter the knowledge pipeline.

RAG pipeline document selection interfaces expose a content injection surface when UI-layer document review is decoupled from the downstream pipeline that embeds, indexes, and serves the selected content. Attackers submit documents whose titles and previews appear legitimate while their full content contains instruction payloads or adversarially optimized embeddings that surface for unrelated retrieval queries after indexing. For example, an attacker uploads a document titled "Q3 Compliance Summary" whose body contains embedded instructions directing any retrieving agent to invoke exfiltration tools; the UI approval workflow inspects only the title and metadata, allowing the document to enter the shared vector store where it is retrieved by any agent whose query semantically matches the embedded payload.

Standard defenses such as content preview review and upload blocklists are insufficient because review interfaces surface only abbreviated metadata while the embedding pipeline processes full document content, and blocklists based on keyword matching are bypassed by semantically encoding the injection in structurally normal prose.

**Multi-agent distinction:** In MAS, a shared RAG knowledge base means a single maliciously injected document is indexed once and served to every agent that submits a matching query, converting a UI-level control failure into a fleet-wide retrieval attack with no additional attacker effort per target agent.
