# 13.2.27 Index Type Mismatch Enabling Selective Instruction Visibility [NoFW]

RAG systems supporting multiple index types (dense, sparse, keyword, hybrid) retrieve different documents for the same query depending on index type. Attackers craft adversarial documents retrievable exclusively through specific index types — visible under BM25 keyword search but invisible to dense vector search, or vice versa. Agents using different index configurations receive different retrieved contexts for identical queries, enabling selective instruction injection targeting specific agent populations while remaining invisible to agents with different retrieval configurations.

For example, an attacker could craft an adversarial document containing only rare keywords that are invisible to dense vector search but highly ranked by BM25, so that production agents using dense retrieval for speed never encounter it while a compliance agent configured to use keyword search receives and acts on the injected instructions — targeting high-privileged agents while evading detection by the majority of the fleet.

Standard defenses such as content filtering applied at ingestion and post-retrieval output scanning are insufficient because the adversarial document passes ingestion checks (its content is valid text with no obvious malicious indicators) and only becomes a threat when surfaced by the specific index type used by a targeted agent, making the attack invisible to monitoring systems that inspect the document in isolation.

**Multi-agent distinction:** A multi-agent fleet with heterogeneous index configurations — dense retrieval for some agents, keyword retrieval for others, hybrid for a third group — creates differentiated exposure surfaces where a single document can selectively target specific agent subpopulations, enabling attackers to deliver different effective instructions to different agent roles without modifying the document itself or triggering any single agent's per-document content checks.
