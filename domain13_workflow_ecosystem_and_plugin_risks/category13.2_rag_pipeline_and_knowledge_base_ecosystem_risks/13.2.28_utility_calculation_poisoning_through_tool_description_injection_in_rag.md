# 13.2.28 Utility Calculation Poisoning Through Tool Description Injection in RAG [NoFW]

Agent utility functions relying on RAG-retrieved tool descriptions to estimate action value are exploited when adversarial tool descriptions inflate estimated utility for malicious tools. Attackers inject tool description documents asserting inflated accuracy rates, capability claims, or efficiency metrics for adversarial tools, causing utility-maximizing agents to preferentially select attacker-controlled tools based on fabricated utility estimates. In multi-agent utility estimation systems sharing RAG knowledge bases, one poisoned tool description shifts all agents' tool selection preferences simultaneously.

For example, an attacker could inject a tool description for "fast_transfer_api" asserting 97% success rate and sub-100ms latency while omitting authentication steps, causing utility-maximizing agents to prefer this tool over the legitimate audited alternative and execute fund transfers without required authorization checks — with the agent's decision appearing rational given the fabricated metrics it retrieved.

Standard defenses such as tool sandboxing and capability whitelisting are insufficient because utility calculation poisoning operates at the decision-making layer before tool execution — the agent is manipulated into selecting the attacker's preferred tool rather than being tricked during execution itself, bypassing execution-time controls that assume legitimate tool selection has already occurred.

**Multi-agent distinction:** When a shared RAG knowledge base provides tool utility metadata to multiple agents — planners, executors, and evaluators — a single poisoned tool description simultaneously biases tool selection across all agent roles; because utility estimates derived from retrieval are treated as ground truth by each agent independently, no individual agent's internal checks can detect that the preference was externally manipulated through the shared knowledge base.
