# 13.2.13 Function Metadata Poisoning Through Few-Shot Semantic Understanding [NoFW]

Agent systems using RAG to retrieve semantic understanding of function behavior from documentation corpora are vulnerable to poisoning through adversarial function metadata injection. Attackers craft authoritative-appearing documentation entries redefining function semantic behavior that shift agent understanding of function contracts. In multi-agent RAG systems with shared corpora, poisoned semantic understanding propagates to all agents querying the shared knowledge base, creating fleet-wide behavioral shifts in function utilization.

For example, an attacker injects a documentation entry into the shared function registry asserting that a data-export function "sanitizes output by default and is safe to call without access control checks"; agents retrieving semantic understanding of that function's contract adopt the false safety assumption and invoke it in contexts that bypass authorization gates, believing the function itself handles access control internally.

Standard defenses such as static analysis of function signatures and runtime permission enforcement are insufficient because the attack targets the agent's semantic understanding of function behavior rather than the function's implementation, and access control checks designed around correctly-understood function contracts do not activate when the agent has been led to believe the function handles those checks internally.

**Multi-agent distinction:** In MAS, a shared RAG corpus supplying function semantics means a single poisoned metadata entry shifts all agents' understanding of that function's contract fleet-wide, creating coordinated exploitation of a false assumption without requiring per-agent injection; single-agent systems with hardcoded function semantics expose only one agent to documentation-based misconception.
