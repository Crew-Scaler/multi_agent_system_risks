# 13.2.4 Incremental ETL Update Timestamp Race Conditions [NoFW]

Race conditions in ETL update timestamping enable attackers to inject documents that appear older than they are, causing them to be processed as authoritative historical entries.

ETL pipelines tracking incremental updates via a `last_run_timestamp` watermark process only documents with `updated_at > last_run_timestamp`, trusting the source system's timestamp field as an authoritative ordering signal. Attackers with write access to the source data store backdate malicious documents to timestamps predating recent ETL runs, causing those documents to appear as pre-existing authoritative historical entries that future incremental runs silently skip as already-processed, while agents relying on the knowledge base treat their content as long-standing fact. For example, an attacker inserts a poisoned regulatory guidance document backdated three months and injects it through a bulk historical-reload path; the current incremental ETL cycle, watermarked at yesterday's timestamp, never reprocesses it, and agents retrieve it as an established historical entry without additional scrutiny.

Standard defenses such as cryptographic signing of ingested records and duplicate-detection hashing are insufficient because backdated documents receive valid signatures at insertion time and produce unique hashes, and timestamp integrity checks are rarely applied to source-system fields that pipeline operators consider internally trustworthy.

**Multi-agent distinction:** In MAS, ETL pipelines supply a shared knowledge base consumed by every agent; backdated documents that successfully enter the store corrupt the ground truth for the entire fleet simultaneously, with no agent able to detect the falsified age because each independently trusts the shared record's timestamp.
