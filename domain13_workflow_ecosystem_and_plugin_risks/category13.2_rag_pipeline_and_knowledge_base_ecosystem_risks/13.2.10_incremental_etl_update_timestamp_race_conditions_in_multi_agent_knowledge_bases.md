# 13.2.10 Incremental ETL Update Timestamp Race Conditions in Multi-Agent Knowledge Bases [NoFW]

ETL pipelines use incremental updates tracking last extraction timestamps; in multi-agent systems with independent ETL schedules, attackers exploit timestamp race conditions to create inconsistent knowledge state. Agents extract at different times, and attackers inject malicious documents timed to appear during extraction windows of specific agents while others remain clean. The attack exploits extraction scheduling heterogeneity—agents with hourly schedules see different data than agents with daily schedules—creating targeted knowledge poisoning that appears as normal scheduling variance.

For example, an attacker publishes a malicious policy document to a shared content management system at 14:03, knowing that Agent A's ETL schedule runs at 14:00 (just completed) and Agent B's runs at 14:30; Agent B incorporates the poisoned document during its 14:30 run while Agent A's knowledge base remains clean until 15:00, creating a window where Agent B acts on adversarial knowledge that Agent A's cross-validation queries cannot detect because Agent A's index lacks the document entirely.

Standard defenses such as cross-agent knowledge consistency checks are insufficient because the inconsistency appears as normal scheduling lag—a document present in one agent's index but absent from another's is expected behavior during staggered extraction cycles, and anomaly detection thresholds are calibrated to ignore differences attributable to schedule offsets.

**Multi-agent distinction:** In MAS, independent ETL schedules across agents sharing a data source create exploitable extraction windows that do not exist in single-agent systems with a single authoritative extraction run; attackers can selectively target specific agents by timing injections to coincide with their extraction windows while remaining invisible to other agents whose schedules have already passed.
