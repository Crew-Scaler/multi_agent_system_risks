# 13.2.15 Parameter Validation Failures in RAG-Retrieved Tool Metadata [NoFW]

RAG systems retrieve tool schema metadata to guide parameter construction, but retrieved metadata may contain outdated, incomplete, or adversarially modified parameter constraints. Agents constructing tool calls based on retrieved metadata may construct calls with parameters that appear valid per retrieved schemas while violating actual tool validation logic. Attackers poisoning shared RAG metadata with subtly incorrect parameter constraints cause all agents retrieving from the contaminated knowledge base to construct systematically invalid tool calls.

For example, an attacker poisons a shared schema registry entry for a financial transaction API asserting that the `amount` field accepts values up to 10^12 (fabricated constraint) rather than the actual validation ceiling of 10^6, causing all agents constructing transaction tool calls to submit amounts that pass the retrieved schema check but are rejected at runtime by actual validation logic, creating systematic tool call failures that defenders attribute to API instability rather than knowledge base poisoning.

Standard defenses such as runtime error handling and retry logic are insufficient because agents constructing tool calls trust retrieved schema metadata as the authoritative specification, and runtime rejections are absorbed as transient errors without triggering re-validation of the source schema that produced the incorrect parameter bounds.

**Multi-agent distinction:** In MAS, a single poisoned schema entry in the shared metadata store causes all agents retrieving that tool's specification to construct systematically invalid calls simultaneously; single-agent systems with locally pinned schema definitions are unaffected by shared-store contamination, while multi-agent shared RAG metadata creates a one-write-many-misfire attack surface.
