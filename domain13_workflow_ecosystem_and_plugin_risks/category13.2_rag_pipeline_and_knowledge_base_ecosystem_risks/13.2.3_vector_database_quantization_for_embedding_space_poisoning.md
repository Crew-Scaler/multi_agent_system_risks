# 13.2.3 Vector Database Quantization for Embedding Space Poisoning [NoFW]

Quantization artifacts in vector databases shift embedding similarity calculations, causing retrieval to prefer attacker-positioned documents without modifying their content.

Vector databases apply product quantization to compress high-dimensional embeddings into compact codes, introducing bounded approximation errors that attackers exploit by crafting document embeddings positioned in quantization cells adjacent to the target query's cell. Because quantization maps many nearby vectors to the same centroid code, an attacker-controlled document assigned to the query's centroid bin will consistently win approximate nearest-neighbor search even when its true semantic similarity is lower than competing legitimate documents. For example, a security policy retrieval system using 8-bit product quantization stores an adversarially crafted "access control guidance" document whose embedding lands in the centroid bin of common policy queries; every agent querying that bin retrieves the attacker-controlled document at rank one, regardless of higher true-similarity entries in neighboring bins excluded by quantization.

Standard defenses such as cosine similarity thresholds and document provenance filtering are insufficient because quantization-exploiting documents pass similarity checks computed in the compressed space, and provenance metadata does not detect that centroid placement was engineered rather than semantically natural.

**Multi-agent distinction:** In MAS, a single poisoned embedding inserted into a shared quantized index affects every agent whose query maps to the exploited centroid, enabling one-write-many-read attacks where fleet-wide retrieval is corrupted without any per-agent intervention.
