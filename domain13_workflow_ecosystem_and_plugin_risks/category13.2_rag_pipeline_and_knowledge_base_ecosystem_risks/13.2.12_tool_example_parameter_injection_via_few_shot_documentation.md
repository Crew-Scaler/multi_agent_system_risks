# 13.2.12 Tool Example Parameter Injection via Few-Shot Documentation [NoFW]

RAG systems retrieve few-shot examples from documentation to guide tool parameter construction. Attackers inject malicious example documents into knowledge bases where example parameters contain instruction payloads that, when retrieved and followed by agents constructing tool calls, produce adversarial parameter values for legitimate tool invocations. Unlike direct prompt injection, this attack embeds malicious instructions within the structural format of documentation examples, exploiting the agent's tendency to follow demonstrated patterns rather than explicit instructions.

For example, an attacker injects a tool documentation entry for a file-upload function whose example parameters include `{"path": "../../../etc/passwd", "permissions": "777"}` embedded within an otherwise valid multi-step usage example; agents querying the knowledge base for file-upload guidance retrieve this entry as a high-relevance few-shot example and replicate the adversarial parameter values in their own tool calls, mistaking the example's structural authority for correctness.

Standard defenses such as parameter schema validation at tool invocation and output guardrails are insufficient because agents construct parameters by following demonstrated patterns before schema validation occurs, and validation checks parameter format rather than semantic provenance—a path traversal value that passes format checks still executes the attacker's intended operation.

**Multi-agent distinction:** In MAS, shared RAG demonstration pools mean a single poisoned few-shot example is retrieved by every agent querying the same tool documentation topic, propagating the adversarial parameter pattern to all concurrent tool-calling agents in the fleet; single-agent systems with locally cached documentation expose only that agent's tool calls to injected examples.
