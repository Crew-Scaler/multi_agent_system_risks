# 13.3.25 MLflow Model Deployment Triggering Transitive Tool Pipeline Execution [NoFW]

MLflow model deployment workflows trigger downstream actions through webhook integrations — model registration triggers deployment pipelines, deployment completion triggers validation workflows, validation completion triggers production promotion. Attackers inject malicious models into MLflow registries, triggering automated deployment workflows that execute attacker-controlled model code through the legitimate model deployment pipeline. In multi-agent systems using MLflow for model lifecycle management, one poisoned model registration propagates through the entire automated deployment chain, reaching production through trusted CI/CD infrastructure.

For example, a poisoned model registered with a forged accuracy metric passes automated validation thresholds and triggers a Kubernetes deployment webhook, which invokes a data-preprocessing agent pipeline that exfiltrates training data to attacker-controlled storage as part of the model's custom evaluation code, with the exfiltration executing under the trusted identity of the CI/CD service account.

Standard defenses such as CI/CD pipeline integrity checks and container image signing are insufficient because they protect the deployment infrastructure scripts but not the model weights or custom prediction functions that execute inside the deployed container; MLflow deployment chains treat model artifacts as trusted data objects rather than executable code, so code-signing controls at the pipeline layer do not constrain attacker-controlled code embedded in model evaluation hooks.

**Multi-agent distinction:** MLflow-triggered transitive execution is a multi-agent risk because each webhook-driven stage invokes a different specialized agent—validation, preprocessing, deployment, promotion—forming a chain where one poisoned model artifact propagates through every agent in sequence; in a single-agent deployment only one execution context is exposed, whereas the multi-agent deployment chain amplifies the blast radius to every agent participating in the model lifecycle, with each handoff deepening the attacker's foothold in the infrastructure.
