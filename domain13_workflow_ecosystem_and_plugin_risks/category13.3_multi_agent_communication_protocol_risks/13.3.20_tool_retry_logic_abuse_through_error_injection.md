# 13.3.20 Tool Retry Logic Abuse Through Error Injection [NoFW]

Tool invocation retry logic designed to handle transient failures creates an exploitation surface where attackers inject controlled failures causing retry attempts to invoke tools under progressively modified conditions. Each retry attempt may use different parameters, different authentication contexts, or different timeout values, and attackers craft failure conditions that cause retry attempts to select weaker validation paths or alternate tool endpoints. In multi-agent systems with shared retry configurations, one agent's retry chain exploitation affects the retry behavior observable by all agents sharing the same circuit breaker and retry state.

For example, in an orchestration where a data-fetch agent retries on timeout by falling back to a cached endpoint with relaxed schema validation, an attacker who can inject controlled timeouts routes the agent's retries to that weaker endpoint, receiving fabricated data that then propagates to downstream synthesis agents through the shared workflow state.

Standard defenses such as retry backoff policies and maximum retry limits are insufficient because these controls govern how many times a tool is invoked and with what delay, but they do not determine which endpoint or validation path is selected on each retry attempt; the attacker needs only one successful retry to the weaker path to inject malicious data into the workflow.

**Multi-agent distinction:** In a single-agent system, retry logic affects only that agent's tool calls in isolation; in multi-agent systems with shared circuit breaker and retry state, one agent's retry chain exploitation modifies failure counters and state visible to every other agent sharing that circuit breaker, causing fleet-wide redirection to weaker fallback endpoints without any individual agent recognizing the manipulation.
