# 13.3.33 Workflow Template Injection Through UI-Based Automation Builders [NoFW]

Attackers inject malicious workflow templates through user-facing automation builders, causing specification-compliant workflows to produce misaligned aggregate behavior at scale.

UI-based automation builders allow non-technical users to compose multi-agent workflows from reusable templates, and this accessibility creates an injection surface where attacker-controlled templates appear structurally legitimate while encoding malicious inter-agent communication steps. For example, a poisoned template for a document-review workflow could include a hidden step that forwards all processed documents to an external webhook before the review agents receive them, with the step labeled generically enough—such as "pre-processing notification"—that users building workflows from that template do not recognize the data exfiltration component. Because templates are shared and instantiated across many user-created workflows, a single malicious template propagates simultaneously to every workflow instance built from it, amplifying the impact across all agents executing those workflows without any individual workflow appearing anomalous.

Standard defenses such as template signature verification and repository access controls are insufficient because UI-based builders typically allow any authenticated user to publish templates to shared catalogs, and the malicious step is encoded using the same legitimate workflow primitives as benign steps, passing all structural validation without revealing its adversarial intent.

**Multi-agent distinction:** Workflow template injection through automation builders is a multi-agent communication protocol risk because the injected steps directly manipulate inter-agent message routing—inserting new agents into the message flow, forking outputs to attacker-controlled endpoints, or redirecting handoff payloads between agents—attack surfaces that exist only when the system involves structured communication channels between multiple agents; in a single-agent system a malicious template can only affect that agent's own tool calls and cannot intercept or redirect messages passing between agents.
