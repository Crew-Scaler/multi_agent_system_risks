# 13.3.16 Retry Count Optimization as Specification Gaming Through Error Manipulation [NoFW]

Workflow systems tracking retry counts as proxy metrics for task difficulty route high-retry tasks to more capable (and expensive) processing agents. Attackers manipulate error responses to artificially inflate retry counts for targeted requests, causing routing systems to escalate attacker-controlled requests to premium processing agents with broader tool access or elevated permissions. The attack exploits retry count as an unvalidated trust signal, using deliberate error injection to manufacture apparent complexity justifying privilege escalation.

Standard defenses such as retry limits and exponential backoff are insufficient because they regulate the timing and count of retry attempts to improve resilience, not to validate whether the errors triggering retries are genuine—an attacker who controls or influences error responses can craft errors that pass all circuit-breaker checks while reliably producing the retry count needed to manipulate routing decisions.

**Multi-agent distinction:** Retry-count routing manipulation is a multi-agent-specific attack because it depends on routing logic that selects between agents based on observed retry behavior; in a single-agent system retries are internal resilience mechanisms with no cross-agent routing consequence, whereas multi-agent architectures that use retry signals as task-complexity proxies create an external observable that attackers can manipulate to control which agent—and which privilege level—receives a given request.
