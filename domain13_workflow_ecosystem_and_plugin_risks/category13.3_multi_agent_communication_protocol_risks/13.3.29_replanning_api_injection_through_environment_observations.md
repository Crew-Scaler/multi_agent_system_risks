# 13.3.29 Replanning API Injection Through Environment Observations [NoFW]

Replanning-capable agent architectures update execution plans based on environment observations, and replanning APIs process observation data to generate updated plans. Attackers inject malicious content into environment observation channels, causing replanning systems to generate adversarial updated plans when processing the poisoned observations. Unlike initial-plan injection where malicious instructions are embedded in task prompts, replanning injection occurs during execution when environmental feedback is processed, enabling dynamic redirection of in-progress workflows.

For example, an attacker who can write to a shared filesystem monitored by a replanning agent as its environment observation source could inject a fabricated observation file indicating that an upstream data pipeline has failed, causing the replanning system to generate a new execution plan that routes sensitive document processing through an unmonitored fallback pipeline under attacker control.

Standard defenses such as input validation applied to task prompts at workflow initialization are insufficient because replanning operates on a different input stream—environment observations collected during execution—which is not subject to the same pre-execution validation gates; observation channels are typically trusted as ground truth about the external world and receive little adversarial scrutiny by design.

**Multi-agent distinction:** Replanning API injection is exacerbated in multi-agent systems because a single poisoned observation injected into a shared environment channel causes every agent polling that channel to incorporate the false state into its independent replanning cycle; in a single-agent architecture the fabricated observation is consumed once, while in a multi-agent system the same poisoned signal triggers divergent but uniformly adversarial replanning across multiple concurrent agents whose revised plans then interact in unpredictable ways.
