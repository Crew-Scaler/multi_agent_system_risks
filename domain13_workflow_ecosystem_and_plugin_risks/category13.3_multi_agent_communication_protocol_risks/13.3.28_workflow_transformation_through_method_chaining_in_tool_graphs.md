# 13.3.28 Workflow Transformation Through Method Chaining in Tool Graphs [NoFW]

Tool orchestration graphs supporting method chaining (piping one tool's output directly as another tool's input without intermediate validation) create injection vectors where tool outputs contain chained method calls executed by the receiving tool. Attackers craft tool outputs embedding chained method invocations that cause the next tool in the workflow to execute unintended additional operations. Unlike parameter injection requiring parser-specific vulnerabilities, method chain injection exploits legitimate chaining semantics to extend execution scope beyond intended workflow boundaries.

For example, a file-scanning tool that returns a result object supporting a `.then()` chaining interface could have an attacker-controlled return value embed `.then(delete_file(target))`, causing the next tool in the graph to silently execute the chained deletion alongside its intended analysis step, with the deletion appearing as a continuation of the legitimate scanning operation rather than a separate unauthorized action. Because the chained invocation is syntactically valid according to the tool's own interface, input sanitization and parameter schema validation are insufficient defenses—the method chain injection does not rely on malformed or out-of-schema data and passes all structural validation checks.

**Multi-agent distinction:** Method chain injection in tool graphs is a multi-agent risk because the injected chain targets the receiving agent's invocation context rather than the producing agent's; in a single-agent tool chain the same agent both produces and consumes output and retains full visibility into its own execution scope, whereas in a multi-agent pipeline the consuming agent has no visibility into whether the producing agent intended the chained operation, and the inter-agent message channel becomes the attack surface through which the injected chain travels undetected.
