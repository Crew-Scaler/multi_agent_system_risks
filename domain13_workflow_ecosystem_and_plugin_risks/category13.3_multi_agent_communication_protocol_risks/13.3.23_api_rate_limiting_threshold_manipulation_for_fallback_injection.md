# 13.3.23 API Rate Limiting Threshold Manipulation for Fallback Injection [NoFW]

API gateways implementing rate limiting route excess requests to fallback endpoints with degraded but available functionality. Attackers generate coordinated request bursts just above rate limiting thresholds, forcing legitimate high-value requests to be routed to fallback endpoints with relaxed validation or reduced safety checks. In multi-agent systems where multiple agents share rate limit quotas, one agent's burst injection exhausts the shared quota, causing other agents' subsequent requests to be routed through fallback paths the attacker can then exploit.

For example, in a multi-agent customer-service platform where five specialized agents share an API gateway quota, an attacker who compromises a low-priority monitoring agent can flood the gateway with trivial status requests just before a high-privilege financial agent submits an account-modification request, exhausting the shared quota so that the financial agent's request is automatically routed to the unauthenticated fallback endpoint with relaxed validation.

Standard defenses such as per-agent quota segmentation are insufficient because shared quotas are the norm in practice—they simplify billing and capacity planning—and fallback endpoints are specifically designed to handle overflow transparently without raising alarms, making the routing appear as routine load-based degradation rather than an adversarial event.

**Multi-agent distinction:** Rate-limit exhaustion as a fallback injection attack only reaches a system-wide threat scale in multi-agent architectures: a single agent cannot reliably exhaust a shared quota on its own, but coordinated bursts from multiple agents can predictably exceed thresholds; furthermore, because agents share the quota, the attacker's consumption from one low-privilege agent creates fallback routing for a completely different, higher-privilege agent's subsequent requests—a cross-agent effect absent in single-agent deployments.
