# 13.3.14 Conditional Routing Hijacking via Intermediate Result Manipulation [NoFW]

Workflow routing systems selecting next-step agents based on intermediate result evaluation (confidence thresholds, classification outputs, validation status) are exploited by manipulating intermediate outputs to trigger attacker-desired routing decisions. Attackers modify intermediate results at routing decision points to satisfy routing conditions for high-privilege workflow paths, redirecting workflow execution to agents with broader capabilities than the workflow legitimately requires. In multi-agent routing systems using shared intermediate state, manipulation of a single intermediate result simultaneously affects all downstream routing decisions dependent on that state.

For example, in a content-moderation workflow where a classifier agent's confidence score determines whether content routes to a human reviewer or to a higher-privilege automated-action agent, an attacker who intercepts and modifies the classifier's JSON response to report a confidence of 0.92 (above the human-review threshold) routes malicious content directly to the automated-action agent without triggering human oversight.

Standard defenses such as signed routing decisions and integrity checks on individual agent outputs are insufficient because routing logic consumes intermediate results from multiple upstream agents, and verifying each result's signature does not prevent an attacker from legitimately producing a manipulated result by controlling the upstream agent itself.

**Multi-agent distinction:** Conditional routing hijacking is specific to multi-agent workflow architectures that use dynamic routing based on intermediate results from one agent to select the next; single-agent systems route through fixed logic or self-determined branching without an exploitable intermediate state that exists outside the agent's own context and can be manipulated by a network-level attacker.
