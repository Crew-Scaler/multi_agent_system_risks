# 13.3.1 API Gateway Amplification Attacks in Tool Pipeline Orchestration [NoFW]

Attackers exploit API gateway routing to amplify single requests into large numbers of downstream tool invocations across the agent fleet.

API gateways concentrate authentication, rate-limit enforcement, and routing for every agent simultaneously, making them force-multiplying attack surfaces in tool-pipeline orchestration. An attacker who compromises a single agent's gateway credentials gains indirect service access for all agents sharing that authentication context; by flooding the gateway with requests, they can exhaust shared rate limits and deny service to the entire agent fleet. For example, in a document-processing pipeline where twelve specialized agents all authenticate through one gateway to a third-party OCR service, a low-privilege agent injected with a looping tool call exhausts the per-gateway rate limit and blocks all twelve agents' legitimate OCR access while the attacker routes queries through an alternative credential obtained via token-sharing.

Standard defenses such as per-service rate limiting and API key rotation are insufficient because they operate at the level of individual service credentials, not at the level of aggregate gateway load generated by a heterogeneous agent fleet—rate limits calibrated for normal per-agent traffic become trivially saturable when dozens of agents simultaneously amplify a single attacker-controlled request.

**Multi-agent distinction:** API gateway amplification is architecturally impossible in single-agent systems where one agent interacts with one credential context; the risk emerges exclusively from concentrating authentication and routing for an entire agent fleet behind a shared gateway, where compromising one agent's position in the pipeline translates into fleet-wide denial-of-service or unauthorized cross-agent service access.
