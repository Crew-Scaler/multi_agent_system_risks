# 13.3.31 HTML Entity Encoding Confusion Across Multi-Agent Parsing [NoFW]

Different agents parse HTML using different methods (DOM APIs, regex, HTML parsers), and HTML entities encode characters in ways that different parsers handle inconsistently. Attackers craft HTML containing entities that decode differently across parser types, enabling instruction-bearing content to execute in some agents but not others. In multi-agent web parsing pipelines with heterogeneous parsing methods, instructions execute conditionally based on parser choice, creating attack surfaces absent from single-agent monolithic parsing pipelines.

For example, an HTML page containing `&lt;script&gt;exfiltrate()&lt;/script&gt;` is rendered as inert escaped text by a DOM-API parser that places the decoded characters into a text node, while a downstream agent using a permissive HTML5 parser may eagerly decode the entity sequence and interpret the result as an executable script element, causing the same byte sequence to be treated as safe content by one agent and as an instruction by another.

Standard defenses such as HTML sanitization libraries applied at content ingestion are insufficient because sanitization is typically performed once at the point where content enters the system; when different downstream agents subsequently apply the already-sanitized content through heterogeneous parsers, entity encoding that survived sanitization may decode differently depending on each parser's entity-handling behavior, reintroducing an instruction surface the sanitizer already processed.

**Multi-agent distinction:** HTML entity encoding confusion is inherently a multi-agent phenomenon: it requires at least two agents with different parser implementations consuming the same HTML to produce divergent interpretations; in a single-agent system one parser handles all HTML processing uniformly, eliminating the inter-agent parsing divergence that the attack relies on to cause instructions to execute in some agents but not others.
