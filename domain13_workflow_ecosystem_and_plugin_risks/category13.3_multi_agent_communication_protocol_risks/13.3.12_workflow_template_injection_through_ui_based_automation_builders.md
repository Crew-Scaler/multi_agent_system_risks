# 13.3.12 Workflow Template Injection Through UI-Based Automation Builders [NoFW]

Visual workflow automation builders (Zapier, Make, n8n, Microsoft Power Automate) enable non-technical users to construct agent workflows through drag-and-drop interfaces. Attackers inject malicious instructions into workflow template fields — trigger conditions, action parameters, filter expressions — that are parsed and executed by underlying automation engines without the sanitization applied to code-based workflow definitions. In multi-agent deployments where workflow templates are shared across organizational teams, one poisoned template propagates to all agents instantiated from that template, enabling large-scale instruction injection through trusted internal workflow infrastructure.

Standard defenses such as code review and access controls on programmatic workflow definitions do not extend to visual template builders where non-technical users construct workflows through drag-and-drop interfaces, and the injection payloads reside in template metadata fields that security scanning tools typically do not inspect for executable content.

**Multi-agent distinction:** Workflow template injection is amplified in multi-agent deployments because shared templates are instantiated by every agent configured from them simultaneously; a poisoned template deployed across an enterprise automation platform affects every agent instance derived from it, turning one template-level injection into fleet-wide instruction manipulation through the shared workflow infrastructure in a way that has no equivalent in single-agent deployments with agent-local configurations.
