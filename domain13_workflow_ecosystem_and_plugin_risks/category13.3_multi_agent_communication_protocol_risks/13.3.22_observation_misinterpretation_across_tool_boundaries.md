# 13.3.22 Observation Misinterpretation Across Tool Boundaries [NoFW]

Agent systems processing tool outputs as observations for subsequent action selection are exploited when tool outputs contain structured data that agents misinterpret across tool boundaries. Attackers craft tool outputs whose serialized format (JSON, XML, plain text) is parsed differently by producing and consuming agents, enabling semantic injection where agents interpret the same byte sequence as different content. In multi-agent pipelines passing tool outputs between agents through message protocols, serialization format ambiguities create systematic misinterpretation opportunities at every agent handoff point.

For example, a tool that produces a JSON response with a field `"action": "log"` may be consumed by a downstream agent whose regex-based parser treats the surrounding escaped markup as a processing instruction, silently interpreting the byte sequence as an executable directive that the producing agent never intended to emit.

Standard defenses such as output schema validation at tool boundaries are insufficient because schema validation checks structural conformance—that keys exist and types match—but cannot detect semantic divergence caused by parser differences; a document that is structurally valid JSON but simultaneously interpretable as something different by an XML or text parser will pass all schema checks without revealing the divergence.

**Multi-agent distinction:** Observation misinterpretation across tool boundaries is intrinsically a multi-agent phenomenon: it requires two agents using heterogeneous parsers on the same byte sequence to produce divergent interpretations; in a single-agent system one parser handles both serialization and deserialization, eliminating the inter-agent divergence. In multi-agent pipelines, every agent handoff point introduces a new serialization boundary where this divergence can independently recur.
