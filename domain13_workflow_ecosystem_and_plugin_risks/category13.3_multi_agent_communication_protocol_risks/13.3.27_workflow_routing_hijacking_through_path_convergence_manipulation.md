# 13.3.27 Workflow Routing Hijacking Through Path Convergence Manipulation [NoFW]

Multi-path workflow systems using voting or consensus mechanisms to select execution paths are exploited when attackers manipulate convergence conditions to route workflows to attacker-desired execution branches. By generating or modifying path evaluation signals to create artificial agreement on adversarial paths, attackers exploit consensus-seeking workflow routing to force selection of high-privilege or unsafe execution branches that nominal operations would not reach. In multi-agent voting systems, one compromised voter agent disproportionately influences routing decisions for the entire agent network.

For example, in a multi-agent document approval workflow that routes to an executive-override branch only when three independent path-scoring agents agree the request is urgent, an attacker who compromises one scoring agent can shift that agent's evaluation score just enough to push the aggregate above the consensus threshold, routing a routine low-privilege request to the privileged override branch without any single agent casting an obviously anomalous vote.

Standard defenses such as majority voting and Byzantine-fault-tolerant consensus mechanisms are insufficient because these controls assume a bounded number of malicious voters casting arbitrary signals, but threshold manipulation only requires nudging one voter's score slightly above its normal range—not corrupting it arbitrarily—making the manipulation indistinguishable from normal scoring variance.

**Multi-agent distinction:** Consensus-based routing hijacking is structurally impossible in a single-agent system because there is only one routing decision-maker with no vote to tip; the attack requires multiple independent voter agents whose aggregate can be manipulated by partial compromise of one participant, an attack surface that exists exclusively in multi-agent voting architectures where no single agent holds authoritative control over path selection.
