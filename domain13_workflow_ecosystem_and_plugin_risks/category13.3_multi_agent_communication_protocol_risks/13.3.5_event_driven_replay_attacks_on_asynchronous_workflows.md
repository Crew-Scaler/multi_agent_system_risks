# 13.3.5 Event-Driven Replay Attacks on Asynchronous Workflows [NoFW]

Attackers replay captured workflow events to trigger re-execution of actions with different current context, exploiting temporal decoupling in event-driven architectures.

Event-driven workflow architectures decouple event emission from event processing through message brokers, and this temporal gap means a captured event carries its original context but executes against the current system state—allowing attackers to replay legitimate events at attacker-chosen moments when that state diverges beneficially. In an order-processing workflow where Agent A emits a "payment-confirmed" event consumed by Agent B to trigger order fulfillment, an attacker who captures that event and replays it after the original order was canceled causes Agent B to fulfill a second shipment against a now-invalid order, because Agent B validates the event's cryptographic signature (legitimate) but not its temporal appropriateness relative to the current order state. The asynchronous multi-agent architecture creates the window: Agent B operates independently with no awareness of order lifecycle changes that occurred between the original event emission and the replay.

Standard defenses such as event signing and idempotency tokens are insufficient because event signing only proves the event originated from a legitimate source, not that it is being processed at an appropriate moment, and idempotency tokens prevent exact duplicates but not semantically replayed events with modified metadata or replayed at a later state transition.

**Multi-agent distinction:** Event replay exploits the temporal decoupling that is definitional to multi-agent asynchronous architectures—in a single-agent synchronous system the agent maintains continuous state awareness and cannot receive a stale event as if it were current; across agent boundaries, each agent's independent state management creates replay windows that attackers can target with precision.
